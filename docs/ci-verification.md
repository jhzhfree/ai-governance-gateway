# CI 验证预算与故障定位

统一入口为 `bash scripts/verify.sh`，CI 与本地共同使用脚本默认值。后端 Go 测试默认每个包 600 秒，可用 `AIGW_GO_TEST_TIMEOUT` 显式覆盖；脚本打印最终值。`go test -timeout` 限制的是一个包的整个测试二进制，不是单个测试。race、数据库集成和各操作的 context/锁等待超时仍启用。执行引擎模块保留 120 秒门禁，浏览器 fixture 保留独立 240 秒门禁，工作流总上限 30 分钟。

故障样本：提交 f88f78a，GitHub run 42239408967、job 127965428034。环境准备和依赖安装成功，后端验证在 internal/httpapi 包累计 2 分钟时终止；当时 TestOwnershipExpiryRoleChangeAndAuditRollback 只运行约 1 秒，不能将它认定为卡死根因。此前相同提交的完整本地回归中，该包 154.223 秒通过，该单项 1.49 秒通过。本地命令显式使用 600 秒，而未设覆盖值的 CI 使用旧默认 120 秒，是已确认的配置差异。

修复只统一包级默认预算，不删除测试、不跳过数据库、不关闭 race、不放宽业务超时、不以自动重试掩盖失败。后续根据输出中各测试/包耗时追踪回归；若再次超时，先看包总时长、当前测试已运行时间、goroutine 栈及数据库锁，再判断是否存在单测挂起或资源竞争。

本次修复验证结果记录于 V1 交付跟踪；本地通过不代替远端 CI 结论。

远程复验 42245393535（3ecc453）：日志确认使用 600 秒预算，internal/httpapi 在 144.353 秒通过。环境中的 Ubuntu 字体包下载出现多次 Ign/Get 重试，使浏览器依赖安装持续约 10 分钟，之后成功完成。工作流随后在两个独立的浏览器色彩对比度断言失败（账单导入与预算通知），不是后端超时复发。

已增强相关 axe 断言的失败输出：保留必须零违规的判断，增加节点选择器和 failureSummary，不输出页面正文，也不忽略 color-contrast。原报告只有规则 ID，无法可靠定位元素。与 CI 相同的 Chrome for Testing 156.0.8078.4 在本地及调整字体配置下的 16 个 OIDC 场景均通过，随后完整本地回归复现了账单页失败：两个刷新按钮恢复可用时，背景仍从禁用色渐变至品牌色，白色文字在 #3f8181 背景上仅 4.49:1。TDesign 默认 `transition: all 0.2s linear` 造成短暂可读性不足。应用现只保留按钮阴影/变换过渡，颜色立即切换，不修改 axe 阈值、规则或预期结果；待完整复验与远端确认。

回归场景还复制真实刷新按钮的样式，在禁用状态稳定后重新启用，逐帧检查随后 250 毫秒内文字/背景相对亮度对比度不低于 4.5:1，并断言实际取得有限测量值。此操作只作用于临时 DOM 副本，不发起额外 API 请求。独立使用实际构建 CSS 的同版浏览器测量：旧 `all` 过渡最低约 1.67:1，新过渡最低约 6.49:1；这是 UI 状态测试，不是网关性能指标。原有整页 WCAG axe 检查继续保留。
