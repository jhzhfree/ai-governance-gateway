# ADR 0011：项目密钥模型发现与成员管理

状态：已实现；真实企业 IdP/供应商与大陆部署验收仍待完成。本轮不修改数据库结构，数据库保持 0010。

## 模型发现

GET /v1/models 使用推理项目密钥，与管理 JWT/Cookie 的 /api/v1/models 分离。一次权威数据库读取验证密钥摘要、到期/撤销、币种及项目模型权限，再与当前配置中驻留条件有效的模型求交集。返回稳定按别名排序的 OpenAI object=list/data 结构，每项仅含 id/object/created/owned_by；配置未公开模型创建时间，因此 created=0，不能把密钥创建时间冒充模型创建时间。

有效密钥的交集可以为空，返回 200 空数组；过期/撤销/未知密钥及管理 JWT 返回 401，授权数据库不可用返回 503，POST 返回 405。忽略客户端组织/项目提示头，不回显供应商密钥、原始模型 ID、价格或证据。查询不联系供应商，不占用推理预算/租约/频率窗口、不建立 attempt，也不更新推理 HTTP 计数。响应 no-store；认证查询和写响应均有期限。

Directory 与实际推理不是一笔事务：权限在列表返回后仍可被撤销，后续推理必须再次授权；列表出现也不是供应商可用性、熔断或账单驻留验收证明。

## 成员管理

新增组织及项目成员列表，只有组织 owner/admin 能查看完整身份标识；组织 viewer/developer 和项目委派 admin 无成员管理能力。组织赋权仍仅 owner，项目单独授权仍仅组织 owner/admin，不扩大原有权限边界。Web 直接使用 issuer/subject，不推断邮箱，不创建或邀请企业 IdP 用户。

项目列表投影组织成员、显式项目角色与 effective_role：组织 owner/admin 继承项目 admin；组织 viewer 继承 viewer；组织 developer 没有项目授权时为 none。不能用项目角色降低继承权限，Web 明确显示来源。组织 owner 不可降权/转移/删除；本阶段不增加组织成员删除，避免破坏历史密钥创建者外键与财务证据。

PUT 向后兼容旧调用方，增加可选 expected_role：空字符串表示期望尚无该角色行；其他值与当前行比较，不符返回 409。Web 始终提供比较值。它是角色比较，不是历史 revision，不承诺防止 A→B→A。写事务先按组织序列化成员写入，再读取并锁住权限行，避免多个操作者共享锁升级造成死锁；管理请求使用既有角色 SHARE 锁语义。

DELETE 项目 members 接受目标 issuer/subject 和必填 expected_role，只移除显式项目角色，重复移除幂等。角色变更/移除与审计在一个事务内，审计失败回滚。查询结果可分页，按 issuer/subject 稳定排序，游标有界且只影响已授权组织内查询，不构成授权凭据。

角色变化影响后续管理请求，不终止在途操作。项目密钥是独立项目凭证，角色降低或移除项目授权不会自动撤销既有密钥；页面明确提示，需要到密钥页单独撤销。企业账号停用、组织成员软删除、所有权转移、个人密钥生命周期联动与全量变更历史属于独立后续工作。
