# CI 验证预算与故障定位

统一入口为 `bash scripts/verify.sh`，CI 与本地共同使用脚本默认值。后端 Go 测试默认每个包 600 秒，可用 `AIGW_GO_TEST_TIMEOUT` 显式覆盖；脚本打印最终值。`go test -timeout` 限制的是一个包的整个测试二进制，不是单个测试。race、数据库集成和各操作的 context/锁等待超时仍启用。执行引擎模块保留 120 秒门禁，浏览器 fixture 保留独立 240 秒门禁，工作流总上限 30 分钟。

故障样本：提交 f88f78a，GitHub run 42239408967、job 127965428034。环境准备和依赖安装成功，后端验证在 internal/httpapi 包累计 2 分钟时终止；当时 TestOwnershipExpiryRoleChangeAndAuditRollback 只运行约 1 秒，不能将它认定为卡死根因。此前相同提交的完整本地回归中，该包 154.223 秒通过，该单项 1.49 秒通过。本地命令显式使用 600 秒，而未设覆盖值的 CI 使用旧默认 120 秒，是已确认的配置差异。

修复只统一包级默认预算，不删除测试、不跳过数据库、不关闭 race、不放宽业务超时、不以自动重试掩盖失败。后续根据输出中各测试/包耗时追踪回归；若再次超时，先看包总时长、当前测试已运行时间、goroutine 栈及数据库锁，再判断是否存在单测挂起或资源竞争。

本次修复验证结果记录于 V1 交付跟踪；本地通过不代替远端 CI 结论。
