# ADR 0010：单进程 Chat 完成证据与恢复结算

状态：已实现并通过本地开发门禁；不等于真实供应商账单或正式发布验收。

## 责任与顺序

产品工厂必须取得根应用创建的 `completion.Store`，使用 `NewDurableManaged`。底层 SDK 的类型继续封装在适配层；不引入 new-api HTTP 通道、源代码或第二套预算账本。原有无持久对象构造器仅保留给隔离契约验证，产品命令不能选择该路径。

1. 现有鉴权、终端、输入审计/策略、预算预占、attempt 和 dispatch 状态先完成。
2. 嵌入执行绑定在实际调用前写入一次性 `engine_execution_bindings`。快照含 request/attempt、供应商、模型映射、价格、输入输出边界和流标记。重复 Bind 拒绝；不以重试 INSERT 授权再次请求上游。
3. JSON 已收到原始单候选响应且明确给出受支持的 `finish_reason`，或 SSE 已收到实际 `[DONE]` 时，适配器标记 `Event.Completed`。缺少/未知 JSON 结束原因不成为完成事件；流式尾部 usage 在真实结束符前不成为完成证据。
4. 桥接层校验原始 counters 与适配器投影一致，先同步写入 `engine_completion_events`，再向治理 Handler 提供用量/终止消息。原始对象最多 8 KiB，只接受有界整数及明确的数值明细，拒绝重复字段、任意嵌套正文和字符串。数据库不保存供应商完整响应。
5. Handler 结算时重新以持久快照计算费用，核对当前计算值；权威预算变更和 `engine_completion_receipts` 在同一 PostgreSQL 事务提交。内容审计封存及客户端成功终止仍由原治理链执行。

数据库迁移 0032 追加三个受结构漂移校验保护的表。保留默认启动自动升级、迁移锁、校验和、失败回滚和 check 模式；不修改已发布 SQL。升级测试从 0031 重建，检查历史占额、重复升级、事务回滚和漂移拒绝。

## 证据边界

持久 `route_digest` 只派生自公开的价格/路由版本，不包含秘密。`Route.ExecutionIdentity()` 包含凭证相关信息，只用于内存池与旧绑定排空，不写入表或日志。凭证轮换不改变历史计费证据；物理 attempt 仍独立且唯一。

同一 attempt 的重复原始事件只允许字节完全相同，冲突拒绝。恢复时重验原始对象、SHA-256、数量、快照上界及价格，防止把投影列或 SDK 补出的零用量当作证据。Hash 是一致性校验，不是抵御数据库管理员篡改的数字签名。

完成是供应商协议事实，不代表客户端已收到响应、输出护栏通过、内容审计已封存或调用账本 outcome 为 completed。已观察到可信完成后，即使客户端取消，仍给同步持久化最多 3 秒；随后保持取消语义。后续恢复可以结算真实已知费用，但不伪造客户端成功或修改审计结果。

## 恢复与失败

共享应用维护任务启动后立即执行一次，之后每分钟执行。仅选取超过 3 分钟的记录，该窗口长于 120 秒总请求期限。每轮最多检查 100 个过期派发及 100 个待结算事件；用 `SKIP LOCKED` 和检查时间轮转，事务回执使多个进程重复消费保持幂等。完成事件的待消费标记与回执同事务更新，部分索引只扫描尚未结算的事件，避免历史成功记录持续占用恢复扫描。

- 事件已落库、结算未提交：从同一数据库按原快照恢复，不读当前费率，不再调用供应商。
- 结算已提交、响应未送达：重复事件不重复扣费，保留原客户端/审计状态。
- 派发后没有有效完成事件（包括 Dispatch 与 Bind 之间的崩溃窗口）：标记 uncertain，保留预算占额；不自动退款、估算成零或重放模型请求。过期派发扫描也可能将旧执行链的 dispatched 改成 uncertain，仅保留原占额，不消费或伪造其完成证据。
- 绑定写入失败：不调用供应商；已有保守 dispatch 占额保持未知，不能仅凭一次错误返回推断提交一定没有发生。
- 原始事件写入失败：不输出成功终止；进程在持久化前退出仍可能丢失尚未落盘的用量，需要外部账单/人工对账。
- 回执或预算事务失败：两者一起回滚，已提交的完成事件保留供恢复。
- 单个坏事件保留并报告固定错误码，继续其他可处理事件。后台不是无限吞吐，仍需后续积压监控与容量验收。

## 验证范围与后续

真实隔离 PostgreSQL、合成供应商与独立进程覆盖：原始计量验证、错误关联/摘要、重复事件、并发回执、回执故障整事务回滚、无完成事件占额、损坏事件不阻塞其他费用恢复；实际 JSON/SSE 在持久事件之后、回执提交之前 SIGKILL，再由新进程恢复且供应商调用数保持 1。现有身份、预算、终端、审计和流式拒绝矩阵接入持久路径。

目前仅文本 Chat JSON/SSE，统一输入/输出单价；缓存字段可保留为原始证据，不自动推断缓存优惠。Embeddings、Responses、Messages、工具和内联图片将在后续迁移中增加明确的证据格式及计费语义。旧 new-api outbox 继续属于旧执行链，本迁移不擅自把旧绑定改成新引擎完成证据。

本 ADR 不承诺生产容量、跨主机 HA、所有供应商用量完整性或商业授权已核清。精确验证结果、失败轮和远端 CI 以根 `docs/v1-delivery.md` 为准。
