# ADR 0001 单引擎与单次尝试执行边界

状态：M0 首批执行契约验证通过；生产选型待完整验收。

采用 Bifrost Core `v1.14.1`，对应发布源码 `2975d142abcffc5783a60201394631b5576c748f`。不使用此前审查的 dev 快照，不依赖商业版治理或集群实现。纳入正式仓库后，模块路径为 `github.com/jhzhfree/ai-governance-gateway/modules/engine`。

执行接口携带 request_id 与 attempt_id，流式事件同步提交给消费者，使背压和消费者错误可传递；消费者必须响应 context 取消。M0 输出为内部规范化事件，不宣称已实现面向客户端的完整 OpenAI HTTP 协议。

模型与供应商配置由服务端构建。外部 body 的 provider、fallbacks、api_key、base_url 拒绝进入执行层。内部 MaxRetries 为零，且不设置 fallback；以实际服务器收到的请求数验证单次派发，不只检查配置字段。

供应商 API 错误映射为内部类别，不向客户端透出原始正文。用量与金额分离：Usage 是供应商归一化证据，不是账本；usage 缺失保持 nil。后续必须补充用量来源、完整性、错误响应部分用量、供应商计费依据和价格快照。

实测发现发布版会在流式 usage 缺失时合成全零对象。适配层暂将所有全零用量视为未知，宁可等待对账也不自动判定免费。此规则也覆盖供应商明确给出的全零用量，直到后续建立来源证明。事件 Payload 不是可直接用于计费的账务记录。

OpenAI provider 的 BaseURL 不含 `/v1`，SDK 自行追加版本与资源路径；本地测试检查最终实际请求路径。

所有 Bifrost 类型隔离在适配器。未来增加身份、预算、审计时应组合执行接口，不将业务状态写进 Provider 代码，也不复用开源内存预算作为权威账本。

本地合成供应商允许显式 TestLoopback＋字面回环 IP 的 HTTP；正式上游要求 HTTPS。该测试选项不暴露为用户请求字段。生产 SSRF 出口白名单、DNS 与重定向策略仍需单独实现，不将 URL 基础检查称为完整 SSRF 防护。
