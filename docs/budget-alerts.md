# 预算阈值站内告警

本阶段提供真实 PostgreSQL 持久站内通知，不发送邮件、企业微信或任意外部 Webhook。所有通知、历史、备份随网关数据库部署在中国大陆。配置默认关闭，在 Web“预算告警”分别设置组织和项目策略。组织 owner/admin 可以配置和确认；项目成员可读自己有权访问的项目告警；组织级告警仅 owner/admin 可读。

## 触发与去重

- 比例是 `(spent + held) / limit`，包含占额，反映预算即将无法接收新请求的压力；不是最终消费比例。阈值可选 50、60、70、80、90、95、100%，至少选择一个。
- 预算预留与终结、在线调额在各自数据库事务中评估，告警和余额变更一并提交或回滚。短时占额越线后立刻结算/释放，告警仍保留，不依赖轮询采样。
- 启用/调整策略时，在与预算相同的账户锁顺序下检查当前余额，补齐已越线的阈值。并发请求不能绕过此检查。
- 每个组织/项目、预算周期、币种、阈值只产生一次。即使余额下降后再次越线、禁用后重新启用，或策略版本变更，也不反复提醒。新的预算周期重新计数。
- 预算为零不触发比例告警；预算硬拦截仍正常工作。修改规则不删除既有记录，晚到的旧周期结算保留旧周期归属。
- 提醒保存触发时预算/已用/占额的精确十进制字符串，金额都是最小账本单位，CNY_MICRO 的 1,000,000 单位为人民币 1 元。

通知写入失败会使对应预算事务失败：预留失败不派发供应商；已经派发的结算失败保留占额，按既有核查与恢复流程处理，不以丢失告警换取伪成功。数据库异常时仍必须核查调用账本。

## 处理与追溯

站内列表需要用户刷新查看新通知，每页 50 条，按编号倒序分页。当前页面不是外部推送通道，不承诺离线实时送达。

管理员“处理”必须填写说明；确认只记录操作人、时间和原因，不释放占额、不调整额度、不解除硬限制。重复确认返回冲突，避免覆盖其他管理员的处理。策略变更带版本比较及追加历史，确认与策略发布均写入组织审计；审计写入失败时整个操作回滚。停用策略后历史仍可读，确认状态不自动复位。

CLI 与终端 UI 为只读，确认使用 Web：

```bash
aigw alerts --org ORGANIZATION_ID --project PROJECT_ID --output json
aigw alerts --org ORGANIZATION_ID --organization
aigw alerts --after NEXT_CURSOR
```

终端 UI 项目页按 `a` 进入告警，`n/p` 翻页，`r` 刷新、Esc 返回。

API 基础路径为 `/api/v1/organizations/{org}` 或 `/api/v1/organizations/{org}/projects/{project}`：

- GET/PUT `{base}/budget/alerts/policy`；写入需要 enabled、升序去重的 thresholds、expected_revision 和 reason。
- GET `{base}/budget/alerts?after=ID`；返回 data 和 next_cursor。
- POST `{base}/budget/alerts/{alert}/acknowledge`，body 为 reason。Cookie 会话需要正确 Origin/CSRF。

## 升级

先停接新流量并排空在途执行，备份数据库与配置，通过正式迁移工具执行 `migrate up` 升至 **0016**，`migrate check` 成功后启动新网关。正常服务启动不会建表。0016 只追加告警策略、告警和策略历史表，不改写既有账本余额或占额。完整 Ubuntu 流程见 [部署文档](deployment/ubuntu-24.04.md)。

外部通知通道、签名投递、重试/死信和送达确认仍待独立阶段；不能把已生成站内记录当作外部通知已送达。
