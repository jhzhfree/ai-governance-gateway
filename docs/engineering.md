# 代码与交付规范

这些规范是后续实现的验收要求。当前已配置 Go 格式/模块/vet/race、OpenAPI 与真实 PostgreSQL 集成测试，以及 Web 冻结安装、类型生成差异、TypeScript、ESLint/React Hooks、Prettier、生产构建和 Chromium 端到端检查。安全依赖扫描、完整无障碍人工验收及生产门禁仍待完善。工作流配置不等于 GitHub 托管执行已通过。

## 工程规则

- Go 使用 gofmt、go vet、golangci-lint；所有 I/O 传递 context，错误增加上下文且可判定类别；明确 goroutine 生命周期，不在领域逻辑中调用进程退出。
- TypeScript 开启 strict，禁止无理由 any 和忽略类型错误；使用 ESLint、Prettier 与 React Hooks 检查。组件按业务职责拆分，不用全局 store 保存所有状态。
- 命名优先领域词汇；公开接口写清输入、权限、错误和副作用。注释解释约束和原因，避免重复语句。
- API、数据库、UI 类型有清晰转换边界；禁止将数据库行或供应商原始错误直接暴露给调用方。
- 固定工具链与依赖版本，提交 Go 模块校验和、Web 包管理器锁文件，CI 使用冻结安装。依赖升级经测试和许可证核查，不关闭 TLS 或完整性校验。
- 密钥不得入库、入日志或进示例。提供只包含变量名和非敏感默认值的配置样例，开发与生产配置明确分离。

## 测试要求

| 层级 | 必须覆盖的风险 |
| --- | --- |
| 单元测试 | 权限矩阵、策略优先级、金额计算、预算状态机、错误映射 |
| 集成测试 | PostgreSQL 并发预算、跨组织隔离、撤销失效、幂等结算、迁移 |
| 协议测试 | OpenAI 响应、SSE 完成/中断、usage 缺失、超时、取消、重试边界 |
| Web 测试 | 关键表单、权限反馈、筛选 URL、失败状态；Playwright 验证首调闭环 |
| TUI/CLI 测试 | 状态转移、终端缩放、取消与恢复、JSON 输出及退出码 |
| 安全测试 | 越权、CSRF、SSRF、敏感日志、请求体上限和凭证撤销 |

测试应验证行为，不以覆盖率数字代替关键风险验证。禁止外网真实付费调用进入默认测试。Go 并发关键路径使用 race detector；测试超时明确，故障注入可复现。

## PR 与 CI 门禁

每个 PR 说明问题、行为变化、验证证据和迁移/回滚影响。涉及 API、权限、预算或持久化时须有对应测试和契约更新；架构边界调整写 ADR，记录理由、替代方案与取舍。保持小批量交付，禁止将重构、功能和依赖升级无关混合。

脚手架阶段建立以下顺序的门禁：冻结安装 → 格式/静态检查 → 单元测试 → OpenAPI 校验及客户端差异检查 → 集成测试 → Web 类型检查和构建 → 关键 E2E → 依赖/密钥扫描。必需任务不得使用 continue-on-error 或零测试成功作为通过依据。

UI 变更附关键状态截图和键盘验证结果；供应商适配器变更附协议兼容证据。发布产物记录 commit、依赖清单和构建版本；生产配置、数据库备份恢复与回滚步骤验证完成后才允许上线。

## 完成定义

功能完成意味着：需求验收通过、服务端权限完整、错误与空状态齐全、相关测试通过、可观测性与文档齐备、没有凭证泄露、迁移与回滚风险已说明。设计文档、界面原型或通过编译均不单独等于功能完成。
