# ADR 0008：一致快照与受管实例池发布

状态：根运行时一致读取已实现；候选模块受管发布已联调，main 尚未切换。

## 读取边界

原 Manager.snapshot 分开读取配置与凭证，并发发布可能拼接不同时间的状态。新增 `Manager.ExecutionSnapshot(ctx)`，在 PostgreSQL READ ONLY / REPEATABLE READ 事务中读取配置、解密凭证并构造不可变 Catalog。Manager 的 Find/Models/Ready 复用该路径。环境凭证在读取时固定到内存映射，不再通过返回的 getter 延迟读环境；运行中不支持多环境变量的原子热更新。

这保证一次读取来自同一已提交数据库时间点，不意味着管理员分开的配置发布与密钥更新事务变成一笔事务。管理页 Status 的展示读取不在本次执行快照改造范围内。数据库没有结构变更，启动自动迁移仍保留到 0024。

Catalog.ExecutionRoutes 只供进程内使用，不是管理 API；不新增返回凭证的 JSON 路径。数据库/解密/配置错误不回退到历史 Catalog 或环境密钥。

## 受管执行器

`gatewaybridge.Managed` 组合 SnapshotSource 与 Pool，同时实现 Routing 和 ProviderExecutor。Find/Models/Ready 会同步刷新，默认最长两秒；也可由拥有者显式调用 Refresh(ctx)。读取与发布串行化，使用进程内单调代次，迟到读取不能用更高代次覆盖已经读取的新版本。相同执行身份继续复用池实例，改变凭证/价格/模型后自动构建并发布新集合。

读取期间已获得的路由快照仍可按旧集合接纳；读取失败被观察到后清空可接纳目录。发布与接纳受同一状态锁协调，发布失败（包括容量不足）同样清空目录，不因为旧实例仍存在就继续接纳旧凭证。已有租约保持原快照并正常排空；有效后续刷新可以恢复。没有后台轮询、数据库通知订阅或分布式推送，变更最迟在下一次成功路由刷新被观察到。正常轮换不等于紧急取消所有在途请求。

Open 的目录检查与池租约获取在同一读锁内完成，通过池内部 admission hook 在取得租约后释放锁，再等待上游响应；长首字节等待不会阻止后续发布。失败刷新与旧租约接纳有明确先后边界。Close 取消并等待实例资源，也等待正在取消的源读取结束。所有者必须关闭组件。

## 事务与接入

ModelsIn 委托源的事务内模型查询，不另取连接、不从未提交事务发布实例；源不支持该接口时返回空列表，避免单连接池嵌套获取导致死锁。模型授权仍由原控制面执行，不复制权限或账本。

接入时必须将同一 Managed 对象同时作为网关 Providers 和 Executor，保留原身份/设备/审计/预算链。主程序目前仍用原生转发；下一阶段需要独立入口/构建边界、显式启用、关闭顺序、readiness 接线和部署回归。根模块不新增对 Bifrost SDK 的依赖。

当前同步刷新有数据库读取及串行化成本，也会在配置变化时暂时阻塞接纳；尚未做容量测试，不宣称性能提升。之后优化刷新/通知时必须保留一致性、过期拒绝和失败关闭，不能引入无限期旧凭证缓存。

## 验证

真实 PostgreSQL 使用查询屏障，强制在读出配置后更新凭证与模型，再继续读取：旧快照必须同时拿到旧配置/旧凭证，下一快照同时观察新值。测试使用单连接读取池，无计时猜测。

受管组件通过实际本地 DeepSeek HTTP 上游验证数据库换密钥、新旧请求各一次、旧租约完整完成、坏密文阻断与修复恢复；事务模型查询不发布实例。另验证读取串行化、排队取消、发布容量失败后禁止旧缓存接纳、容量恢复及关闭取消源读取。完整测试与重复 race 证据见根交付跟踪。没有真实模型付费调用、生产迁移或 V1 发布。
