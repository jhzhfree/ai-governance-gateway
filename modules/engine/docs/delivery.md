## 持续发现

- F001：默认 `/usr/bin/go` 不是本项目所需 Go 编译器。采用已存在的 `/workspace/.onboarding/toolchains/go/bin/go`（1.27.3），验证脚本显式校验版本。
- F002：默认 HOME 不可写，Go cache 与 sumdb 会失败。显式配置可写 GOPATH、GOMODCACHE、GOCACHE；不关闭校验和。
- F003：Bifrost SDK Core 发布版与 dev 版本必须区分。已选择发布版 v1.14.1，未来升级以同一契约测试集验收。
- F004：Bifrost OpenAI provider 会追加 `/v1/chat/completions`。最初测试使用带 `/v1` 的地址，实测出现 `/v1/v1/chat/completions`；已纠正配置契约与合成服务地址，保留实际路径断言。BaseURL 是 origin 或代理前缀，不含 OpenAI `/v1`。
- F005：Bifrost 流式响应在上游缺失 usage 时会生成全零 usage。新增测试初次失败；适配层现将全零用量保守处理为未知。真实的全零用量也暂不能自动结算为零，须补齐来源证据或对账。内部 Payload 仍保留 SDK 规范化响应，未来账本只能使用显式用量证据，不得从 Payload 的零值推导免费。

## 本轮实测记录

2026-11-06，Go 1.27.3，Bifrost Core v1.14.1，在本云环境运行 `bash scripts/verify.sh`（编译器和缓存参数见 README）。最终退出码 0：格式检查、`go mod verify`、`go vet -mod=readonly ./...`、`go test -mod=readonly -race -count=1 -timeout=120s ./...` 均通过。适配器 12 个顶层测试，另有 2 个在途流子场景，测试包耗时 3.127 秒；该时间不是吞吐性能指标。内部 execution 包当前只有契约，无独立测试。

两次发现问题后保留回归断言并重跑门禁，没有跳过失败用例。GitHub Actions 仅建立配置，未推送、未执行远端 CI。原 new-api 与 ai-governance-gateway 工作区状态均干净；没有部署或调用真实模型服务。

## 接下来按交付门禁推进

1. 完成 M0：Responses／多轮工具／多模态的支持边界、并发与过载、长流、内存及 goroutine 回收、关闭过程；明确未支持协议的拒绝行为。补充依赖安全与许可证清单，验证升级回退；真实供应商抽样需要独立安排凭证与预算。
2. M1 首个纵向闭环：租户／项目／主体／设备身份、服务端模型授权、哈希存储的客户 Key、短期凭证与撤销、预算原子预留、attempt 持久化、版本化价格、幂等结算、未知费用待对账。先用 PostgreSQL 事务验证并发与崩溃恢复，不能以内存限额作为权威账本。
3. M2 内容审计：明确请求／响应／工具参数的采集策略，持久化接收确认、加密与分级授权、脱敏、保留和删除、访问审计；区分“已观察”与“已可靠落盘”，为后续护栏预留同步拦截与异步检测接口。
4. M3 终端管控：设备注册和证书生命周期、短期会话、用户与设备绑定、防重放、撤销传播；网关准入不能替代终端侧防绕过，终端 Agent 与网络出口管控需单独验收。
5. M4 企业交付：双节点一致性、配置版本、故障演练、容量基线、费用分析与对账、可观测性、备份恢复、安装升级回滚、运维手册。每项保留可复现证据，未通过不宣称生产可用。

## 企业验收不能省略

账务：并发预算、价格快照、派发后崩溃、未知费用、重复结算、供应商对账。

安全：跨租户、凭证撤销、防重放、SSRF、内容查看授权、机密不进入日志。

可靠性：数据库与审计存储故障、节点退出、配置版本、恢复与升级回滚。

性能：分别报告基础执行、账务、设备、内容审计开启后的增量开销，不使用开源宣传数字代替实测。
