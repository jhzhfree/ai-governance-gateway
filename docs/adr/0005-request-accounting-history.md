# ADR 0005：复用权威账本实现调用查询

状态：已实施；真实供应商与完整请求日志另行验收。

## 决定及原因

当前治理链路已经持久化 request_id、预算周期、单位、价格版本、预留/结算量与状态，但界面无法将推理返回的 request_id 与费用对齐。直接从 budget_reservations 提供只读管理查询，复用现有项目成员授权，是本轮能够完整验证的最小排障闭环。

管理 API 新增项目作用域的列表/详情，生成 Go/TypeScript 类型。查询层在同一事务先校验项目权限，再按组织、项目和请求 ID 读取，禁止全局 request_id 查询绕过作用域。按创建时间倒序、request_id 倒序采用复合游标；追加编号 0005 的历史索引迁移，已发布迁移不变。没有新的权威账本、缓存或异步写入，因此不引入双写丢失导致的假记录。

Web 采用现有 TDesign 资源列表、URL 条件、独立详情和 TanStack Query；缓存键含主体与完整项目路径。CLI 输出管理 API 契约，TUI 添加可取消的账本列表和详情命令，保持请求代次检查及错误保留策略。

## 取舍

完整调用日志需要可靠的模型/attempt、结果类别、耗时及失败落库规则。当前数据不存在这些事实，故不推断或伪造；预算拒绝前的请求也不补造调用记录。不能以 settled 推导客户端收到了响应，也不能将 estimated_final 展示成真实供应商账单已核对。界面明确使用“调用账本”和“账本状态”。

另建请求表可覆盖未预留失败与协议结果，但会引入事务边界、失败时补写和恢复要求，留待完整元数据阶段。按 request_id 字典序分页更简单，却不符合按时间排障的习惯；本轮采用创建时间和 ID 的复合索引，仍明确分页非快照。不会由查询接口触发退款、重试或恢复操作。

## 对真实供应商接入的约束

现有模型白名单及组织币种固定 mock-text/MOCK。下一阶段应先建立明确的模型目录、价格版本、货币单位及可验证的费用上界；报价和计价策略通过显式适配器隔离，原有 mock 路径继续可复现。真实供应商凭证仅由服务端持有，配置端点限制协议/重定向/私网访问；SSE 开始后禁止重放。usage 缺失、超额、断连或持久化失败继续保留 uncertain 及保守占额。真实付费联调必须与本地协议测试分别记录证据。

运行及验收方式见[调用账本查询](../request-history.md)。
