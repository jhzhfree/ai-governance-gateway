# V1 当前功能盘点与下一步

盘点基线：feature/v1.0-enterprise-gateway，4aff9bc 后的 DeepSeek 扩展阶段。依据仓库实现与测试，不以历史规划表的“完整/生产可用”标签代替验收。当前架构与执行顺序以 [V1 交付跟踪](v1-delivery.md) 为准；早期双产品线一页纸不是本分支当前架构决定。

| 模块 | 已实现的代码能力 | 仍需完成的验收或功能 |
| --- | --- | --- |
| Token/身份 | 项目 Key 一次性展示、模型权限、撤销；OIDC 接入；本地账号、强制改密、停用、会话；成员生命周期、所有权操作 | 真实企业 IdP；本地账号不等于自建标准 OIDC Provider |
| 费用治理 | 组织/项目预算，原子预留/结算/uncertain，价格快照、调额审批、周期轮转、站内告警、费用报表/部门归集、标准 CSV 对账 | 官方账单样本、真实价格/账单验收；新执行器原始用量完整性 |
| 终端管控 | 设备登记审批、DPoP 绑定会话、防重放/撤销、Linux 代理 | 企业终端状态协议、真实 Agent 联调与出口防绕过；网关准入不能替代终端管理 |
| 审计/护栏准备 | 默认元数据审计，项目显式开启内容审计、信封加密、独立查看授权与留痕、检查点/恢复、保留删除、哈希链、关键字策略 | 工具/多模态完整覆盖；外部锚定/KMS/SIEM；真实合规留存要求 |
| 路由/运行治理 | 四家供应商配置和凭证托管、发布、模型发现；共享限流/熔断；Web/CLI/TUI；指标 | 真实四家供应商兼容；容量、长流、双节点故障/恢复 |
| 升级 | 版本化 SQL、启动自动迁移、事务锁/校验和/漂移检查；显式只检查模式 | 生产备份恢复演练、兼容升级矩阵；自动迁移不是自动降级 |
| 可替换执行器 | Bifrost 独立模块、请求边界、取消/关闭/过载；治理桥接、严格原始 SSE、四家参数契约与凭证快照工厂 | main 尚未切换；动态轮换、供应商参数与性能门禁 |

## 本阶段交付

增加 `ProviderExecutor` 和 `gatewaybridge.Binding`，贯通合成上游与现有治理链，而非复制账本/权限。发现 SDK 会聚合、修正 usage 后，增加原始帧证据校验与重复/冲突回归。具体边界及 SDK 原始捕获限制见 [ADR 0004](../modules/engine/docs/adr/0004-governed-execution-bridge.md)。第六阶段将流式物理接收改为自有严格接收器，非流式继续固定 Bifrost SDK；不再依赖 SDK 可截断的流捕获。当前主程序运行行为保持原生供应商路径。

## 接下来顺序

1. 当前 SSE 子集已通过直接原始接收补齐畸形帧、超大帧和断流的明确拒绝，用量证据延后至 DONE；持续保留这些升级回归。详见 [ADR 0005](../modules/engine/docs/adr/0005-strict-stream-reception.md)。
2. 四家固定路径与参数、本地契约及凭证快照绑定已完成；接下来实现有界共享池、自动轮换/排空与资源回收，再受控启用单引擎。禁止隐式重试或回退。
3. 扩展工具内容与治理/审计闭环；逐项维持拒绝边界。
4. 做可复现性能、双节点故障、安装升级和备份恢复演练，再收敛真实 IdP、终端及供应商外部验收。

每阶段验证后提交推送。V1.0 标签须等全部必须门禁完成，当前仍为开发分支。

第七阶段详情见 [ADR 0006](../modules/engine/docs/adr/0006-mainland-supplier-bindings.md)。SDK 非流式转换曾改写 token/思考字段，现对已校验的固定供应商请求固定原始发送内容；生产账号兼容仍待真实验收。

DeepSeek 能力与计费边界见 [接入说明](deepseek.md)。
