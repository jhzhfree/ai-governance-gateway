# 数据库备份恢复演练

本阶段交付的是可重复的隔离恢复门禁，不是生产自动备份服务。脚本只接受专用测试数据库连接，自己生成 fixture schema，不接受任意待恢复数据库、schema 或外部备份文件。不会覆盖已有应用 schema；演练期间先把生成的源 schema 改名保留，再恢复到原随机名称，结束清理两份 fixture。不要在生产数据库运行测试。

## 执行

需要 `.go-version` 指定的 Go，以及与服务端兼容的 `pg_dump`、`pg_restore`。本轮实测客户端和服务端均为 PostgreSQL 17.11。由受控环境注入 `TEST_DATABASE_URL`，使用含主机、用户、数据库的 PostgreSQL URI；凭证不放入终端历史。脚本不会打印 URI，不把密码放入子进程 argv；子进程用独立 libpq 环境，明确拒绝不支持或重复的连接选项，不继承操作者的 PG service 覆盖。

```bash
# 只执行恢复门禁
bash scripts/verify-restore.sh

# 在完整后端回归结束后追加恢复门禁
AIGW_VERIFY_RESTORE=1 AIGW_VERIFY_WEB=0 bash scripts/verify.sh
```

缺少测试数据库、客户端或固定编译器时失败，不静默跳过。普通 CI 默认不启用恢复门禁；具备客户端的交付环境须显式启用，不能把普通 CI 通过当作已执行恢复演练。该门禁不执行真实供应商请求、主机网络变更或生产库操作。

## 已验证的边界

- 当前版本 0025：真实 `pg_dump` custom archive → `pg_restore --single-transaction --exit-on-error`，校验迁移历史、所有 fixture 表的规范化行摘要及序列状态一致。
- 上一版 0024：使用已有测试 helper 构造旧 fixture，备份恢复后应被识别为待升级；运行生产共用迁移函数升级到 0025，再执行结构与校验和检查。该 helper 不是生产降级工具。
- 备份截断后恢复必须失败，目标随机 schema 不得残留；随后完整备份仍能成功恢复。
- 合成费用数据覆盖 settled、reserved、dispatched、uncertain。恢复函数只将滞留 dispatched 标为 uncertain，保留全部未确定费用占用；已结算费用保持不变。
- 恢复后系统审计 identity 序列能够继续插入。供应商凭证表填充合成 bytea，验证二进制值未改变；不声称已演练真实密钥解密或真实内容审计载荷恢复。
- 备份文件仅存测试临时目录，0600，结束删除；数据摘要用于回归比较，不是外部可信审计锚点。重置数据库连接池后比较恢复数据，避免旧预编译计划仍指向保留的源 schema。

## 生产恢复操作顺序

1. 记录发布 commit、数据库迁移版本、PostgreSQL/客户端版本及备份时间点；按实际业务确定并演练 RPO/RTO。升级前保留已验证的备份和旧发布包，自动迁移不等于可自动降级。
2. 在独立安全保管中备份所有仍在使用的内容审计 KEK、供应商凭证加密密钥版本及相关配置。数据库中只有密文/包装密钥，数据库备份不能替代外部密钥备份。OIDC、本地身份、TLS、节点绑定和主机代理部署配置也需单独恢复核对。
3. 对可信备份做完整性和访问权限检查。按部署规范准备隔离目标数据库、角色及权限；生产应备份完整应用依赖，不能直接复制本门禁的 fixture schema 选择方式。数据库逻辑备份不包含全部集群级对象；角色/表空间等需单独安排。[PostgreSQL pg_dump 文档](https://www.postgresql.org/docs/17/app-pgdump.html)
4. 在不接收用户流量、不能调用供应商的隔离目标中恢复。选定失败即停止和事务恢复方式，核对结构、数据、序列及业务不变量后，再使用目标版本迁移程序。恢复本身会执行备份中的数据库定义，必须信任备份来源。[PostgreSQL pg_restore 文档](https://www.postgresql.org/docs/17/app-pgrestore.html)
5. 核验密文可用性、审计链和访问权限；恢复后的会话/Key/设备可能回到备份时状态，备份之后的撤销、停用与授权变更须补齐，必要时统一失效再重新签发。不可直接认为恢复的旧授权仍有效。
6. 对齐供应商账单及备份时间之后的外部请求。已发生的付费调用不会随数据库回滚撤销；未知请求不自动重放、不凭数据库缺失自动退款。系统网卡/DNS 是外部状态，恢复系统审计记录不会恢复机器配置，须独立核查。
7. 完成真实身份、终端、模型、密钥及监控验收后切流，保留旧环境隔离证据并观察；发生问题时执行已评审的切回方案。当前分支尚无跨版本自动降级保证。

## 尚未覆盖

跨主机/灾备站点、真实数据规模、PITR/WAL 连续归档、真实 KEK 丢失/轮换恢复、外部审计锚定、生产权限角色与扩展依赖、备份后撤销补偿、四家供应商账单对账以及具体 RPO/RTO 均待部署环境验收。本机小型合成 fixture 的耗时不能外推为生产恢复时长。
