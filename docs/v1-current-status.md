盘点基线：feature/v1.0-enterprise-gateway，59e5fee 后的系统管理通信与采样加固阶段。依据仓库实现与测试，不以历史规划表的“完整/生产可用”标签代替验收。当前架构与执行顺序以 [V1 交付跟踪](v1-delivery.md) 为准；早期双产品线一页纸不是本分支当前架构决定。

## 本阶段交付

增加 `ProviderExecutor` 和 `gatewaybridge.Binding`，贯通合成上游与现有治理链，而非复制账本/权限。发现 SDK 会聚合、修正 usage 后，增加原始帧证据校验与重复/冲突回归。具体边界及 SDK 原始捕获限制见 [ADR 0004](../modules/engine/docs/adr/0004-governed-execution-bridge.md)。第六阶段将流式物理接收改为自有严格接收器，非流式继续固定 Bifrost SDK；不再依赖 SDK 可截断的流捕获。原生入口默认行为保持；新增独立入口可显式选择受管执行器。

## 接下来顺序

1. 当前 SSE 子集已通过直接原始接收补齐畸形帧、超大帧和断流的明确拒绝，用量证据延后至 DONE；持续保留这些升级回归。详见 [ADR 0005](../modules/engine/docs/adr/0005-strict-stream-reception.md)。
2. 四家固定路径与参数、本地契约及凭证快照绑定已完成；有界实例池和显式发布后的自动排空已实现；配置/凭证一致快照与下一次路由刷新触发的发布联动已实现；独立入口、readiness 和生命周期已接线；已增加 12 秒流与本机双进程故障回归，下一步完成生产容量、跨主机故障、发行安装与恢复演练。禁止隐式重试或回退。
3. 扩展工具内容与治理/审计闭环；逐项维持拒绝边界。
4. 做可复现性能、双节点故障、安装升级和备份恢复演练，再收敛真实 IdP、终端及供应商外部验收。

每阶段验证后提交推送。V1.0 标签须等全部必须门禁完成，当前仍为开发分支。

第七阶段详情见 [ADR 0006](../modules/engine/docs/adr/0006-mainland-supplier-bindings.md)。SDK 非流式转换曾改写 token/思考字段，现对已校验的固定供应商请求固定原始发送内容；生产账号兼容仍待真实验收。
