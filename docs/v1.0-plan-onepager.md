# V1.0 交付一页纸（1 个月 · 2 研发 + 1 测试 + 1 产品经理）

**目标**：交付可受控试点形态的 AI 流量治理网关 V1.0——单机、非高可用、性能数字待实测。
**五大功能**：① 厂商 Token 核心管理 ② 记录审计 ③ 终端准入 ④ 本地 OIDC 支持 ⑤ 系统配置。
**口径**：研发净 8.0 人周（容量 8.5，留 0.5 缓冲）；测试第 3 周介入约 1.5–2 人周；实现程度分**完整 / 基础 / 预留**（预留=接口+归期明确，非砍功能）。

> **特别说明（交付边界）**：本月交付的是**产品软件的核心功能**，即上述五大功能的软件实现与测试。以下工作**均不在本月范围**，属后续阶段另行排期：
> **硬件适配**（盒子产物、A/B 分区、镜像、容量实测）、**产品发布**（发布工程、渠道与上线）、**授权管理**（离线许可证、License 服务）、**文档编写**（用户手册、部署手册等）及**其他产品资料**（汇报/报价/培训材料等）。
> W4 仅产出运行必需的最小工程产物：单二进制 + 数据库迁移脚本 + 最小启动说明。

**架构选型说明**：本评估基于**自研内核**路线（Go 模块化单体 + 单一 PostgreSQL；开源项目仅作协议语义与兼容性对照，**不作为运行时底座**）。

| 自研路线 | 要点 |
| --- | --- |
| 优点 | 1) 治理正确性可证明：预算原子预留/结算、限流租约、审计哈希链同库事务完成；2) 单二进制+单库，适配低资源硬件与离线部署；3) 无上游绑定：版本节奏、漏洞处置、许可证（含 AGPL 类条款）不受制于人；4) 安全审计链自持，合规验收对象清晰 |
| 缺点 | 1) 协议生态兼容面靠自建对照测试逐项累积，短期窄于成熟开源；2) 内核全部代码长期自维护；3) 无开源社区问题库与第三方集成生态可借力 |

**若改走"成熟开源底座（候选：LiteLLM、One API/New API、Higress/Kong AI 网关等）+ 定点改造"路线，本评估不适用，需另行立项评估**，验证工作至少含：① 各底座功能覆盖与架构调研（治理链/审计/多租户匹配度）；② 定点改造可行性 PoC（预算原子预留、加密审计、准入能否等价实现）；③ 许可证合规与社区健康度、上游跟进成本；④ 资源占用与硬件盒子适配。**理论上该路线改造成本与总周期相对本评估会有所延长**（叠加底座学习、内核改造、上游同步三项成本），且开发周期与最终选定的开源项目直接相关——**需验证完成后另行给出结论，本排期不可直接套用**。

### 成熟底座路线的优点（与自研对照）

| 优点 | 说明 |
| --- | --- |
| 起点高、见效快 | 协议覆盖与客户端兼容现成（成熟底座普遍已适配数百供应商、上千模型与主流开发工具），自研需逐项累积 |
| 生态跟进成本低 | 供应商适配器与协议演进由社区维护，新品类模型上线通常"升级即得" |
| 生态功能即取即用 | 自动回退、配额聚合、MCP/A2A、桌面/PWA 控制台等社区功能直接复用 |
| 社区问题库 | 疑难问题有先例可查，集成与排障成本低 |
| 许可证可行 | MIT 类许可证允许商用改造与销售（仍须核查各依赖项许可） |

### 后续产品候选：基于 OmniRoute（github.com/cheaper-inference/OmniRoute）改造的大体成本

**底座快照**（公开资料，2026-10）：MIT 许可；TypeScript / Node.js 22–26；存储 SQLite(WAL)+LowDB（可选 Redis/Qdrant/Bifrost sidecar）；375 供应商、1400+ 模型、额度感知自动回退、MCP/A2A、桌面/PWA 控制台；约 79k Star、900+ 贡献者、更新活跃。**定位**：面向开发者/BYOK 的聚合网关——与 V1.0 企业治理网关是**互补产品线**，改造目标是"治理内核 + OmniRoute 生态覆盖"的后续产品，不占用本月 V1.0 排期。

**大体开发成本（按五项功能清单评估，2 研发 + 后期测试；1–2 周 PoC 先行）**：

| # | 需求 | 实现方式与要点 | 估算 |

| 1 | 国内模型接入 ×3 | 底座已含 DeepSeek/Kimi/GLM 类适配器，工作量集中在大陆端点兼容验证、凭证托管对接与调用留痕 | 0.5–1 人周 |
| 2 | OIDC 本地实现（参考当前系统） | 移植本地身份设计：初始化向导、首次强制改密、会话与短期令牌、停用/恢复、离线恢复；落到 Node 技术栈 | 1.5–2 人周 |

**与完整治理版（下表 17–24 人周）的差异**：只接 3 家国内模型（不做全量供应商生态治理化）、哈希链/KMS/双人导出后置、终端控制走简化档（不做 SDK 代理与企业准入协议）、数据层倾向保留 SQLite——省下的主要是数据层重写与全量适配器治理化。

**完整治理版对照**（2 研发 + 后期测试配置；供立项参考）：

| 阶段 | 内容 | 估算 |
| --- | --- | --- |
| 选型验证 PoC | 跑通底座；验证预算事务、审计挂点、多租户在底座内的改造可行性；依赖许可合规审查 | 2–3 人周 |
| 数据层改造 | SQLite/LowDB → PostgreSQL；账本与预算预留/结算事务化；数据迁移工具 | 3–4 人周 |
| 治理内核移植 | 五大治理功能映射到底座（复用自研设计的语义与测试用例）；凭证加密托管接入 | 6–8 人周 |
| 供应商与路由整合 | 保留 OmniRoute 适配器与回退能力；SSE 回退边界对齐账本语义；多 attempt 入账 | 2–3 人周 |
| 控制台与交付 | 前端整合、指标导出、打包与最小交付物 | 2–3 人周 |
| 测试与验收 | 门禁、回归、验收用例 | 2–3 人周 |
| **合计** | | **17–24 人周 ≈ 2 研发 2.5–4 个月**（对外口径建议报 4 个月含缓冲） |

**主要不确定点**：① SQLite WAL 上的预算原子性与并发写是 PoC 必须验证的第一项，若不达标需换 PostgreSQL，轻量版上界逼近完整版；② Node.js 技术栈与自研 Go 线并存，运维两套栈；③ 上游迭代快（版本周更级），fork 跟进需建立补丁管理机制；④ 免费额度聚合等社区功能与商用治理产品定位需产品侧裁剪。

## 风险与超支预案（按序触发）

单人中断→启用裁剪：① 报表砍 CLI/TUI（-0.2）→ ② 审计导出降级为页面筛选导出（-0.1~0.2）→ ③ 关键字规则整体移 V1.1（-0.5），同步修订对外功能清单。功能②为最高优先级，不可裁。

## 验收判据（DoD）

全量测试（含 race）通过；程度声明逐条勾稽；治理链固定顺序（鉴权→校验→准入→审计预写→预留→派发→结算→封存）未被打破；未发布供应商配置时 ready=503 且拒绝推理；交付单二进制+迁移脚本+最小启动说明+遗留项清单（**不含**硬件适配、产品发布、授权管理、文档与产品资料，见头部交付边界）。
