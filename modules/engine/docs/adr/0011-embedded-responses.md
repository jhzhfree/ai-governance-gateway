# ADR 0011：单进程受控 Responses

状态：本地后端/Web/SDK/故障检查通过，精确门禁与提交状态见根 `docs/v1-delivery.md`。

## 复用与授权边界

复用根 `provider.ResponsesRequest`、`PublicResponses` 和 `responsesStreamWriter` 的严格文本转换，不复制供应商 SDK 或另一套预算/审计实现。固定 Bifrost 执行实际 Chat 请求；公共 `/v1/responses` 是本产品审核的兼容子集，并非启用 SDK 全部 Responses API。

原 new-api 的独立治理渠道条件继续保留。单进程路径要求 Handler 具有持久 completion Store，且当前执行器显式声明该路由支持此公共转换；Binding 只有安装 journal 且请求通过原校验才声明支持。Supplier、Pool 和 Managed 逐层核对关闭状态与不可变路由快照，过期发布拒绝；查询能力不会发出物理请求。最后 Open 仍按当前快照复核，不能用先前能力查询跳过准入。

用户输入必须显式 `store:false`，使用字符串或已有有界文本消息列表，输出上限至少 16 且不超过审核模型上限。服务端状态、previous_response_id、后台处理、工具、媒体、developer/phase 和未知字段继续拒绝；不新增供应商回退或重试。

## 原始计量与实时输出

身份、模型授权、设备证明、输入策略、预算预留、attempt、输出策略与加密审计均沿用原 Handler。实际物理协议仍是 Chat，故 0032 中 `protocol=chat_v1` 表示**原始用量格式**，不是客户端入口。转换后的 Responses 用量不作为独立供应商证据，保持同一 attempt、事件及回执，不引入二次计量。

SSE 原始增量经严格接收器实时交给既有转换器；不会为等待最终用量而缓冲整条文本流。原始 DONE、有效 usage、持久事件、费用与所需内容审计均满足后，才发送 `response.completed` 或合法的 `response.incomplete` 终止事件。缺少原始完成证据时不生成成功终止、不自动释放未知占额。已知完成后客户端取消或结算事务失败，继续按 ADR 0010 恢复，不改变实际客户端/审计结果。

管理费用卡片标注“上游 Chat 计量”，避免把物理用量协议误解为公共 API。此阶段无新迁移、无新依赖，默认自动升级仍至 0032。

## 当前输入准入限制

Responses 初始阶段保留请求大小/消息数与返回原始用量上界检查，但尚无派发前输入 Token 估算；后续 [ADR 0012](0012-embedded-embeddings.md) 已补本地文本估算准入。配置的最大输入决定预算预留，不能据此宣称任意供应商的实际输入费用已被派发前精确封顶。超出原始用量上界时不会伪造结算；仍需对未知费用核查。新准入保持原始证据结算；估算与供应商真实 tokenizer/账单验收必须区分。

## 开发验证

- 同一真实 PostgreSQL/实际 SDK 治理矩阵分别覆盖 Chat 与 Responses；Responses 追加无 journal、无 Handler Store、请求持久状态/工具的派发前拒绝。
- 正常 JSON/SSE、缺失/重复用量、缺少结束原因、畸形/超大帧、断流、身份/模型/设备/预算/审计拒绝、绑定/事件/回执故障、完成后取消。回执失败移除故障后可以恢复，实际供应商调用仍为一次。
- JSON/SSE 独立子进程在完成事件落盘后、预算/回执提交前 SIGKILL，重新启动进程恢复；不重放供应商、不伪造成功终止。
- 真实 HTTP 流以测试屏障阻止上游发送最终用量；客户端收到第一段文本时，数据库仍为 dispatched 且事件/回执为零。解除屏障后核对费用、事件、回执、attempt 和审计封存。
- 发布价格变化后旧快照不再声明支持，关闭后能力撤销，检查过程零派发。
- 可选 `sdk_e2e` 使用已固定 OpenAI Python 3.46.0，连接本次真实嵌入式执行链，验证 JSON、低层 SSE、高级 stream、消息列表及服务器状态拒绝。缺失原始用量时高级 SDK 不能取得最终成功结果，占额保留且调用不重试。根可选 SDK 门禁已包含此路径；旧 new-api SDK 回归继续单独保留。

上述仅为合成供应商、真实数据库和本机进程证据。真实供应商、完整 Responses 兼容性、生产容量与商业分发仍需独立验收；Embeddings、Messages、工具/内联图片及缓存细分尚待继续迁移。
