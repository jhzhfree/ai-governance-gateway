# ADR 0009：独立引擎入口与共享应用生命周期

状态：代码接线与本地验收；未部署生产、未发布 V1.0。

## 构建与选择

将原 cmd/gateway 的启动、配置、schema 和 health 实现及测试迁至 internal/gatewayapp。原命令保持薄入口，调用共享 Main(nil)，不引入 Bifrost SDK。新增 modules/engine/cmd/gateway-engine，提供 Managed 工厂并调用同一 Main。管理 API、身份、设备、预算、审计、迁移和 Web 组装只有一份实现。

2026-11-07 单进程分支修订：引擎二进制通过 `MainEmbedded` 默认且仅允许 `bifrost`，明确拒绝 native/newapi；历史原生二进制仍默认 native。两者复用同一配置解析、schema 和应用生命周期；产品入口不允许回退。未知选择、mock 模式、静态 --providers 文件以及非法实例/并发上限拒绝；本轮新引擎只接数据库托管供应商。工厂失败或返回空引擎时启动失败，后续初始化失败时释放已创建引擎。

默认 MaxBindings=64，允许最多 32 个配置模型进行一轮全量轮换；MaxConcurrent=32。排空中的旧版本仍占容量，连续轮换仍可能触及上限并进入不接纳状态。取值边界是资源保护，不是生产容量承诺。SDK imports 仍仅限 adapters/bifrost；共享应用只依赖 RuntimeEngine 接口。

## 成对接线与 readiness

同一个 RuntimeEngine 同时安装为推理 Handler 的 Providers/Executor，以及控制面的 ModelCatalog。原 Manager 继续处理受保护的配置/凭证管理 API。ModelsIn 复用授权事务，避免嵌套连接与未提交配置发布。没有复制或绕过预算、设备、关键字、内容审计和 attempt 链。

未配置供应商可以启动管理服务以完成初始化，但 readiness 返回 503。readiness 同时检查受管执行器、内容审计密钥、设备准入、数据库版本与结构；live 仅表示进程 HTTP 存活。配置/凭证错误、容量失败、审查到期不会通过健康检查。路由刷新是同步观察数据库，不是后台通知或多节点一致发布。

## 关闭

收到信号后，应用门禁拒绝新 HTTP 请求并让既有请求在 10 秒窗口内结束。引擎资源 context 不直接绑定信号，避免刚开始排空就取消推理。超时关闭连接并取消资源，再留最多 15 秒等待处理器的账本/审计清理，随后回收引擎及数据库池。强制取消不会自动退款；沿用 uncertain 与恢复机制。完成等待超过边界会明确返回错误，不能宣称所有清理必然成功。

后台维护任务有独立取消和完成等待，在启动监听失败、正常退出或信号关闭时回收，不留在数据库池关闭之后运行。初始化和退出均按资源拥有关系清理。

## 验证与剩余边界

真实隔离 PostgreSQL 启动测试验证同一引擎接到路由/执行/控制面、readiness 正反切换、在途请求跨关闭信号完成并结算 14 微元、禁止原生回退、引擎关闭一次。另覆盖初始化中途失败的回收、非法/不可用选择、强制关闭等待处理器及拒绝新请求。独立入口真实 Managed 工厂在未配置时不就绪，发布四家合成配置后就绪，关闭后不可用；不发送真实上游请求。

入口测试使用合成执行对象验证应用接线；实际 Bifrost/严格 SSE、数据库轮换和治理链依然由执行模块集成测试验证。不能将两层测试扩大为真实厂商账号端到端验收。根命令依赖列表检查不包含 Bifrost 或嵌套 engine 模块；引擎模块脚本增加命令格式检查与实际链接构建。

当前监听仍仅限回环地址，真实部署须使用既有 TLS 反向代理与受控网络配置。真实账号、企业 IdP、终端 Agent、长流/容量、双节点故障、升级恢复、发行镜像与运维演练仍待验收。部署选择说明见根 docs/engine-entrypoint.md。
