# V1 当前功能盘点与下一步

当前分支为 `feature/v1-single-process-commercial`，按用户已批准的 [复用优先 V2 规划](single-process-commercial-plan.md) 实施。依据实现与实测，不以历史规划表的“完整/生产可用”标签代替验收。准确验证与提交状态见 [V1 交付跟踪](v1-delivery.md)。

- 产品入口是一个 `gateway-engine` 进程，使用固定 Bifrost SDK 的网络与类型适配；不启动或连接 new-api 数据面。原身份、项目 Key、预算、内容审计、终端与系统管理继续共用。
- 文本 Chat JSON/SSE 已接入迁移 0032：执行绑定、原始用量、原子回执、后台恢复。强杀、取消和缺失证据保持独立语义；最终完整门禁按交付跟踪记录。
- 控制台已改善导航、移动布局、金额精度、按页面加载和异常恢复；新增完成证据状态、冻结单价和回执金额，统计及对账使用恢复后的可信数量；完整验证状态见交付跟踪。
- 新执行器的受控文本 Responses 已接线并通过治理/实时/SDK 针对性检查，本地后端/Web/SDK 检查全部通过；文本 Embeddings 已接入 0033 的独立 input-only 完成事件/恢复，派发前增加文本输入估算准入；DeepSeek 文本 Chat/Responses 已增加原始命中/未命中细分计费与 0034 冻结费率恢复，原生 DeepSeek Messages 文本 JSON 已接入 0035，0036 增加显式审核的原始起始用量和 message_stop 实时完成契约，完整门禁见交付跟踪；工具/内联图片尚未迁移完成，不能以旧双进程能力代替新产品验收。
- Chat/Embedding JSON 已共用解析前限长接收器，保留原始 usage 字节；实际 SDK 复用范围和维护边界见 [ADR 0013](../modules/engine/docs/adr/0013-bounded-json-reception.md)，不是完整 Bifrost 平台接入。
- 新的持久链性能、目标机器/真实供应商/企业系统和完整来源许可核验仍待完成；目前是开发候选，未发布 V1.0。

## 本阶段交付

增加 `ProviderExecutor` 和 `gatewaybridge.Binding`，贯通合成上游与现有治理链，而非复制账本/权限。发现 SDK 会聚合、修正 usage 后，增加原始帧证据校验与重复/冲突回归。具体边界及 SDK 原始捕获限制见 [ADR 0004](../modules/engine/docs/adr/0004-governed-execution-bridge.md)。第六阶段将流式物理接收改为自有严格接收器，非流式继续固定 Bifrost SDK；不再依赖 SDK 可截断的流捕获。原生入口默认行为保持；新增独立入口可显式选择受管执行器。

## new-api 专项验证分支

`feature/newapi-foundation-validation` 已启动，第一阶段为实验性接入契约与治理回归；尚未切换生产入口。详见 [new-api 落地进度](new-api-integration.md)。

new-api 专项已推进到显式 `--execution-engine=newapi`：可信内部入口、原始计数完成钩子、事务 outbox、控制面价格快照/恢复收据、自动迁移 v26、readiness 和双进程 SIGKILL 联调已落地。当前客户端支持受控 Chat Completions（含审核函数调用与内联图片）、input-only Embeddings 以及无状态文本 Responses（JSON/实时 SSE）子集，上游 Chat 已验证 OpenAI 兼容、DeepSeek 和 Anthropic Messages，SSE 已支持 v2 实时内容传输；详细限制、配置和验证证据以 [接入文档最新章节](new-api-integration.md#已接通可信入口恢复消费与显式启动) 为准。默认入口及 V1.0 发布门禁未改变。

追加迁移 v27 支持 new-api 审核目录的独立供应商标识，贯穿执行记录、费用分析和账单对账；原生直连厂商和凭证白名单不变。实时 SSE、三协议故障矩阵、升级回滚及账单身份专项见接入文档。

恢复消费已加入主体隔离分页，异常事件不再挡住后续合法费用；未解决的扫描周期保持不就绪，修复后恢复。长流与恢复采用独立连接池，避免推理连接饱和饿死对账。开发环境完成范围和外部发布门禁以 new-api 接入文档为准，不将模拟供应商或本机故障测试视为生产验收。

new-api 工具阶段：客户端函数声明、结果关联、JSON/SSE 参数完整性与缓冲、加密内容审计和解码参数关键词检查已接通。后续继续有界图片理解输入与其他协议，不把工具阶段当作总体改造完成。

图片阶段新增审核模型开关、有界内联 PNG/JPEG 与加密审计摘要；OpenAI/Anthropic 图片输入故障矩阵通过。函数调用 SSE 完整参数延后至完成证明与结算之后。仍须继续输入计量限制、其他协议和企业治理缺口，不能视作 new-api 全量能力已经迁入。


输入准入 v2：显式 newapi 路径将审核输入上限绑定至请求指纹，数据面对实际转换请求做本地 token 估算，超限在派发前拒绝；控制面验证数据面能力及响应回显。支持受控文本、客户端函数和已审核内联图片；估算不替代供应商原始用量、精确 tokenizer 或独立图片/工具费率。升级须数据面先行，数据库仍为 v27。细节见 `docs/new-api-integration.md`。

受控客户端工具新增目录级 `allowed_tools` 名称白名单，默认关闭；策略进入不可变路由版本，未审核工具在预留与派发前拒绝。不替代实际工具执行方的参数校验或用户/业务权限。

渠道配置指纹 v1：审核目录要求显式渠道 HMAC 指纹；绑定请求与价格版本，数据面对选中配置快照复核。配置漂移停新请求，历史完成事件继续恢复结算。配置审批 UI、跨实例立即撤销、真实供应商和生产切换尚未验收。

new-api 已增加可复现的 [治理链性能基线](new-api-performance.md)，验证调用次数、预算守恒、持久回执和审计链；本地短流/小样本结果不代表生产容量。

缓存费率推进至 v29：审核目录可选普通输入/缓存读/聚合缓存写/输出四类费率，按最大输入费率预留，原始计数和冻结单价支持崩溃恢复；目录与请求详情显示对应费用证据。启用前须排空所有旧控制面/恢复消费者，禁止新旧计费版本混跑。TTL/长上下文/服务端工具/音视频等附加计费仍不在当前支持范围。

20 并发开发基线已识别并修正内容审计原 16 路上限，改为有界 32 路并保留超额拒绝。Chat/Responses 长流的 8 组合成场景达到实际 20 路上游并发，逐笔费用、回执与审计封存核对通过；目标 32 GB 机器尚未验收，当前 4 vCPU/16 GiB 结果不是生产 SLA。详见 [性能基线](new-api-performance.md#20-并发验收配置与审计容量修正)。

受控 Messages 文本 JSON 已接通已有可信 Chat 执行链，要求原始缓存明细，分离普通输入/缓存读写计数；Token、设备路径证明、预算、内容审计和恢复规则共用。已补显式审核的 Anthropic 文本实时 SSE；工具/媒体 Messages 仍属后续开发，详细验证见接入文档。

## 缓存写入时长计费阶段

新增可选 5 分钟/1 小时独立写入价格、原始证据版本协商、冻结快照和恢复对账；v30 启动自动迁移保留旧价格与未知时长语义。管理 API、模型授权页、请求详情同步展示。合成上游双进程三协议故障门禁通过；客户端 cache_control、真实供应商缓存账单、其他计量单位仍未开放。详见 [接入记录](new-api-integration.md#控制面缓存写入时长计费schema-v30)。

## Messages 实时流阶段

显式模型开关、原始起始用量、实时检查点和最终停止封存已接通；SDK 低层/高级流与双控制面混合费率崩溃恢复专项通过。默认能力关闭，当前仅审核 Anthropic 文本渠道；原始完成证明不足时继续保留未知占额。真实供应商/终端验收及其他公共协议边界仍按接入记录逐项推进。


## Responses 文本输入扩展

补充客户端有界文本历史和 input_text 数组，保持角色顺序、输入关键词拼接检查与规范化审计。继续显式拒绝 developer、phase、输出对象、工具、媒体、缓存控制和服务端状态；字符串输入兼容。验收结果见接入文档。


## Messages 纯文本块扩展

messages 的 user／assistant content 和 system 增加有界 text 块输入，JSON／审核 SSE 共用；跨块关键词、规范化审计及故障恢复仍受原治理链控制。cache_control、citations、工具和媒体块继续拒绝，不以兼容纯文本块声称兼容全部 Messages／Claude Code。
