# ADR 0010：标准账单导入与人工对账

状态：已实现受限闭环，真实账单格式、账号及大陆部署验收待完成。

## 决策与信任边界

先支持标准 CSV，而不是假设百炼、方舟、智谱提供相同字段或能够用网关 request_id 自动关联。七列依次为 record_id、request_id、period、currency、amount、input_tokens、output_tokens；由操作人员根据官方账单与网关记录补齐准确关联，缺少关联可留空等待人工处理。不做模糊匹配；填写 request_id 也不构成供应商证据自动验真。

仅支持 CNY_MICRO，金额使用十进制整数字符串传输和 bigint 记账，1 元 = 1000000 单位。金额非负且不超过 9007199254740991；token 数为明确非负整数，不能以零冒充缺失信息。每批最多 100 条、24 KiB；标识字段限安全 ASCII 引用编号，禁止公式形式或正文，保留证据引用，不保存原始文件或附件。当前有效大陆配置缺失时账单接口不可用；配置审查仍不能替代实际部署驻留证明。

导入、查询、审核分开。导入仅组织 owner/admin 可操作，读取复用项目权限。标准化记录按 record_id 排序计算批次摘要，CRLF/行排序差异不重复导入；相同项目/摘要重试返回已有批次。组织内 provider/account_ref/record_id 唯一，跨项目也不能重复认领同一供应商记录，冲突时整批回滚。同一请求的多条未驳回证据显示 duplicate_request，须先排除重复候选。

## 审核与财务

财务通过需另一位组织 owner/admin，issuer+subject 不得与原始导入人相同。审核人显式提供最终关联 request_id、最终账单确认和原因。驳回不改变预算，允许导入人自行驳回错误证据。决定一经提交不可覆盖，revision 从 0 到 1；同一审核人、动作、请求与原因的精确重试幂等，其他重复决定返回冲突。

通过前按项目、供应商、周期、币种核对请求。缺少请求/供应商元数据、重复关联、超出预留、最近 5 分钟更新或有效执行租约阻止处置。用量差异可以由人工核实最终账单后在预留范围内处理，但差异会展示，不能自动判断账单可信。

只支持 dispatched/uncertain 的最终结算，以及 settled 同金额的证据确认。明确最终费用为零时记录 settled/actual=0 并清除对应预留，不把超时自动转成零费用。reserved、released、estimated_final、已结算不同金额与超过预留的账单均不强行调整，留待独立调整/贷项流程。账单导入不会让未出现在文件中的请求自动免单；缺少供应商记录不能当作零费用。

复用预算 request_id 事务级锁与固定顺序的组织/项目账户锁，财务变更、outbox、审核决定与审计在同一事务提交。任何审计或唯一约束失败都回滚财务变更。approved 的 resolved_request_id 有唯一索引，防止不同证据重复通过同一请求；并发自动结算遵守同一请求锁，审核必须重查最新账本状态。执行元数据和财务状态仍分开，不补造响应成功或结束 unfinished。

当前实现选择小批事务和有界列表；列表对每条记录进行索引查询以返回实时差异，尚未声明大账单容量。正式原生账单导入、签名/附件验真、自动拉单、折扣/税费/退款及终态差额调整另行设计。
