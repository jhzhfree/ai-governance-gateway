# 开发计划与验收

## 排期假设

以下是顺序与工作量参考，不是交付承诺。按 2 名后端、1 名前端、共享测试/设计支持估算约 8–10 周；人员更少应延长，不压缩安全和集成验证。TUI 安排在管理 API 稳定后。各阶段须以退出条件验收，发现兼容性或身份接入问题时重新估算。

| 阶段 | 参考时间 | 交付内容 | 退出条件 |
| --- | --- | --- | --- |
| M0 需求与技术验证 | 第 1 周 | 角色矩阵、低保真流程、首个供应商范围、OIDC/TUI 登录验证、选型 ADR | 首调流程可评审；SSE 与取消验证；锁定版本和部署约束 |
| M1 工程基础 | 第 2 周 | Go/Web 脚手架、PostgreSQL 本地验证环境、配置校验、迁移、OpenAPI、CI | 干净环境可重复启动；构建与实际测试通过；健康检查有效 |
| M2 推理纵向闭环 | 第 3–4 周 | 项目密钥、模型授权、单供应商、非流式/SSE、取消、调用元数据 | 使用测试供应商完成调用；跨项目越权失败；超时及断连无泄露 |
| M3 治理闭环 | 第 5–6 周 | 角色权限、限流、预算预留/结算、策略版本、审计与用量 | 并发预算不超额；故障重启可恢复；撤销和审计可验证 |
| M4 双端体验 | 第 7–8 周 | Web 引导、资源页和排障；TUI 概览/查询；CLI JSON 输出 | Web 完成首调；TUI 可登录切换项目并查记录；键盘与错误状态验收 |
| M5 发布准备 | 第 9–10 周 | 性能基准、安全测试、恢复演练、部署及接入文档 | 关键缺陷清零；已知限制公开；回滚和恢复通过演练 |

Web 可以从 M1 起基于契约和模拟数据并行开发，但不能在服务端授权和真实链路未验证时宣布业务完成。

## 第一轮可执行任务

技术选型同时执行[开源参考研究任务](open-source-references.md)：固定参考版本与许可证证据，对照 Bifrost/LiteLLM 验证网关，对照 TDesign/Coze Studio 验证 Web 流程，对照 Bubble Tea 验证终端。研究结果写入 ADR，不以列入参考清单代替技术验证。

已完成第一轮[源码研究及局部测试](research/findings.md)、PostgreSQL 并发账本、模拟供应商取消/恢复，以及[管理 API/权限/密钥闭环](management-api.md)。OIDC 已使用本地签名测试 IdP 验证，真实企业 IdP 和真实模型仍待验收，Web/TUI 本地集成增量见下文；Bifrost 目标测试仍受模块下载域名限制。

1. 确认组织登录、首个供应商与部署方式；完成 3 个 ADR：技术栈、预算一致性、管理认证。
2. 定义角色/操作矩阵和项目密钥权限；起草管理 OpenAPI 与推理兼容字段清单。
3. 画出首次接入、调用记录详情、预算编辑的低保真界面，覆盖失败与无权限状态。
4. 创建固定版本脚手架、开发配置样例和本地依赖启动方式，建立最小 CI。
5. 用模拟供应商贯通鉴权 → SSE → 取消 → 用量记录，作为首个可运行增量。

当前已实现[预算与 SSE 原型](prototype.md)，先验证两级预算事务、幂等结算及流式取消；见 [ADR 0001](adr/0001-budget-and-stream-prototype.md)。这属于 M0 技术验证增量，不表示 M1 脚手架、身份接入、Web/TUI 或整体阶段验收完成。

第二轮开发已补充 OpenAPI、组织/项目 RBAC、OIDC JWT 校验、一次性项目密钥、实时撤销与模型白名单、原子审计，以及本地 mock-only 服务入口，见 [ADR 0002](adr/0002-management-identity-and-project-keys.md)。这是 M1/M2 的后端纵向增量，不能将浏览器登录、真实身份提供方或生产部署标记完成。

第三轮开发已增加 [Web 控制台与浏览器会话](web-console.md)：组织/项目切换与创建、密钥管理、用量及审计，授权码/PKCE、Cookie 与 CSRF，以及桌面/移动浏览器验证。管理 JWT 和项目密钥都不存入浏览器持久化存储。

第四轮增加[版本化迁移](database-migrations.md)：不可变 SQL、旧库结构核对和数据保留、并发锁、整批事务、独立命令以及只读启动/readiness 检查，取代各模块自行建表。

第九轮完成[项目共享限流与只读故障核查](traffic-and-recovery.md)：项目并发租约、滚动 60 秒限频、策略版本/审计、未结束执行与预算账户重算，提供 Web 和 CLI。租约过期仅恢复接纳容量，不自动退款或重放。生产容量、全库保留清理与真实恢复演练待验收。

第十轮完成[供应商故障隔离与运行状态](supplier-resilience.md)：PostgreSQL 共享路由熔断、单次恢复探测、迟到结果隔离、项目未结占额汇总和有界实例 HTTP 计数；Web/CLI/TUI 使用同一受权接口。无自动重放、跨供应商切换或财务调整。生产遥测导出、容量、真实供应商恢复演练仍待验收。

本轮同时完成[整体功能覆盖核查](functional-coverage.md)，以源码和测试区分已有实现与长期目标；M5 生产发布条件未达成。

## 重点验收场景

- 管理员建立项目、授权模型并创建密钥；开发者完成一次非流式和一次流式请求，能查到同一 request_id 的记录。
- 非成员、跨组织 ID、撤销密钥、未授权模型均被服务端拒绝，响应不泄露资源或凭证信息。
- 多实例并发请求争用剩余额度时，预留账本保持约束；供应商 usage 缺失和进程中断不会导致预算被无条件释放。
- SSE 输出后上游断开不会触发隐式重放；客户端取消终止上游，费用状态可解释。
- 当前 PostgreSQL 故障出现明确错误和 readiness 变化；恢复后结算、审计任务可继续且不重复计数。
- Web 与 TUI 展示相同项目权限和用量定义；时间区间、币种、费用估算状态明确。
- 提示词、回复、认证头和供应商凭证不会进入默认日志与持久化记录。

## 指标与风险

M0 明确预期峰值并发、请求体大小、最大输出与测试硬件。M2 起测量网关自身非流式额外延迟、流式首字节开销、内存、连接数；将上游推理耗时单独统计。M5 在固定硬件、模拟上游和公开压测脚本下制定并验证容量目标，不能提前虚构吞吐或延迟承诺。

主要风险：供应商兼容差异（契约测试与明确支持矩阵）、费用估算差异（保守预留与对账状态）、双端重复实现（共享契约而非 UI）、范围扩大（首期单供应商与核心治理）、敏感数据泄露（默认不采正文、日志检查）、身份提供方不支持终端流程（M0 提前验证）。

每周演示可运行增量，并记录验收证据、缺陷与下一阶段阻塞。只有实际验证的能力可标记完成；设计方案和未来目标保持待办状态。
