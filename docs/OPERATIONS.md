# 部署、备份和恢复

## 本地运行

遵循README，Node24直接执行。默认HOST=127.0.0.1、PORT=8090，策略文件路径由POLICY_FILE指定。var目录700，.env 600。数据库文件应由操作系统umask限制为当前服务用户可读写。建议启动前设置`umask 077`。

## 容器预研

1. 准备已审查digest的Node24与Higress镜像，写入未跟踪的.env。
2. 执行`node --env-file=.env scripts/check-release.ts`。
3. 执行`docker compose --env-file .env -f deploy/compose.yaml up --build -d`。
4. 使用本机8001完成Higress路由与凭证配置，详见HIGRESS.md。
5. 执行本机烟测，停止模拟上游，确认实际请求进入Higress。

本轮未运行容器验证；模板不包含生产TLS/管理SSO/镜像签名、主机加固和HA配置。Higress内部8080不发布到宿主机，控制台和治理端口仅绑定本机。容器环境变量可以被容器管理者读取，生产采用密钥挂载或密钥管理系统。

## 备份

alpha只运行单实例。维护时先停止接收请求并等待在途调用完成，停止进程后复制数据库及仍存在的WAL/SHM文件和受保护配置，或者使用SQLite官方在线备份机制。禁止只复制正在写入的主db文件后假定备份一致。备份中包含身份摘要和账本元数据，应加密并限制访问。

恢复到隔离环境，执行数据库完整性检查，核对预算cap/spent/held和ledger事件。启动时遗留RESERVED会变为PENDING_RECONCILIATION，不自动释放。按真实供应商记录对账后结算，保留人工依据。pending账本不得通过删除DB重置。

## 升级

当前schema版本1，尚无自动生产迁移器。后续变更先备份，跑schema契约和恢复测试，再在预生产升级。生产迁移应使用显式版本号与只追加迁移，不能依靠CREATE TABLE IF NOT EXISTS替代迁移系统。当前不支持滚动多实例升级。

## 故障处理

上游错误/超时：按请求ID核对pending，不自动换键重试。预算不足：检查真实消耗和悬挂预占，再由管理员调整。503：检查文件系统空间、SQLite锁和服务进程，不将认证服务故障自动放行。认证401：检查有效期和撤销。初始admin到期后本版没有远程恢复入口，应在受控开发环境完成验证；生产轮换/恢复是P1阻断项。

健康接口只报告进程状态。生产需要独立就绪检查、指标、磁盘水位与审计积压告警，本版没有Prometheus暴露或长期SLA实测。
