# ADR 0020：预算变更事务中的站内阈值告警

状态：已实现并验证。

定时扫描会漏掉预留后迅速结算的短时越线。采用显式 Go 事务内评估，在预算写路径调用共享 budgetalert 包；不添加未纳入函数体漂移核查的数据库触发函数。配置写入遵循组织行 SHARE、组织/项目账户升序 UPDATE 的既有锁顺序，并在发布后检查当前余额，覆盖首次启用与配置/请求竞态。

按 spent+held 评估，PostgreSQL numeric 乘法避免大整数溢出；每个范围/周期/币种/阈值唯一。去重跨配置版本，避免频繁修改策略造成告警风暴；新周期重新计数。告警写失败使预算事务失败，保持原子性。默认关闭；零额度不产生比例告警。

持久提醒保存元数据快照；确认处理独立于预算，重复确认拒绝覆盖，操作与审计原子提交。组织权限与项目范围保持现有边界，CLI/Bubble Tea 只读，管理写入放在 Web。告警不是供应商调用成功证据，也不是外部消息的送达凭证。

此阶段只交付站内通知。境内经过审查的外部通道、签名、投递队列与幂等/重试/死信在后续阶段，不在网关事务内同步发送 HTTP，以免通知系统拖垮财务主链路。
