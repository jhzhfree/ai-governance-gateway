# ADR 0005：直接接收并校验原始 SSE

状态：本地受控接入，尚未开放主程序生产切换。接续 ADR 0004 的流完整性阻塞。

## 决定与代价

非流式 Chat 继续使用固定 Bifrost Core v1.14.1，并校验完整原始 JSON 的用量。流式 Chat 改为适配层自有的 net/http 接收器，先校验原始 SSE，再发出引擎无关事件。请求仍经过同一输入白名单、实例并发限制、生命周期与根治理链；每次请求仅选择一种物理执行路径，不在失败后重试另一种路径，也不做影子双发。

不通过 SDK 的可选 RawResponse 捕获来证明流完整性，也不引入临时反向代理或整份 SDK fork。复用固定 SDK 的公开 network 客户端以保留 TLS、代理环境与 SSRF 保护；不复制其源码。代价是本项目负责维护所支持 OpenAI Chat/SSE 子集的接收与兼容测试，不能将其他 SDK 流式供应商能力算成本项目已支持。

## 接收契约

- 地址由服务端 Config 构造，保持 BaseURL 前缀 + `/v1/chat/completions`；调用方不能提供 provider/base_url/credential。服务端添加 `stream_options.include_usage=true`。
- 生产使用严格非公开地址拒绝客户端，TLS 校验始终开启，拒绝所有重定向。测试例外只允许显式 TestLoopback 且地址为字面回环 IP；测试例外也不关闭 TLS 校验。客户端保留 SDK network 的代理选择策略，真实部署代理/出口联调仍待验收。
- 初始响应头最多等待 10 秒，每次阻塞正文读取最多 3 秒，整次 HTTP 调用最多 120 秒；上层更短 deadline 优先。消费者背压由同步 Emit 传递，Body.Close 或引擎 Close 可取消并回收上游。用户取消与空闲超时保留明确类别，原始 HTTP 错误不外泄。
- 仅接受 HTTP 200、text/event-stream 和未压缩/identity 正文。支持 LF/CRLF、多行 data、注释心跳和 `event: message`；其他 SSE 字段/事件类型拒绝。有效 UTF-8、完整 JSON、重复字段、单 choice/index、结束原因及用量规则逐帧检查。
- 每个事件最多 64KiB，整个原始流最多 16MiB；注释、空行和未知字段同样计数。4KiB 固定读取缓冲，长行在累积前检查限额，超大非转发事件不能绕过限制。
- 必须观察真实 finish_reason 和完整空行分隔的 `[DONE]`。EOF、残缺终止标记及读取错误都不是成功。`[DONE]` 是本次响应协议终点，之后的数据不属于已接受响应；不等待无限保持连接的服务端 EOF。
- 正文按顺序同步输出。最多暂存一个有界用量事件，只有看到有效 `[DONE]` 后才输出该证据。用量之后若出现重复/冲突、畸形事件、超限、断流或取消，则不输出可结算证据。缺失用量仍保持 nil，由治理层保留 uncertain。

## 治理验证

原集成中的 JSON/SSE、撤销、模型授权、设备拒绝、预算不足和审计失败继续覆盖。增加原始畸形 JSON、超过 1MiB 的非转发帧、用量帧后断开三类真实 HTTP/真实 PostgreSQL 场景：一份物理派发、一份 attempt、uncertain、actual 为 NULL、无成功 DONE、无原生链路回退。

接收器测试还覆盖重复用量、已结束后新增内容、缺失 finish/DONE/空行、无效 UTF-8、总心跳字节上限、读取故障与消费者失败，以及合法 CRLF/多行 data。网络测试核验 503 不重试、307 不跟随、错误媒体/编码拒绝、3 秒空闲后释放连接、正式模式拒绝回环连接、测试模式仍拒绝不可信 TLS 证书。

## 本轮关闭及剩余门禁

对当前声明支持的 SSE 子集，ADR 0004 中“SDK 解析丢弃/捕获截断”不再参与接收和计量依据；新增负向样本必须在引擎升级时持续运行。非流式仍固定 SDK，不能扩称所有协议/供应商均已证明完整。

主程序仍使用原生供应商路径。下一轮须处理三家实际端点路径、thinking 与 stream_options 差异、动态凭证轮换及共享执行池，再讨论受控启用。真实供应商、企业 IdP/终端、代理出口、容量和双节点故障等验收继续待完成。数据库无变化，保持启动自动迁移。
