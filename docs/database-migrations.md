# 版本化数据库迁移

数据库结构由 `internal/database/migrations` 的内嵌 SQL 统一管理。预算、治理和浏览器模块不再自行建表。当前迁移面向 PostgreSQL 17 的受管普通表，已验证从已发布原型库接管数据；它不是任意第三方 schema 的自动修复工具。

## 操作命令

设置专用环境的 `AIGW_DATABASE_URL` 后执行，保持现有 TLS 和认证配置，不在终端输出或聊天中粘贴连接字符串：

```bash
go run ./cmd/migrate status
go run ./cmd/migrate up
go run ./cmd/migrate check
```

这些命令不依赖 OIDC、模型供应商或 Web 构建。可在命令前设置超时，例如：

```bash
go run ./cmd/migrate --timeout=5m up
```

| 命令 | 行为 | 成功退出语义 |
| --- | --- | --- |
| status | 只读查询版本、待执行文件、接管标记与结构状态 | 输出状态 JSON；未迁移的空库也可查询，ready=false |
| up | 校验历史后，原子执行全部待迁移版本 | 输出升级后的状态 JSON |
| check | 只读校验当前二进制与库结构兼容 | 版本齐备、校验和与结构一致才成功 |

错误退出码为 1。历史不合法、旧 SQL 校验和不符、数据库版本比程序新或结构发生变化时，status/check/up 都会拒绝继续；错误不输出连接字符串、SQL 正文或行数据。数据库操作错误仅给出迁移版本及可用的 SQLSTATE。

正常网关启动只执行 schema 检查，不会创建表、接管历史或自动升级。推荐先在独立部署步骤执行迁移，再启动：

```bash
go run ./cmd/migrate up
go run ./cmd/gateway --mock-only
```

本地开发也可使用 `--migrate` 在启动前迁移；原来的 `--init-schema` 保留为弃用别名，执行同样严格的迁移流程，不再跳过结构验证。应用启动阶段受其启动超时约束，大型升级应使用独立命令。

## 当前版本

| 版本 | 内容 |
| --- | --- |
| 0001 | 预算账户、预留和 outbox |
| 0002 | 组织、角色、项目、模型白名单、密钥和审计 |
| 0003 | 浏览器登录流程与会话 |
| 0004 | 预算恢复扫描与登录流程过期清理索引 |
| 0005 | 项目调用账本按创建时间与 request_id 查询的复合索引 |
| 0006 | 增加 CNY_MICRO 独立币种及受控模型别名；保留原 MOCK 数据 |
| 0007 | 预算请求关联的执行意图/终态元数据和 outcome 索引；历史不回填 |
| 0008 | 项目限流策略、滚动窗口事件和并发租约；不修改既有预算与执行记录 |

`aigw_schema_migrations` 记录文件名、SQL SHA-256、结构摘要、执行时间及是否接管旧表。已发布 SQL 必须保持原样，变更只能新增递增编号文件；新建受管表还须登记到迁移模块的 managedTables。版本不可跳号，旧二进制不接受更高版本数据库。

所有待迁移版本位于同一个 PostgreSQL 事务中；事务级 advisory lock 按应用 schema 串行化升级。任何 DDL 或版本记录失败都会回滚整个待迁移批次，之前已提交的历史版本不受影响。取消、超时或连接失败后可先查询状态，再重试，不能假定缺少客户端成功响应就代表提交未发生。

重复执行不会重建表、重写历史记录、重置预算或重复创建索引。不提供 down、force、忽略校验和或直接修补记录的命令。

## 接管已发布的原型库

支持原 `d705631` 及之前已交付的无版本记录原型：预算阶段、治理阶段和可选浏览器阶段。测试 fixture 保留了该提交的原始 SQL，供后续兼容性回归，不能随新迁移改写。

在同一事务内创建临时对照 schema，执行不可变的前三个版本，比较既有阶段的实际结构：

- 一个阶段的受管表必须全部存在或全部不存在。
- 已存在表的列、类型、非空、默认值、identity/generated、约束、索引有效性、用户触发器及 RLS 开关/策略必须一致。
- 匹配后仅登记接管标记，保留原表和数据；缺失阶段正常创建，随后执行新版本。
- 缺表、额外字段、不同默认值或手工增加索引等差异会导致拒绝接管，不会删表、覆盖数据或自动修改成预期结构。

接管过程需要临时创建/删除自己生成的空 schema，因此首次接管角色额外需要数据库 CREATE 权限。临时 schema 在成功时删除，失败时随事务回滚。已完成接管后的正常查询和 readiness 不需要此权限。

旧的预算独立原型若没有组织身份信息，只保留其账本，不自动虚构组织 Owner 或补造业务关系；数据治理映射应另行明确处理。

## 就绪检查与权限

启动和 `/health/ready` 使用同一套只读校验：检查版本连续性、文件校验和及最新记录的受管表结构摘要。未迁移、待升级、版本过新、记录不合法或缺失索引等异常均拒绝就绪。`/health/live` 仍只表示进程存活。

结构摘要不包含行数据、序列计数、owner、权限授予、注释、非受管表、独立函数/视图或扩展定义。因此它不是数据质量审计、授权安全审计或完整 PostgreSQL schema 比较器。修改受管表的索引也必须通过迁移，否则会触发结构漂移。PostgreSQL 大版本升级可能改变 catalog 输出，必须提前验证，不能自动重新盖章。

迁移角色需要相应 schema/表 DDL 权限；运行角色只需要业务 DML、读取迁移记录和系统 catalog。应用 schema 由连接 search_path 选择，拒绝系统 schema；迁移和检查在事务内固定到该应用 schema，其他应用表不被自动纳入管理。当前未自动创建或授予数据库角色，权限配置仍需部署管理。

## 验证与剩余边界

使用统一验证脚本；完整回归包括 Web：

```bash
AIGW_VERIFY_WEB=1 bash scripts/verify.sh
```

新增真实 PostgreSQL 测试覆盖空库与只读状态、完整旧库和预算旧库升级、数据保留、旧结构拒绝、八个并发迁移调用、DDL/版本记录共同回滚、历史/结构漂移、锁等待取消、独立 CLI 配置路径和 readiness。现有预算、鉴权、登录与 Chromium 场景继续使用同一迁移建库路径。

本轮实际验证（2026-11-03）：38 个后端/会话/迁移顶层测试、26 个 Go 子测试和 3 个 Chromium 端到端场景通过，0 失败、0 跳过；另有 Go fixture 承载浏览器测试。模块校验、go vet/race、OpenAPI、冻结前端安装、类型差异、TypeScript/ESLint/Prettier、生产构建与页面 axe 检查通过。结果来自当前环境，不代表 GitHub 托管 CI 或生产数据库升级已验收。

当前执行器仅支持事务内 SQL。`CREATE INDEX CONCURRENTLY` 等非事务 DDL 会失败并回滚，需要未来设计独立流程，不能直接放入现有批次。尚未完成生产备份恢复演练、真实大库锁时长和容量评估，也未声称整个产品已生产就绪。
