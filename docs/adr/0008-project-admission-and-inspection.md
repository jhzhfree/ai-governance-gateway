# ADR 0008：项目共享限流与只读故障核查

状态：已实现，生产容量和真实供应商恢复演练待验收。

## 决策

本阶段采用 PostgreSQL 事务级 advisory lock，在同一项目下串行完成策略读取、有效租约/滑动窗口统计和接纳记录写入。策略修改使用同一把锁，加 expected_revision 比较并在同一事务写审计，避免多个管理员覆盖配置。默认 60 次/滚动 60 秒、4 个并发租约；允许 1–10000 次和 1–64 个租约。不提供无限制开关。

选择现有 PostgreSQL 可复用持久化、事务、故障模型与部署依赖，直接验证多实例共享计数，避免在预算数据库之外增加 Redis 故障一致性协议。代价是每次接纳涉及数据库事务，同项目热点串行，尚未提供容量基准；Redis 仍是未来经压测证明需要后可选择的实现，并非当前限流的运行依赖。

在授权与请求校验通过后、预算预留和供应商派发前获取租约。超限返回 429 和正整数 Retry-After；数据库或策略读取失败返回 503，不放行。已被接纳但随后预算不足或供应商失败的请求仍消耗频率窗口；拒绝不占额、不产生执行尝试。降低限额不会重置窗口或中止正在执行的请求。并发 Retry-After 根据最早租约到期提示等待值；主动释放可能使容量提前可用，限额降低或其他请求竞争也可能使该时刻仍需等待，它不保证预约容量。客户端应避免无界重试。

租约 180 秒；接纳后处理上下文最多 120 秒，接纳事务最多 3 秒，响应写入有 2 秒期限；结束时独立 3 秒上下文释放租约。异常退出或释放失败依靠租约自然到期恢复接纳容量。唯一 lease_id 确保迟到释放不会删除新租约。系统依赖数据库时钟稳定，所有网关都必须执行同样的处理期限。

租约约束网关接纳容量，不证明供应商物理执行数：网络超时/取消后供应商可能继续计费。任何到期都不自动释放财务预留、不重写执行终态、不重放供应商请求。长任务、流式任务超过 120 秒的需求需重新设计续租与超时协议，不能直接延长期限突破租约边界。

## 核查

GET inspection 在 repeatable-read 事务中形成单页一致快照，比较账户 held/spent 与预留账本重算值，列出超过阈值的开放占额或 unfinished 执行，并关联有效租约。金额以十进制字符串传输，避免 JS 数值精度损失。组织聚合账户仅组织 owner/admin 可见；其他有项目访问权限者只能看到项目账户。账户最多 100 条并显式标记截断，请求按创建时间/request_id 游标分页，每页有自己的快照，不承诺多页全局快照。

只读核查可能持有权限行共享锁，但不改变数据。无记录不证明供应商无费用；metadata_unrecorded 提醒历史或记录失败情况，不能补造结果。Web 和 CLI 使用同一管理 API；TUI 现有调用详情仍可查询相应 request_id，暂不增加独立核查屏幕。

接纳记录只保留当前活动项目最近一分钟的事件，后续成功接纳时清理旧事件/租约；闲置项目残留不参与计数，并非永久日志或导出接口。全库定期保留清理、自动对账、人工调整接口、熔断和重试均留待后续设计。
