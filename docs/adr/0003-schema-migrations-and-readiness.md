# ADR 0003：统一迁移、旧库接管与只读就绪检查

状态：实现与本地 PostgreSQL 验证。

## 决策

把分散在预算、治理、浏览器模块的建表 SQL 迁入统一内嵌目录。应用默认不做 DDL；独立 migrate 工具提供 up/status/check。保留旧开发标志为严格迁移的兼容别名。

当前只有少量事务型 PostgreSQL 迁移，使用现有 pgx 事务与 advisory lock 实现受限执行器，避免同时维护两套迁移状态。Goose/golang-migrate 等成熟工具可覆盖更广泛的迁移场景，但旧原型结构等价接管和运行期结构核对仍需本项目的专门验证逻辑。本实现不定位为通用替代品；未来需要非事务 DDL 时应重新评估执行方案。

历史文件按 SHA-256 校验，待执行批次整体提交。原型库通过临时对照 schema 的 catalog 比较后接管，不使用 IF NOT EXISTS 掩盖既有差异。所有受管表结构摘要随版本保存，启动/readiness 只读验证，不在流量路径中自动修表。

## 取舍

完整批次事务便于失败恢复，但 DDL 锁可能持续到批次提交；大型数据升级和并发建索引需要未来扩展。结构核对以当前 PostgreSQL catalog 表达为基础，数据库大版本升级需专门验证。严格检测额外索引意味着人工调优也应转为版本化迁移。

拒绝自动降级和 force/repair，保护账本和权限数据；不保证旧二进制可以直接回滚到新库。应用回滚需遵循 expand/contract 和明确的兼容窗口，生产还需备份恢复与锁时长演练。
