# 页面操作手册

> 单进程分支提示（2026-11-08）：`feature/v1-single-process-commercial` 现在以进程内 Bifrost 为产品入口，并已开始提供对应候选安装包；下文四协议和双进程能力仍是旧分支基线，不等于新引擎已全部迁移。新引擎已接入受控文本 Chat、无状态文本 Responses JSON/SSE 和仅输入计费的文本 Embeddings JSON；原生 DeepSeek Messages 文本 JSON 已接入 0035，0036 增加显式审核的实时流；工具和多模态仍在迁移。当前启动与安装以 [单进程入口](../engine-entrypoint.md)、[Linux 候选包](../linux-package.md) 和 [交付跟踪](../v1-delivery.md) 为准。

版本和适用范围见 [文档中心](README.md)。页面名称以当前导航为准。金额、请求状态和审计内容是不同事实，不应互相代替。

## 新控制台导航与金额展示

桌面导航分为工作台、模型与访问、费用治理、安全与审计、组织与系统五组；短屏可在侧栏内滚动。移动端使用右上角“导航”按钮展开，选择页面后自动收起；键盘可用 Escape 关闭并返回按钮，或使用“跳到主要内容”跳过导航。

页面仍按组织/项目授权读写。概览预算卡片将人民币显示为元，保留最多六位小数，避免将微元费用显示为零；悬停可查看账本原始单位。表单、账单与 API 继续以各自标明的单位输入，不应直接把页面元数值当作微元提交。供应商页显示当前执行方式，路由配置就绪只说明本地配置与执行器条件满足，不代替真实厂商调用验收。

## 单进程文本向量接入

在“供应商与模型”页确认执行方式为进程内 Bifrost，选择阿里云、火山引擎或智谱的已审核路由，将 API 类型改为“文本向量”，配置实际供应商模型、公开模型名、输入费率及输入额度后发布。输出费率与输出上限固定为 0；DeepSeek 没有此向量适配。切回对话时必须重新填写输出费率和上限。供应商密钥由平台管理员托管，应用使用项目密钥。

在项目模型授权中允许该公开模型，再用 OpenAI 兼容 SDK 调用 `/v1/embeddings`，显式设置 `encoding_format="float"`。当前只接受文本字符串或文本数组；base64、预分词 token ID、图片和音频不在此范围。阿里云最多 10 条文本，火山/智谱最多 16 条；维度选项和细项边界见 [向量接入契约](../../modules/engine/docs/adr/0012-embedded-embeddings.md)。输入估算超限会在预留与派发之前拒绝，应调整文本长度或审核路由额度；此估算不能代替供应商实际 token 计量。

完成后，在“调用账本”按 `X-Request-ID` 查详情。“供应商完成证据”显示“文本向量 · 仅输入计费”，输入数量来自供应商原始 usage，输出为此协议的零输出语义，费用使用派发时冻结的输入费率。`awaiting_usage`、`recorded` 和 `receipted` 分别表示缺证据、证据已保存、回执已生成；未知状态保留占额，不能手工当作免费或重发请求。回执不证明客户端收到向量。真实供应商账号仍须独立验收。

## 单进程原生 Messages 接入

供应商配置中选择 DeepSeek，将“接口能力”设为“原生 Messages · 文本”，填写供应商实际模型名和经核验的缓存命中费率后发布；不使用 `claude*` 映射别名。同一模型不能同时标为 Chat 和 Messages 上游能力，需要两种协议时建立不同模型条目。继承的输入价格只是编辑初值，发布前需核对合同与版本；当前仅支持原始缓存写入计数明确为零的响应。

授权项目模型后，客户端使用网关项目 Key，调用 `POST /v1/messages`，字段为 `model`、`max_tokens`、`messages`，可加 `system`；使用 `anthropic-version: 2023-06-01`，Key 放 `x-api-key` 或 Bearer 其中一种。支持字符串/纯 text 块；规范化后必须是可选首条 system、交替 user/assistant，并以 user 结束。SDK 多轮历史同样受模型输入估算上限限制。此原生模型也可承载受控 Chat/Responses。实时流默认关闭；经核验供应商原始早期计数、最终累计计数与完整结束事件后，在同一页面勾选“已核验供应商原始起始用量与完整结束事件，启用文本实时流”并发布。随后三个公共入口均可使用 `stream:true`；未经审核的请求在预留/派发前拒绝。工具、图片、thinking、beta 等尚未开放。

完成后在“调用账本 → 详情 → 供应商完成证据”核对“原生 Messages · 缓存命中计费”、总输入/输出、缓存命中/未命中、原始缓存写入 0、冻结单价与回执。计数缺失会保留未知费用，不能把未取得当作零；成本报表只把已记账且匹配原始证据的记录纳入缓存覆盖。具体完成契约见 [ADR 0015](../../modules/engine/docs/adr/0015-embedded-messages-json.md)。实时流细节见 [ADR 0016](../../modules/engine/docs/adr/0016-embedded-messages-realtime.md)：起始数量仅供展示，最终数量不能相加；缺少 message_stop 不生成完成事件。原生流只接受从空 text 起始、顺序编号的纯文本 delta；部分输出已经送达后发生错误仍可能保留未知费用。最终审计失败不会伪装成功，也不会丢弃已经确认的供应商费用。

## 1. 使用前准备

向实施人员获取正式 HTTPS 访问地址、登录方式、组织/项目授权。平台没有可直接使用的默认管理员密码。外部 OIDC 与本地账号是两种部署模式，本地账号登录不代表产品提供标准 OIDC 身份服务。

权限应分别配置：

| 身份/权限 | 用途与注意事项 |
| --- | --- |
| 组织 owner | 组织治理、组织角色管理、交接及审计员授权等；不是自动的平台管理员 |
| 组织 admin / 项目管理权限 | 授权范围内的项目、预算、模型、密钥及成员操作；具体操作由服务端判断 |
| 开发者 / 只读成员 | 访问被授予的项目；页面显示和按钮可用性不能替代服务端鉴权 |
| 供应商平台管理员 | 按精确 issuer+subject 配置，维护全局供应商目录和凭证 |
| 系统管理员 | 独立 issuer+subject 配置，查看主机与修改允许的网络配置 |
| 本地账号管理员 | 本地账号生命周期；创建账号不自动授予组织/项目权限 |
| 项目内容审计员 | 独立授予的正文查看权；组织 owner/admin 不自动获得解密权 |

### 登录、退出和页面结构

OIDC 模式跳转企业身份服务登录；本地模式填写用户名和密码。首次创建或重置的本地账号必须先改密，再重新登录。遇到会话过期，重新登录，不连续重试保存操作。

```text
侧栏：17 个导航入口       顶部：当前身份、退出
                        工作区：组织 / 项目选择、当前角色、刷新
                        页面：指标或列表 → 筛选/编辑 → 确认 → 操作反馈
```

供应商配置、系统管理、本地账号属于全局或身份范围，不因切换组织而改变其管理对象。本地账号入口仅在本地模式显示。其他页面先核对组织和项目；看到同名资源时以 ID 为准。列表的“更多”/继续加载只扩展当前范围，不表示已下载全部历史。

管理页面首次打开时按需加载，短暂显示“正在加载功能页面”。若网络中断或升级使页面暂时无法显示，侧栏仍可切换到其他页面；网络恢复后点击“重新加载页面”。重新加载不会自动提交或重放业务操作，尚未提交的表单内容不会保留。已经发送的操作应先查当前状态或审计记录，再决定是否重试。

退出会使当前服务端会话失效。不要把浏览器 Cookie、CSRF 值、CLI 令牌、项目密钥复制进截图、工单或聊天。

## 2. 首次开通：从登录到一次调用

1. 运维完成数据库、身份、域名、加密密钥和供应商平台管理员配置。
2. 平台管理员进入“供应商配置”：native 模式保存本地厂商凭证；newapi 模式管理数据面渠道、核对审核指纹，再配置模型与真实价格/依据并发布。普通启动没有演示模型；目录尚未配置时，应从管理入口完成初始化。
3. 创建组织，核对币种与预算周期；创建项目并设置预算。
4. 在“项目概览”的模型授权区域选择实际可用模型；不以厂商任意模型名代替网关模型 ID。
5. 在“访问密钥”创建最小权限密钥，立即保存一次性明文。
6. 应用使用 HTTPS 网关地址、项目密钥和已授权模型调用。真实厂商调用可能产生费用。
7. 在“调用账本”按返回的 request_id 核对执行、结算和占额；再查看成本报表。
8. 需要设备准入时，先完成设备登记确认及代理联调，再启用项目强制策略，避免直接封锁现有应用。

普通项目密钥调用示例（凭证通过安全环境注入，示例不会自动执行）：

```bash
curl --fail-with-body "$AIGW_BASE_URL/v1/chat/completions" \
  -H "Authorization: Bearer $AIGW_PROJECT_KEY" \
  -H 'Content-Type: application/json' \
  --data '{"model":"PROVIDER/APPROVED_ALIAS","messages":[{"role":"user","content":"合成验收请求"}],"max_tokens":32}'
```

强制设备准入的项目不能用此方式绕过设备证明；应经已登记设备的本地代理接入。当前只支持受限文本聊天协议，不能按“兼容 OpenAI”推断支持所有接口、工具或多模态。

## 4. 项目概览

**前提**：已经拥有组织/项目访问权限；创建组织需要当前目录提供可用币种。

1. 在顶部选择组织、项目，核对当前角色与预算周期。
2. 有管理权限时使用“新建项目”；填写名称和预算等页面要求，不将组织余额误当作项目独立额度。
3. 查看预算总额、已结算、占额和剩余值。组织和项目预算都可能限制调用。
4. 在模型授权区域从当前目录选择模型并保存；模型应同时满足项目授权与密钥授权。
5. 刷新后确认列表反映新授权。撤回模型授权可能使现有密钥的相应调用失效。

**常见情况**：没有项目可能是未创建或未获授权；不能仅凭空列表认定数据丢失。目录为空先联系供应商平台管理员。

## 5. 访问密钥

1. 选择项目，创建密钥并填写可识别的名称；按实际需要限定模型。
2. 在一次性弹窗中复制明文，保存到应用的秘密管理系统。关闭后只能看到元数据，不能找回原明文。
3. 应用用该密钥调用推理接口；它不能登录管理控制台。
4. 泄露、人员变动或应用下线时，选中对应密钥并确认撤销；根据名称、前缀与创建者复核对象。
5. 用新密钥验证应用，核对旧密钥已被拒绝。撤销不会抹除历史账本，也不自动退款。

不要把供应商 API Key 填作项目密钥；供应商凭证属于平台统一托管范围。

## 6. 审计记录

在选定组织下查看操作主体、动作、对象、时间等元数据，按页面支持的加载方式查阅历史。调查时记录组织 ID、对象 ID、request_id 和时间范围。

这里不是模型正文浏览器，也不是所有认证失败的全量协议日志。正文需走“内容审计”的独立权限和查看留痕；系统网络操作历史在“系统管理”查看。缺少记录时先确认范围、权限和记录类型。

## 7. 调用账本

1. 选择项目并查询列表，使用 request_id 打开详情。
2. 分别核对模型、供应商、价格版本、预留额、实际金额、执行结果和物理 attempt。
3. 对失败或断流请求，检查是否已经派发、有无可靠用量证据，再决定是否进入人工对账。

单进程 Chat 记录在详情下方提供“供应商完成证据”卡片：分别显示未取得证据、完成证据已记录、已生成结算回执。核对记录用量、派发时冻结单价、回执金额和时间。CNY_MICRO 在卡片转换为元，保留微元精度；缺失证据显示“未取得”而非零。进程崩溃后可能出现“执行未结束”但“已生成结算回执”，表示费用已恢复，不代表客户端成功。成本报表及标准账单核对使用已结算证据，详情见 [调用账本](../request-history.md#单进程供应商完成证据)。查看或刷新不会重新派发或触发扣费。

| 财务状态 | 操作含义 |
| --- | --- |
| reserved | 已预留；不能仅因暂未看到回复就释放 |
| dispatched | 已派发，可能产生费用 |
| uncertain | 结果/费用尚不能确定，保留占额，等待核查 |
| settled | 按已有可信证据结算；执行状态仍应独立查看 |
| released | 已按对应流程释放，不代表所有失败都可进入此状态 |
| estimated_final | 按明确估算流程终结，不是供应商最终账单 |

执行未完成不等于免费；财务审核完成也不会把执行状态改为成功。列表以已建立账本的请求为基础，认证或预校验阶段拒绝不一定出现在这里。

## 8. 流量与核查

### 限流与运行状态

核对项目请求速率和并发上限，根据实际容量修改授权范围内的设置。429 可能来自速率、并发或其他接纳条件；结合响应错误与运行状态确认，不直接提高预算解决。运行状态中区分供应商熔断与应用存活，不将单个实例状态当作所有实例状态。

### 开放占额与账单对账

1. 查询需要核查的开放请求，先查看 request_id 详情与供应商证据。
2. CNY_MICRO 项目可使用“账单对账工作台”；选择供应商并填内部账户引用、最终账单证据引用。
3. 导入标准 CSV（不是直接兼容所有厂商原始文件）：

```csv
record_id,request_id,period,currency,amount,input_tokens,output_tokens
synthetic-row-001,GATEWAY_REQUEST_ID,2026-11,CNY_MICRO,14000,300,200
```

4. 一批最多 100 条、24 KiB；缺失 token 不可猜成 0，供应商请求号不能冒充网关 request_id。
5. 导入只保存待核对记录，不直接改变余额。由另一位有权限的组织管理人员核验最终证据并批准；导入人不能自审通过。
6. 被拒绝的证据保留记录；金额超过原预留上界、周期/币种不符、有效租约等条件可能阻止结算，应保留问题并核查，不能反复换编号绕过。

具体审核约束见 [账单对账](../billing-reconciliation.md)，以当前 0030 结构运行，不按专题中的早期迁移号停留。

## 9. 成员管理

使用稳定的 issuer+subject 识别成员，不以同名昵称或邮箱猜身份。组织角色、项目授权、部门授权可能共同影响有效权限。

1. 选择组织，核对要操作的成员；按权限配置组织角色或项目角色。
2. 移除单个项目授权后，检查是否仍通过其他授权路径拥有访问权。
3. 人员离职时使用组织成员停用流程，填写原因并核对影响；本地账号或企业 IdP 的全局停用需另行处理。
4. 恢复成员时重新选择适当角色。旧密钥和已撤销授权不会因恢复自动复活。
5. 遇到版本冲突，刷新成员当前状态再操作，不能提交旧页面覆盖其他管理员修改。

Owner 交接使用“组织交接”，不要通过普通角色编辑模拟转让。专题见 [成员生命周期](../organization-member-lifecycle.md)。

## 10. 部门管理

维护部门树、成员和项目关联，并核对部门带来的项目访问范围。更改项目归属后，对当前授权与后续费用归集分别验证。

成本归属使用请求预留时的部门路径快照。项目迁移部门不会把历史费用自动改挂新部门；旧记录可能显示“历史”或“未归属”。部门报表不是可靠的员工个人计费账单。历史归属不能授予当前已撤销的访问权限。详见 [部门费用归集](../department-cost-attribution.md)。

## 11. 终端准入

1. 先在终端生成独立设备密钥对，仅提交公钥；私钥留在终端受控目录。
2. 在“终端准入”登记或查看待确认设备；组织 owner/admin 核对所属人员和公钥后确认。
3. 使用 CLI 设备代理绑定组织、项目与设备 ID。代理向网关申请短期设备会话，并提供本机 SDK 入口。
4. 验证成功后启用项目要求设备准入的策略。再次测试：合法设备可用，普通项目密钥直连不能绕过要求。
5. 设备丢失、换机或人员离职时撤销设备/相关授权，验证后续请求被拒绝。

管理员确认不等于终端安全体检；当前不提供完整 EDR、软件安装控制或网络出口防绕过。五分钟设备会话、DPoP 公钥绑定及防重放限制只属于网关准入能力。代理命令与本地令牌文件权限见 [终端准入说明](../device-admission.md)。

## 12. 内容审计

### 开启采集

1. 运维先配置独立内容审计加密主密钥与有效的供应商部署条件。
2. 组织管理人员在当前项目明确开启，填写告知/授权依据、保留天数和每方向采集上限。
3. 范围：保留 1–90 天，每方向 1024–262144 字节。策略修改作用于后续请求，旧记录沿用采集时的策略。
4. 生成一条合成测试请求，核对采集状态、截断标识和到期时间。

### 授权与查看

由组织 owner 独立授权项目审计员。审计员可使用专用入口 `/?audit_only=1&org=ORG_ID&project=PROJECT_ID`；选择记录、填写查看理由后查看。查看前会验证权限并记录访问；失败尝试也可能留痕。

正文可能完整、未完成、截断、取消或已过期，不得把部分内容称为完整取证。过期清理与主密钥保留需协调；删掉历史密钥可能使仍需保留的数据无法解密。内容审计不自动等于护栏；关键字策略在独立页面配置。

## 13. 供应商配置

此页面影响全部署，只有明确配置的平台身份可发布。

1. 核对供应商：阿里云百炼、火山方舟、智谱、DeepSeek；服务入口受代码约束，不可随意填写 Base URL。
2. 保存供应商 API Key：填写秘密输入框并提交，之后只查看状态，不回显原值。页面托管需要预先配置供应商加密密钥。
3. 配置模型行：供应商、网关别名、厂商模型/endpoint ID、价格版本、输入/输出价格、token 上界、部署与模型依据及有效期。
4. 使用真实合同数值，不把示例价格直接发布。最多 32 个模型，别名唯一，发布时按当前版本整体替换。
5. 发布成功后查看版本与可用模型；若返回 409，刷新最新目录，重新核对后编辑。
6. 发布不会自动向厂商发推理请求；“凭证已配置”也不代表已验证账号的付费/模型权限。单独安排真实验收。

数据库托管凭证优先；环境注入变更需要重启相应实例。各实例仍应检查 readiness。使用兼容的只读配置文件模式时不能期待页面发布生效。DeepSeek 用量边界见 [接入说明](../deepseek.md)。

## 14. 系统管理

**只读部分**：核对节点名、采样时间、CPU、内存、cgroup 限额、网卡和 DNS。首次 CPU 差分可能未知；cgroup 指标不是任意服务的独立配额。DNS 可能显示本机缓存解析器。容器内观测不自动等于宿主机。

**网络变更前提**：专用系统管理员、Linux 主机代理已正确部署、NetworkManager 支持所需 API、接口在允许列表中、已连接的普通以太网 profile；保留带外恢复通道。

1. 核对节点及接口，选择 DHCP 或静态 IPv4，填写地址/网关/DNS/是否接受自动 DNS以及操作原因。
2. 查看预览，确认目标无误后临时应用。网关先提交操作意图审计，再调用代理。
3. NetworkManager 创建 90 秒检查点；在稳定管理地址验证连通性后确认保存，最后 15 秒不能开始确认。
4. 不合预期时回退；界面未证明恢复前不要把“已接受回退请求”当作完成。
5. 失联、超时或结果未知时，使用带外入口核对实际配置和历史记录；不要直接重复提交。

不支持通过此页修改 Wi-Fi、桥接、Bond、VLAN、IPv6、MTU或删除接口。NetworkManager 重启、主机断电不在自动超时回退保证内。当前仅有合成通信验证，实机验收是启用生产写操作的前置条件。详见 [系统管理部署与边界](../system-management.md)。

## 15. 本地账号

仅本地模式显示。普通用户可修改自身密码；本地账号管理员可创建账号、分配本地管理权、停用/启用、重置密码、撤销会话并查看安全事件。

创建账号后先完成首次改密，再单独授予组织权限。停用会撤销相关会话/令牌及该身份创建的项目密钥；恢复不会还原旧密钥。管理员不能通过页面停用自己或取消自己的管理权。密码不得写入命令参数，离线初始化使用 TTY 或受控标准输入。密码至少 12 个 Unicode 字符，最多 256 UTF-8 字节。

修改密码、重置或撤销会话后，应重新登录，确认旧会话不可继续操作。在途模型请求可能仍产生费用。专题见 [本地身份](../local-identity.md)，其中旧迁移版本须以本手册基线为准。

## 16. 预算管理

分别查看组织与项目预算，确认币种、周期及当前已结算/占额。新上限不能破坏已有费用和占额约束。

1. 填写新上限与调整原因，核对页面显示的版本及影响。
2. 若启用双人审批，提交申请后由另一位具备权限的管理员批准；申请者不得自审。也可按权限驳回或撤回。
3. 批准前再次核对当前额度、期限和申请状态；并发变化或申请过期可能使操作失败。
4. 月度轮转按 UTC 月份处理；轮转策略与立即切换周期分别配置。手动切换应核对新周期并完成页面确认，不把切周期用作清理旧账。
5. 切换后验证新请求使用新周期；旧请求、占额、审计仍需按原账本核查。

## 17. 关键字匹配

编辑当前项目规则，填写规则文本、字面/正则方式、输入/输出/双向以及告警/阻断处置。保存后用合成文本验证命中记录中的请求编号、规则与策略版本、方向和处置。

告警留痕不会自动增加预算；阻断也不保证厂商未计费，特别是输出阶段已经发生调用。规则匹配不等于通用语义安全审核；当前文本子集不能覆盖工具和多模态内容。变更前评估误拦截，用测试项目验证后再启用正式策略。

## 18. 成本报表

1. 选择组织或项目范围，输入日期范围及页面提供的模型、供应商、部门等筛选条件。
2. 提交查询后查看分组结果；按币种分别解释，不把 MOCK 与 CNY_MICRO 相加。
3. 已结算、估算终结和开放占额分别核对；用量覆盖不完整时，不自行补零推算精确单价。
4. 部门筛选支持历史 ID/状态；部门迁移前后可能分成不同历史路径组。
5. 导出使用已提交的查询条件。先提交新筛选再导出，不以未提交输入框内容推断文件范围。
6. 导出文件包含业务元数据，按企业访问与保存要求处理。文件导出需要审计成功，不应绕过失败直接从数据库导出给无权限人员。

财务金额以整数最小单位保存：CNY_MICRO 的 1,000,000 微元为 1 元。页面展示与 CSV 单位应分别核对，不能把底层整数当成人民币元。

## 19. 预算告警

设置组织/项目阈值，查看按“已用＋占额”触发的告警。相同周期同一阈值只提醒一次。确认告警时记录处理意见，再到相关页面进行实际调额或核查。

“已确认”只表示处理留痕，不会增加预算、释放占额或解除拦截。当前站内告警不代表已接入邮件、短信或企业 IM。

## 20. 组织交接

当前所有者先在成员管理确认接收方已是组织成员；本地接收账号须已启用并完成首次改密。进入页面选择该成员、填写原因并确认身份，发起交接。接收方须用自己的账号登录，在 24 小时有效期内核对组织、来源和原因，勾选后接任。此流程不创建或邀请外部账号，发起人不能代替接收人确认。接受前可由当前发起所有者取消。

完成后原 owner 变为 admin，接收成员成为 owner；重新登录或刷新，验证新旧身份的有效角色及管理操作。原 owner 的既有项目密钥及独立审计授权不会因此自动撤销，离职时需继续核查。接收方停用、权限变化或并发交接可能阻止操作；恢复账号不自动复活已经取消的交接。见 [组织所有权交接](../organization-ownership.md)。

## 21. 常见问题与处理

| 现象 | 首先检查 | 处理原则 |
| --- | --- | --- |
| 401 / 会话过期 | 登录状态、模式、issuer/origin | 重新登录；确认此前保存是否已完成 |
| 403 / 无权限 | 当前组织/项目及独立平台权限 | 联系授权方，不靠切换 URL 绕过 |
| 409 / 版本冲突 | 是否有其他管理员修改、操作是否仍 pending | 刷新并复核，不盲目重复提交 |
| 429 / 接纳受限 | 限流、并发、预算及具体错误信息 | 降低速率或调整经核验的对应设置 |
| 503 / 服务不可用 | 数据库、供应商配置/证据、代理、运行状态 | 保留 request_id，恢复依赖后再核查 |
| 密钥关闭后看不到明文 | 是否已关闭一次性弹窗 | 新建替代密钥，撤销遗失旧密钥 |
| 请求失败但仍占额 | 是否已派发、是否 uncertain | 按账单/证据核查，不自动退款 |
| 内容无法查看 | 独立审计授权、到期状态、密钥版本 | 走审计恢复流程，不把密钥发给页面用户 |
| 改 DNS 后管理页失联 | 目标节点、检查点、带外通道 | 核对真实网络状态，不宣称已自动恢复 |

提交工单时提供软件 commit、时间范围、组织/项目/节点 ID、request_id、脱敏错误；不要附真实提示词、回复、密码、密钥或浏览器会话。

## new-api 执行模式的操作差异

运维显式启用 new-api 模式时，项目模型授权、Token、预算、终端准入及审计页面继续使用原有流程。厂商密钥、渠道 endpoint 和模型映射由独立 new-api 控制台维护；企业网关读取经审核的价格/模型目录文件，不要求再保存同一份厂商密钥。目录修改后由运维受控重启，不能把供应商配置页的修改当作已经发布到该模式。

发生超时或进程故障后，请先查看请求状态与费用：`uncertain` 表示没有足够的最终证据，预算占额会保留；有可信完成事件时后台可以补记费用，因此“客户端没收到答复”不代表模型未执行。不要自行重复提交原始请求以试图解除占额。本模式首版 SSE 等待上游完成后才交付；适用范围与运行门禁见 [new-api 接入说明](../new-api-integration.md)。


### new-api 审核供应商账单

在项目的“账单对账工作台”选择“其他已审核供应商”，填写模型审核目录或该项目历史调用中记录的供应商标识，再填写账户引用、证据引用和标准 CSV。系统拒绝没有审核目录或项目历史依据的标识。导入不会直接扣费，仍需另一名管理员核对并审核；审核、重复导入和恢复沿用原有规则。

new-api 模式下供应商密钥由数据面管理。公共入口包括受控 `/v1/chat/completions`、`/v1/embeddings`、`/v1/responses`、`/v1/messages`，各自限制见后文；实时内容块通过治理后逐步返回，只有用量完整、数据面持久完成并通过完成证明校验，才返回成功结束。断流或完成证明丢失可能保留占额，随后由恢复对账处理；不得通过重复发送同一业务请求来代替核对。当前支持 OpenAI 兼容、DeepSeek 和 Anthropic 上游文本协议，不表示全部原生 API 已开放。


## 受控 Embeddings 接入

管理员在 newapi 审核目录配置 `api: embeddings`，输入费率/整批 token 上限及真实模型名，输出费率/上限均为 0。该能力不通过原生供应商配置页自动开启。先升级数据面，再启动控制面自动升级至当前 v29；按目录发布流程重启后，在模型管理页确认授权模型。客户端使用项目 Key 调用 `/v1/embeddings`，input 为字符串或最多 16 个字符串，encoding_format 为 float。详见 [请求、计费和审计边界](../new-api-integration.md#受控文本-embeddings)。

项目输入关键词规则继续生效；输出或双向文本规则会在派发前拒绝向量请求，不能通过关闭必要治理策略绕过组织要求。启用内容审计后输入和向量均按授权加密留存。未知结果占额通过现有恢复/费用核查流程处理，不能直接视作零费用。

## new-api 缓存费率与请求核验

使用审核的 newapi Chat 目录时，管理员可在模型授权页面查看缓存读/写费率。费率由部署审核目录发布，未启用时仍使用统一输入价格；此页面不修改 new-api 渠道或企业费率。

在“请求账本”打开请求详情，可查看该请求冻结的输入/输出、缓存读/写单价及原始回执 token。普通输入量等于回执输入总量减去缓存读、缓存写；四类金额求和后只进行一次微人民币舍入。旧目录价格变更不会更改已派发请求的单价。

“未取得”表示当前没有对应回执计数，不能当作零费用；已完成请求的回执可能稍后经恢复任务入库。状态“不确定”的请求保留占额，不要因客户端失败就自动退款或重发。管理员应按恢复对账流程核对持久回执、供应商原始用量与交付结果。

首次启用缓存费率前，运维须完成 v29 自动升级并排空旧计费消费者。费率是企业审核配置，缓存写目前按合计数量计价，未区分供应商缓存 TTL、长上下文、服务端工具等附加价格。详细边界见 [new-api 接入](../new-api-integration.md)。


### 无状态文本 Responses

审核 newapi Chat 模型也可通过 `POST /v1/responses` 的受控文本子集调用。必须显式提供 `store:false`、`model`、文本 `input` 和 `max_output_tokens`（至少 16 且不超过目录上限），可提供字符串 `instructions`。当前支持 stream:true 实时文本，不支持工具、图片、后台任务、会话或历史响应检索；未知字段会拒绝，不会被静默丢弃。项目 Key 与受控设备身份沿用原治理链，终端代理已允许此路径。

`store:false` 表示不提供 Responses 历史存储/检索，不关闭项目明确开启的企业内容审计。审计记录包含协议标记、规范化请求和实际公开响应，依旧受加密、捕获上限、独立授权与保留策略约束。返回的 input/output token 来自供应商原始证据；未知缓存/推理细项不填写假零。请求示例与限制见 [Responses 接入](../new-api-integration.md#无状态文本-responses-公共协议)。

### Messages 文本客户端

newapi 执行模式下可调用 `/v1/messages` 文本 JSON 子集。模型目录需审核渠道指纹并配置缓存读写费率，以取得分离的原始计数。项目 Key 放在 `x-api-key` 或 Bearer 中（二选一），版本使用 `anthropic-version: 2023-06-01`。请求包含 model、max_tokens 和纯文本 messages；内容可用字符串或下文的纯 text 块，工具、图片、带附加语义的内容块或 beta 暂不支持；stream 需另外满足下文“Messages 实时流”的审核条件。内容审计与预算仍生效，缺失原始计量不会自动退款。详细范围、终端用法和固定 SDK 验证见 [接入说明](../new-api-integration.md#受控-messages-文本-json)。

### 缓存写入时长费用

管理员审核模型目录时，可为缓存写入配置 5 分钟和 1 小时的独立费率（`cache_pricing.write_ttl`）。启用后，模型授权页显示两类实际采用的写费率；请求详情展示请求发出时冻结的价格、原始聚合缓存读写量和两个时长的计数。普通输入不包含已经计入缓存读写的部分，所有类别合计后只取整一次，避免重复计费。

历史请求或尚未取得完成证明的请求，时长显示“未知”；这不表示没有产生费用。证据不完整时预算保留待核实，不能手工把未知量补成零。该功能要求先升级数据面及全部控制面消费者，再启用新费率；数据库随新版启动自动升级至 v30。当前不接受客户端 `cache_control` 创建缓存参数，供应商真实计费与缓存行为另行验收。

### Messages 实时流

模型经管理员审核为 Anthropic 文本流渠道后，可在模型目录启用 `allow_messages_stream:true`，同时配置缓存费率。模型授权页会显示“已审核 Messages 文本实时流”。客户端向 `/v1/messages` 发送 `stream:true`，可以使用固定 SDK 的 `messages.stream()`；默认关闭的模型会在供应商派发前拒绝流式请求。

起始事件展示供应商原始的初始输入／输出和缓存计数，最终输出计数在结束事件更新；起始计数不是已结算账单。只有收到 `message_stop` 才表示网关正常完成交付。断流、错误事件或客户端取消后，先查看请求账本与审计状态，不自行重试或将未知费用补成零。当前实时输出只支持字面量关键词告警；项目配置输出阻断／脱敏规则时会拒绝实时流，可继续使用已支持相应策略的非流式请求。


### Responses 结构化文本输入

`input` 可使用原有字符串，或 1–63 条按顺序排列的 `system`／`assistant`／`user` 消息，最后一条必须为 user。每条 content 可为非空字符串；system/user 还可使用 1–16 个 `{"type":"input_text","text":"..."}`，按顺序直接拼接，每条合计不超过 16 KiB。instructions 会作为首条 system 指令，整个请求仍不超过 64 KiB。assistant 目前只接受字符串，不接受输出消息对象或块数组。

例如 `input:[{"role":"assistant","content":"上一轮文字"},{"role":"user","content":[{"type":"input_text","text":"继续说明"}]}]`；仍必须设置 `store:false`。这只是客户端提供的文本历史，不提供服务端会话或历史响应检索。developer、phase、消息 ID、工具结果、媒体和缓存控制字段都会明确拒绝。审计保存规范化角色／文本，不保留原有文本块的分段方式；关键词检查在拼接后执行，不能通过拆分文本块绕过规则。


### Messages 纯文本块输入

messages 中 user／assistant 的 content，以及可选 system，均可使用字符串或 1–16 个 `{"type":"text","text":"..."}`。每块必须非空，按顺序直接拼接后每条最多 16 KiB，整个请求仍最多 64 KiB。消息最后一条必须为 user，暂不支持 assistant prefill。

文本块分段不会绕过关键词策略；内容审计记录规范化角色和拼接后的文本，原始分段方式不保留。不要附加 `cache_control`、`citations`、工具、图片或其他字段，这些会被明确拒绝，而不是静默丢弃。此扩展不主动创建供应商缓存；已有缓存计费仍依据供应商原始实际计数。JSON／审核实时流使用相同输入校验。

## new-api 模式的渠道管理

部署选择 `--execution-engine=newapi`，并完成独立后台管理身份配置后，原“供应商配置”导航统一展示真实 new-api 渠道。

1. 点“新增渠道”，填写名称、协议、经过批准的 Base URL 和上游模型列表；供应商密钥为密码输入框，多 Key 使用逗号分隔。提交立即清空，不从状态接口返回旧值。
2. “编辑渠道”可修改同一组字段并启用/停用；密钥留空保留原值，填写则整体替换。保存成功不意味着真实账号已验证，也不自动授权企业项目。
3. 在“发布真实路由与价格”添加模型别名，选择实际渠道并核对指纹，填写上游模型、合同价格、输入/输出边界与驻留依据；勾选实际审核结果后发布。随后再给项目/Key 授权。
4. 修改使用中的渠道后，“须重新审核”提示表示既有目录不再匹配。先刷新渠道，再在模型下重新选择并核对当前渠道，最后重新发布；不要仅复制新指纹绕过审核。
5. “渠道变更记录”保存操作编号、操作者、状态与数据面回执。看到“结果待核查”先查回执，不要重新新增同一渠道。回执找不到时仍保持待核查，不自动判定失败。
6. 旧文件目录模式保持只读发布，页面会提示。协议/高级设置不在当前编辑范围的渠道显示只读；需要扩展时先进行治理兼容性验证。

供应商密钥只用于后台数据面访问上游。应用继续使用企业网关地址与项目 Key；项目预算、审计和设备准入不因管理入口统一而改变。
