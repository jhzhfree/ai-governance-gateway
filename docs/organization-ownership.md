# 组织所有权交接

“组织交接”支持现任所有者与已有组织成员之间的两方交接，使用真实 PostgreSQL、OIDC/本地身份与业务权限，不使用邀请或模拟账号。所有记录与备份应随网关部署在中国大陆。

## 操作流程

1. 现任所有者先在成员管理添加接收身份，核对准确的 issuer/subject。本地账号必须已启用并完成首次改密；交接不会创建或邀请账号。
2. 打开“组织交接”，选择已有成员、填写原因并确认身份。发起时校验当前角色，24 小时内最多一条待处理请求。
3. 接收成员以**自己的账号**登录，打开对应组织的“组织交接”，核对来源、原因和有效期，明确勾选后接任。普通开发成员也可访问交接入口，但不能查看其他成员的交接详情。
4. 接收成功后，原 owner 降为 admin，接收成员成为唯一 owner；现任所有者可在接收前取消。刷新会重新读取组织角色。

仅发起请求不改变所有权，发起人不能代替接收人确认。过期或已处理的请求不能接受或覆盖；接收人的当前角色与发起快照不同，需要现任所有者取消并重新发起。过期请求不再出现在待办查询中，新建请求会将旧超时请求记为 expired。

本地模式中，发起与接受都会检查账号可用性，接受时双方须启用且无强制改密要求。请在旧账号停用前完成交接；停用、重置或外部目录故障的恢复仍依赖对应管理员。OIDC 模式验证签名、issuer/audience/scope 与数据库成员，不声称额外实时查询企业目录状态。后续 JH-SAC/JH-DAS 联动仍需接口契约。

## 安全与原子性

- 数据库唯一索引限制每组织最多一名 owner，待处理请求同样有唯一约束。
- 复用成员写入的组织事务锁，串行化角色变更、发起、接受和取消。接受在一个事务中先将旧 owner 改为 admin，再将接收成员改为 owner，最后提交状态与审计；其他请求不会看到中间的无 owner 状态。
- 审计失败整体回滚，旧所有者继续保有权限。接受与取消并发只允许一个决定成功。
- 只向发起人和指定接收人提供待办详情，其他已有组织成员得到空待办；非成员拒绝访问。
- 本地账号禁用与权限授予通过用户行锁协调，已进入认证流程但随后停用的账号不能利用此接口获得所有权。
- 原 owner 保持管理员权限，既有项目密钥不被撤销，独立审计员授权不自动新增或取消；本地平台管理员和供应商平台管理员身份也不随之转移。交接只变更组织角色，离职停用和正文解密授权分别管理。 若要完全终止旧人员访问，必须继续核查账号、项目密钥及审计员授权。

审计事件：`organization.ownership_requested`、`organization.ownership_accepted`、`organization.ownership_canceled`。详细来源、接收人、角色快照、原因、有效期和最终状态保存在追加的交接记录中。当前 Web 提供待办处理，未提供完整交接历史分页、外部邀请消息或自动目录同步。

## API

均在既有管理面认证下运行；Cookie 写操作需要正确 Origin/CSRF。

- GET `/api/v1/organizations/{org}/ownership-transfer`：返回 `{ "transfer": null }` 或本人可见的有效待办。
- POST 同一路径：body 为 `target: {issuer, subject}`、`expected_role: admin/developer/viewer`、`reason`，返回新请求。
- POST `/api/v1/organizations/{org}/ownership-transfer/{id}/accept`：仅指定接收人本人。
- POST `/api/v1/organizations/{org}/ownership-transfer/{id}/cancel`：仅当前发起所有者。

管理客户端不会代为发送邮件、企业微信或其他外部消息。终端已有组织查询会显示最新角色；交接写操作使用 Web 明确确认。

## 升级与验收

按 [Ubuntu 部署流程](deployment/ubuntu-24.04.md) 摘流、排空、备份，用新迁移工具 `migrate up` 升至 **0018**，`migrate check` 成功后启动新版网关。正常服务不自动修改业务表。

0018 新增交接表及唯一索引，不改写预算、占额、供应商或密钥。若旧库存在一个组织多名 owner，唯一索引创建会失败并整体回滚；不会擅自选择或降权任何人。运维须先在受控流程中核查并协调旧数据，再重试升级。只检查多所有者组织可使用：

```sql
SELECT organization_id, count(*)
FROM organization_members WHERE role = 'owner'
GROUP BY organization_id HAVING count(*) > 1;
```

测试使用真实临时 PostgreSQL、签名测试 IdP 与真实本地登录会话，包括跨组织隔离、两方确认、并发决定、角色变化、过期、审计回滚、本地停用/首次改密及迁移回滚。不代表真实企业目录、实际大陆物理部署或安全专项验收。

组织范围离职回收已补充为独立功能：[成员停用与恢复](organization-member-lifecycle.md)。完成交接后，现任所有者可显式停用原成员，不能假设交接本身已撤销旧密钥。
