# ADR 0012：项目显式开启的加密内容审计

状态：已接受，实现同步 MVP（2026-11-04）。

技术可行性评估要求保存输入输出，同时保留默认不采正文的隐私基线。选用现有 Go 模块化单体与 PostgreSQL，追加迁移 0011；不引入外部日志平台或独立 Python 网关，避免正文复制和预算链路分裂。

请求派发前持久化加密请求，成功 JSON/DONE 前同步封存回复。有界内存累积流式前缀与完整已观测 SHA，不逐 token 写库。失败关闭放行，正文状态与执行/预算分离。同步增加请求延迟，换取明确的正常成功边界；硬崩溃仍可能失去未封存回复，不声称异步持久缓冲已实现。

使用组织/密钥版本 DEK + AES-256-GCM 信封加密；主密钥由部署秘密系统注入，保留旧版本读取。AAD 绑定作用域及策略快照。采用独立项目审计员授权，owner 无隐式正文权限；理由与访问日志先提交，再解密。与普通组织角色分离，支持审计专用身份。Web 正文只留短时组件内存；CLI 只读元数据。

正文分区表配默认分区启动，按记录到期拒读，独立维护命令分批清理；不直接按分区删除，因为不同项目保留期可能不同。月分区自动维护、异步 spool、KMS SDK、外部不可变锚定和双人导出均为后续工作。哈希链只在可信检查点边界内有意义，不阻止数据库超级用户整体重写。备份/WAL 清理和真实大陆驻留必须另行验收。

操作契约、密钥遗失恢复和限制见[内容审计手册](../content-audit.md)。
