# ADR 0003 执行接纳与关闭

状态：隔离执行模块已实现，主网关接入仍待后续阶段。

实例按 `MaxConcurrent` 限制完整执行生命周期（包括流和消费者），默认 4，配置范围 1—1024；适配器不建立等待队列。满载返回 `ErrOverloaded`，不会产生对应的上游请求。SDK worker 数与该配置一致，业务层仍不得增加隐式重试。

Close 先停止接纳，再取消在途上下文，等执行/消费者退出后关闭 SDK。关闭与活动计数采用同一锁，防止 Wait/Add 竞争；并发/重复 Close 共用一次实际 Shutdown。关闭后新请求返回 `ErrClosed`。所有者必须在 Execute/Emit 回调外调用 Close；消费者必须响应传入 context，Close 不能强制终止不合作的用户代码，不能将此协议描述为任意插件下的硬超时保证。

测试观测实际 HTTP 派发计数：4 个活动流时第 5 个请求拒绝，取消后容量可复用；并发关闭时活动流取消、上游连接释放、后续请求不派发。该结果不是负载容量或长期内存/goroutine 泄漏验收。

接入治理层时，`ErrOverloaded`/`ErrClosed` 必须映射为未派发状态，按预留状态处理，而非当成模型成功或直接写零费用。账本与审计的权威状态仍由主网关事务控制；当前模块不自行退款或结算。
