# 加密内容审计（0011）

本阶段实现默认关闭、项目显式开启的同步审计 MVP。它保存通过校验的文本请求和网关规范化输出，不是内容安全审核模型，也不自动拦截敏感词。管理审计、执行结果、财务状态与内容审计分别解释。

## 启用与访问

1. 先备份并执行 `go run ./cmd/migrate up`、`go run ./cmd/migrate check`，升级到 0011；正常启动不隐式迁移。
2. 在中国大陆部署中，通过部署秘密管理系统向网关注入 `AIGW_CONTENT_AUDIT_KEYS`（JSON 对象：不可变版本 ID → 标准 base64 编码的随机 32 字节主密钥）与 `AIGW_CONTENT_AUDIT_ACTIVE_KEY`（当前版本 ID）。不要把值写入 Git、命令行参数、日志或浏览器。两项均空表示未配置；不允许开启正文采集。
3. 用组织 owner/admin 在 Web 项目“内容审计”中明确开启，填写告知/授权依据 `consent_ref`，设置保留天数与体积。启用和解密要求已有通过配置校验、证据未过期的大陆 CNY 供应商目录。配置声明不能代替合同与实际处理、存储驻留验收。
4. 只有组织 owner 可以授予/撤销项目审计员能力；owner/admin 不自动拥有解密权。可授权仅有 IdP 身份、没有普通组织成员资格的审计员；该身份不能因此访问预算或密钥。
5. 审计员访问 `/?audit_only=1&org=<组织ID>&project=<项目ID>`，选择记录并填写查看理由。权限校验和访问日志成功提交后才解密；解密失败的查看尝试仍留痕。撤权后新请求立即受限。

默认保留 30 天，范围 1–90 天；每方向默认最多 65536 字节，范围 1024–262144 字节。修改策略仅影响后续请求，记录固定保存策略版本、依据、上限与到期时间。每实例同时最多 16 个开启审计的捕获，超额关闭放行（返回错误）。未开启项目不保存正文。

Web 正文只放组件内存，不进入查询缓存或本地存储；主动隐藏、离开页面、标签隐藏、60 秒或正文到期会清除展示。正文按文本渲染，不执行 HTML。已经被用户复制的正文不能远程收回。没有批量导出/跨项目解密接口；单条访问依然需要组织内权限治理。

## 捕获和失败语义

请求经过身份、模型和币种校验后，在准入/预算/派发之前，原子写入加密请求与链事件；故障返回 503，不派发、不占预算。认证前或格式校验失败的请求不采集。正文是支持字段组成的逻辑快照，不保证保留原始 HTTP 字节。

SSE 正常转发片段，只在内存维护有界前缀与完整已观测流的 SHA-256；没有逐 token 数据库写入。同步封存成功后才发送 `[DONE]`；JSON 也在封存后发送。封存失败返回 JSON 503 或流内错误且不发送 DONE。此时预算可能已结算，不能据此退款或自动重试，应使用 request_id 核查。

状态 `capturing/complete/incomplete/canceled/expired` 描述捕获，不证明客户端收到、供应商全部生成内容或费用已结算。取消保留已观测片段；硬崩溃留下 capturing 与已持久化请求，尚在内存的回复会丢失。**没有 WAL spool/异步重放或崩溃零丢失承诺。** 哈希覆盖完整已观测规范化字节，密文只保存 UTF-8 完整前缀；返回 observed_bytes、captured_bytes、truncated 和哈希。不采集认证头、Cookie、供应商错误原文或来源 IP。

## 密钥、完整性与恢复

每组织/主密钥版本有独立随机 DEK；主密钥以 AES-256-GCM 包裹 DEK，DEK 分别加密请求和回复。AAD 绑定组织、项目、请求、模型、方向、策略快照、时间、长度及摘要等；组织内 start/seal/purge 事件串成哈希链。

轮换时先部署同时含旧、新版本的 keyring，再切换 active ID；旧记录仍使用原 key ID。readiness 检查有效策略和未过期记录需要的密钥版本是否存在。不要替换同一 ID 的密钥字节；检查 ID 存在不能验证其密钥值正确。退役旧版本前必须覆盖正文保留期与备份恢复周期，并完成恢复演练。

主密钥遗失：立即停止开启新采集，从受控大陆秘密备份恢复同一版本和值，再验证读取；只恢复数据库不能恢复正文。若无法恢复主密钥，相应正文不可解密，不存在管理员绕过通道。不要生成同 ID 的新密钥冒充恢复。

`go run ./cmd/content-audit verify <组织ID>` 用 `AIGW_DATABASE_URL` 检查事件连续性、已保留密文/nonce/元数据摘要及当前链头，输出 sequence/hash/valid；不合法退出非零。该命令不解密，也不需要主密钥。可将检查点存入受控外部不可变归档。**自动外部锚定未实现；数据库超级用户整体改写链与根时，数据库自证不能独立发现。** 过期正文删除后不再声称能重新验证已删除正文。

## 到期维护与数据库

读取实时检查 expires_at，到期立即拒绝。运维在大陆环境用独立维护账号运行：

```bash
go run ./cmd/content-audit purge 1000
go run ./cmd/content-audit verify <组织ID>
```

purge 每批最多 1000 条，事务内删除正文、写 expired 墓碑与 purge 链事件，返回 purged；重复执行直到 0。由部署侧定时任务调度，当前没有内置后台调度器；不要对活跃事务手工删表。元数据、访问日志、DEK 和链仍保留，预算不变。

0011 新增策略、授权、DEK、记录、分区正文、链头、链、访问日志八张逻辑表及一个默认分区。正文按 created_at RANGE 分区，当前仅有 bootstrap 默认分区；自动按月创建/迁移/删除分区尚未实现。结构检查覆盖分区键、边界和父子关系，并保持旧普通表指纹兼容。

逻辑清理不等于磁盘、WAL、复制副本、数据库备份立即消除；应另定这些载体及元数据/访问日志的保留策略并演练，不宣称密码学销毁。大陆处理和存储约束适用于数据库、备份、秘密系统与后续外部锚点。

## 接口与验收证据

公共前缀 `/api/v1/organizations/{org}/projects/{project}/content-audit`：GET/PUT `/policy`、GET/PUT `/auditors`、GET `/records`、POST `/records/{request}/reveal`（reason）、GET `/access`。Cookie 写请求需要 CSRF；正文接口 no-store。契约见 OpenAPI。

远程终端仅提供 `aigw content-audit list --org <ID> --project <ID> --output json` 的分页元数据，不将正文输出到终端。维护二进制 content-audit 与远程 aigw 分离，不能向浏览器或远程客户端提供数据库凭证。

本阶段全量验证：125 个后端顶层测试和 9 个 Chromium 场景通过，包含真实临时 PostgreSQL、签名测试 IdP、合成 TLS 供应商；冻结依赖、类型检查、lint、构建与 race 检查通过。覆盖授权/撤权/跨项目、访问日志失败、篡改检测、版本轮换、取消与占额、SSE 封存故障、到期清理和迁移漂移。没有真实供应商/真实企业 IdP、生产性能、安全专项、生产备份恢复或大陆实际部署验收证据。
