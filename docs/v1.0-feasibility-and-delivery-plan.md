# V1.0 交付规划：功能评估与人力排期（2 研发 + 1 测试 + 1 产品经理，1 个月）

| 项 | 说明 |
| --- | --- |
| 范围 | V1.0 五大核心功能：厂商 Token 核心管理、记录审计、终端准入、本地 OIDC 支持、系统配置 |
| 人力 | 2 名研发全程；1 名测试第 3 周起参与；1 名产品经理兼职推进口径、依赖与验收 |
| 工期 | 1 个月（约 4.3 周）；研发容量约 8.5 人周，须按本文优先级裁剪 |
| 交付边界 | **本月只交付产品软件的核心功能**（五大功能的软件实现与测试）。硬件适配与盒子产物、产品发布与发布工程、授权/许可证管理、用户与部署文档编写、其他产品资料（汇报/报价/培训等）**均不在本月范围**，属后续阶段另行排期；W4 仅产出运行必需的最小工程产物（单二进制 + 迁移脚本 + 最小启动说明） |
| 配套 | 交付判据见文末 DoD；架构约束（模块化单体、单一权威数据库、固定治理链顺序）沿用技术评审文档，本文不重复论证 |

---

## 0. 结论摘要

1. 五大功能均可行，无技术未知道路；瓶颈在外部依赖（企业准入协议契约、厂商官方账单、合规确认）而非编码。
2. 研发净工作量估算 **8.0 人周**（含测试用例与联调），对 8.5 人周容量留 0.5 人周缓冲；测试约 1.5–2 人周（第 3 周切入）。
3. 每个子模块按三级程度定义交付目标（完整 / 基础 / 预留），**"预留"不是砍功能，而是有接口、有文档、有排期的明确边界**。
4. 一个月内可交付的是"可受控试点"形态：单机、非高可用、性能数字待实测——对外承诺口径同步受此约束。

## 一、评估口径

### 1.1 实现程度三级定义

| 程度 | 定义 | 验收要求 |
| --- | --- | --- |
| 完整 | 生产可用：核心路径 + 异常路径 + 权限控制 + 审计留痕齐全 | 全量测试通过；验收用例逐条勾稽 |
| 基础 | 核心可用、边界明确：满足单机试点，已知限制写入文档 | 主路径测试通过；限制条款进交付文档 |
| 预留 | 本期不实现，但接口/数据结构/文档定位确定 | 接口定义评审通过； roadmap 归期 |

### 1.2 容量

| 角色 | 投入 | 折算 |
| --- | --- | --- |
| 研发 × 2 | 全程 | ≈ 8.5 人周 |
| 测试 × 1 | 第 3 周起（第 3 周熟悉与用例补全，第 4 周集中回归） | ≈ 1.5–2 人周 |
| 产品经理 | 兼职：需求裁决、外部依赖催办、验收组织 | ≈ 0.3 FTE |

## 二、V1.0 五大功能评估

### 功能一：厂商 Token 核心管理（约 2.0 人周）

目标：供应商凭证不出明文、不进代码；管理员在控制台完成接入与发布；请求按别名路由到供应商。

| 子模块 | 说明 | 程度 | 估算 |
| --- | --- | --- | --- |
| 供应商与模型目录 | 三家供应商注册、区域/端点配置、模型别名 → 供应商静态路由 | 完整 | 0.5 人周 |
| 凭证加密存储 | 信封加密（组织级密钥 + AES-256-GCM，AAD 绑定凭证标识与版本）、多版本密钥轮换、错误次数限制 | 完整 | 0.7 人周 |
| 控制台托管界面 | 凭证录入/更新/停用、发布双人审计留痕、生效版本管理 | 完整 | 0.5 人周 |
| 健康监控 | 供应商连通性与错误计数、指标导出 | 基础 | 0.2 人周 |
| 自动故障切换 | 失败自动换供应商 | 预留（2.0，涉及账本改造） | — |

边界：V1.0 为"健康展示 + 手动切换"；配置发布后 `ready` 才转绿，属设计语义。

### 功能二：记录审计（约 2.0 人周）

目标：请求/响应可查、可导出、可证明未被篡改；崩溃不产生审计空洞；默认关闭、显式开启。

| 子模块 | 说明 | 程度 | 估算 |
| --- | --- | --- | --- |
| 治理账本 | 组织/项目/密钥/模型维度的请求元数据、用量与成本入账 | 完整 | 0.4 人周 |
| 内容审计管线 | 项目级开关 + 告知依据；正文信封加密；独立审计员授权（owner 不自动可解密）；保留期与截断上限；到期拒读 | 完整 | 0.7 人周 |
| 防篡改 | 组织内哈希链 + 校验命令 | 完整 | 0.2 人周 |
| 崩溃完整性 | 同步加密检查点、崩溃后恢复、过期清理 | 完整 | 0.4 人周 |
| 导出与对接 | 单组织 CSV 导出；受控 SIEM 对接、KMS/外部锚定、双人审批导出 | 预留（SIEM/锚定 2.0；双人导出视合规确认排期） | 0.3 人周（CSV） |

边界：内容安全审核模型（护栏"理解"部分）本期不做；正文长期沉淀口径需合规确认后写入合同附件。

### 功能三：终端准入（约 1.5 人周）

目标：只有受控设备与持证用户能拿到项目密钥的调用权；设备可登记、可撤销、可追溯。

| 子模块 | 说明 | 程度 | 估算 |
| --- | --- | --- | --- |
| 设备登记与确认 | 设备公钥登记、管理员审批、项目强制策略 | 完整 | 0.4 人周 |
| 设备绑定会话 | 私钥持有证明（DPoP）、五分钟级短会话、撤销与账号停用联动 | 完整 | 0.5 人周 |
| 终端代理 | Linux 回环 SDK 代理：应用零改动接入，代持会话与重试 | 完整（Linux）/ Windows、macOS 预留 | 0.3 人周 |
| 企业准入协议对接 | 设备状态与身份映射适配层；证书/mTLS、TPM 硬件锚定 | 预留（适配层接口本期定义；真实协议待外部契约冻结后接入） | 0.3 人周 |

边界：依赖外部协议契约；未冻结前按评审假设开发适配层，联调排到契约到位之后。

### 功能四：本地 OIDC 支持（约 1.5 人周）

目标：离线环境开箱可用；在线环境标准 OIDC 对接企业 IdP；双模式同构。

| 子模块 | 说明 | 程度 | 估算 |
| --- | --- | --- | --- |
| 本地账号体系 | 初始化向导、首次强制改密、账号管理/停用、离线恢复流程 | 完整 | 0.5 人周 |
| 会话与令牌 | 浏览器会话、短期管理令牌、撤销与强制下线、登录限速 | 完整 | 0.4 人周 |
| 标准 OIDC 对接 | 授权码 + PKCE、discovery/JWKS、企业 IdP 接入配置 | 完整 | 0.3 人周 |
| 目录同步 / SCIM | 组织成员与外部目录自动同步 | 预留（2.0） | — |

边界：本地模式仅回环部署使用，不得暴露公网；两模式的会话语义保持一致，避免后续切换成本。

### 功能五：系统配置（约 1.5 人周）

目标：治理策略全部可配、可审计、可回滚；运营人员不改代码完成日常管理。

| 子模块 | 说明 | 程度 | 估算 |
| --- | --- | --- | --- |
| 预算与限额 | 组织/项目两级预算硬上限、原子预留/结算、周期轮转、调额双人审批 | 完整 | 0.5 人周 |
| 权限与层级 | 组织/项目/部门三级模型、角色继承、成员停用与作用域回收 | 完整 | 0.4 人周 |
| 监控与报表 | 指标导出（认证前入口计数、全流耗时）、成本报表（Web/CLI）、部门入账快照、CSV 导出 | 基础 | 0.4 人周 |
| 告警与通知 | 预算阈值站内告警；外部通知（邮件/webhook）通道 | 站内完整 / 外部通知预留 | 0.2 人周 |
| 关键字规则 | 项目级关键字/正则规则：输入侧告警/阻断、非流式输出脱敏、流式输出仅告警 | 基础 | — |

**工作量合计：8.0 人周**（功能一 2.0 + 功能二 2.0 + 功能三 1.5 + 功能四 1.5 + 功能五 1.5 为 8.5，其中关键字规则并入功能五计 0，合计 8.5 时需触发第 4.3 节裁剪预案；推荐按 8.0 执行，0.5 人周缓冲）。

## 三、四周排期

### 3.1 周计划

| 周 | 研发甲（后端/安全向） | 研发乙（平台/交付向） | 测试 | 产品经理 |
| --- | --- | --- | --- | --- |
| W1 | 功能二·内容审计管线 + 哈希链（0.7+0.2） | 功能一·供应商目录 + 凭证加密存储（1.2） | 未介入 | 冻结口径三个修订项；发起 SAC/DAS 契约、厂商账单样本、合规三确认申请 |
| W2 | 功能二·崩溃完整性 + CSV 导出（0.7）；功能三·设备登记（0.2） | 功能一·控制台界面 + 健康监控（0.7）；功能五·预算与限额（0.3） | 未介入 | 跟踪外部依赖；确认部署形态口径（显式代理） |
| W3 | 功能三·设备绑定会话 + 终端代理（0.8）；适配层接口定义（0.3） | 功能四·本地账号 + 会话令牌（0.9）；功能五·权限层级（0.4） | **介入**：补验收用例、搭验收环境、对 W1–W2 交付物回归 | 组织第一轮功能验收 |
| W4 | 功能四·OIDC 对接（0.3）；缺陷修复与联调 | 功能五·监控报表 + 告警（0.6）；收尾与最小运行产物 | 全量回归 + 性能冒烟 + 备份恢复演练 | 组织验收评审，输出遗留项清单 |

里程碑：M1（W2 末）审计与凭证主链可演示；M2（W3 末）准入 + 本地身份可演示；M3（W4 末）全量验收。

### 3.2 关键路径与并行约束

1. **关键路径是功能一 → 功能五**：供应商可发布后，预算/报表/告警才有真实数据可验；W1 必须优先打通"凭证入库 → 请求路由 → 用量入账"。
2. 功能二的加密与哈希链属安全敏感模块：AI 生成初稿后必须人工逐行复核（见 4.2），预估已含复核时间。
3. 功能三的外部协议对接是**挂墙时间风险**：适配层按接口先做，真实联调不占本月排期，进 V1.0.x。

### 3.3 超支裁剪预案（按顺序触发）

1. 砍功能五·成本报表的 CLI/TUI，仅保留 Web + CSV（省 0.2 人周）。
2. 功能三·终端代理仅保 Linux（本就是规划），Windows/macOS 不排期（无损失）。
3. 功能二·CSV 导出降级为"审计员页面导出当前筛选结果"（省 0.1–0.2 人周）。
4. 仍超支则功能五·关键字规则整体移入 V1.1（省 0.5 人周），同步修订对外功能清单。

## 四、协作方式与风险

### 4.1 测试介入策略（第 3 周起）

- W3：熟悉系统 → 按本文"程度定义"补全各功能验收用例（重点：权限矩阵、撤销/停用联动、并发撤销、崩溃恢复）；对 W1–W2 交付物做首轮回归。
- W4：全量回归 + 性能冒烟（并发 50、流式长会话）+ 备份恢复演练；遗留缺陷分级（阻塞/重要/一般）。

### 4.2 AI 辅助开发红线

研发全程使用 AI 编码工具提效（脚手架、测试补全、文档），但：

1. 门禁不可绕过：格式、契约冻结、静态检查、race 测试全绿才合入；
2. 加密/哈希链/身份令牌/权限回收四类模块人工逐行复核；
3. 数据库迁移只增不改，锁语义（行锁/租约）人工审；
4. 按可独立验收的子模块切分提交，验收通过再进下一块。

### 4.3 外部依赖与风险

| 依赖/风险 | 影响 | 应对 |
| --- | --- | --- |
| 企业准入协议契约未冻结 | 功能三真实联调延期 | 适配层接口先行，联调排 V1.0.x；PPT 标注依赖 |
| 厂商官方账单样本未提供 | 官方账单对账不进 1.0 | 对账框架按标准格式实现，样本到位后适配 |
| 合规三确认（告知/留存/删除） | 内容审计不能作商用承诺 | 功能照常交付，商用口径为"合规确认后启用" |
| 低端硬件容量未实测 | 性能数字不可对外承诺 | W4 性能冒烟给出单机基线，正式实测排下阶段 |
| 单人请假/外部打断 | 容量无冗余 | 启用 3.3 裁剪预案；功能二优先级最高不可裁 |

## 五、V1.0 验收判据（DoD 摘要）

1. 五大功能全部达到第 2 节声明的程度；每个"预留"项有接口定义与 roadmap 归期。
2. 全量测试（含 race）通过；验收用例由测试人员勾稽；浏览器主流程场景通过。
3. 治理链固定顺序（鉴权 → 校验 → 准入 → 审计预写 → 预留 → 派发 → 结算 → 封存）未被任何功能打乱。
4. 未发布供应商配置时系统可启动但拒绝推理（ready 503），语义与文档一致。
5. 交付物：单二进制 + 迁移脚本 + 最小启动说明 + 遗留项清单（**不含**硬件适配、产品发布、授权管理、文档与产品资料——见头部交付边界，均属后续阶段）。
