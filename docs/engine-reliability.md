# 执行引擎：故障回归与性能基线

范围：开发分支的本地可复现证据，不是生产 HA 或 V1.0 发布验收。均使用合成请求、回环上游、专用 PostgreSQL，不调用付费模型。下方性能数字属于 2026-11-06 的历史执行链，不包含随后追加的 0032 持久完成事件和回执开销，不能作为当前产品的容量证据；启动自动升级行为保持。

## 单进程持久化增量

0032 阶段将现有集群故障夹具接入完成 Store，并新增 `TestCompletedEvidenceSurvivesKilledSettlementProcess`：JSON/SSE 两种请求在原始用量事件落库、预算与回执事务尚未提交时强杀进程，验证事务回滚、客户端无成功终止，再启动新进程恢复为 14 微元且供应商请求数始终为 1。仅在隔离测试库提前事件年龄，并将测试维护轮询设为 100 毫秒；生产仍为 3 分钟恢复窗口和每分钟巡检。该用例检验跨进程恢复函数，不代表完整应用调度、跨主机 HA 或代理传输验收。

`benchmark.sh` 的历史构造路径尚未切换到持久完成 Store。后续性能阶段必须先接入该路径，再按并发 20、内容审计和终端准入分别重新测量，不复用下表推导新性能结论。当前阶段的通过/失败与提交记录见 [交付跟踪](v1-delivery.md)。

## 双进程故障

`modules/engine/gatewaybridge/cluster_test.go` 启动两个独立测试二进制进程，共享隔离 PostgreSQL schema；每个进程组装真实 Manager、Managed/Pool、根 Handler、Key 授权、准入、账本、attempt、内容审计及设备验证接缝。不是启动完整 gateway-engine 应用，不覆盖反向代理或应用维护任务调度。

1. 项目并发上限设为 1，A 进程打开持续流；B 拒绝同项目第二请求。
2. SIGKILL A，客户端不能收到成功结束；B 仍被共享租约挡住。
3. 仅提前测试 schema 中该请求的租约到期时间，验证并发名额回收后，预算仍因未知用量占额拒绝请求。生产租约 180 秒未缩短；测试没有真实等待完整 TTL。
4. 父测试进程调用与生产相同的账本/审计恢复函数：派发记录变为 uncertain，384 微元预留保持、Actual 为空；审计恢复为 incomplete，不能伪造成功。此项验证恢复逻辑，不证明另一节点维护任务自动接管的时间上界。
5. B 服务其他项目并结算 14 微元；上游总调用恰好 2 次，无失败重放。组织总账 held=384、spent=14，跨进程审计链可验证；B 收到 SIGTERM 后正常退出。

这不证明跨主机分区、数据库主从切换、跨节点配置同时生效、NTP 偏差、反向代理重试或完整部署的高可用。节点崩溃后的未知费用必须保守保留，等待可信账单或人工对账，不能自动退款。

## 持续流

`TestStrictStreamProgressBeyondHeaderDeadline` 通过真实回环 HTTP，每 500 毫秒一个内容帧，累计 24 帧、约 12 秒；请求超时上界 30 秒。验证活动流可超过 10 秒响应头等待时间，24 帧完整且关联 ID 保持，终端用量只确认一次，未发生重试。既有畸形帧、用量后断流、3 秒空闲断连、取消和过载测试继续保留。

本测试不覆盖 120 秒最大请求持续期、小时级浸泡、慢客户端内存曲线或并发长流容量。

## 重现

需要仓库固定 Go 编译器和专用 `TEST_DATABASE_URL`。脚本不输出连接串；测试创建并清理隔离 schema，不得指向生产数据库。

```bash
bash scripts/verify.sh
# 以下从仓库根执行；性能测量与验证脚本分开运行，避免竞争污染结果。
bash modules/engine/scripts/benchmark.sh
# 单独重复故障回归：
(cd modules/engine && go test -race ./gatewaybridge \
  -run '^TestMultiProcessGovernanceCrashRecovery$' -count=5 -timeout=120s)
```

基准固定每项 50 次，分别设置 GOMAXPROCS=1 和 4（RunParallel 默认对应 1/4 个工作者），原生/受管执行器 × 内容审计关闭/开启共 8 组；非 race 构建。预热一次后计时，输出 req/s、p50/p95/p99、分配量。全部返回 200、上游调用数无重试、预算 held=0、spent=14×请求数、审计链有效才接受结果。

每组在独立数据库 schema、单组织单项目下测量：项目 Key/模型授权、同步数据库配置刷新、共享准入/熔断、预算预留与结算、attempt、元数据审计，加上可选加密内容采集；HTTP 入口为进程内 Recorder，上游是本地 HTTP，响应仅几百字节。没有入口 TLS、OIDC 登录、设备 DPoP、真实模型网络/生成延迟、流式负载、跨租户分布或生产磁盘。共享组织账本与审计链存在串行热点，单组 50 样本的尾延迟仅供回归比较，不能当成容量上限或 SLO。

后续容量验收应增加稳态/突发、组织数量、审计内容大小、并发长流、慢客户端、数据库延迟与不可用等维度，并记录 CPU/内存/goroutine/连接池等待。优化需先定位事务和串行等待，不移除权威预算或持久审计来提高吞吐。
