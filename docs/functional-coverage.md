# 整体功能覆盖核查（2026-11-04）

结论：项目已具备可运行的治理主链路和 Web/终端入口，适合受控开发集成与验收；目前不能标记为生产可发布。最大缺口已经从基础功能转向真实服务接入、管理体验收尾及生产运行保障。

本报告以源码、OpenAPI、迁移、测试和发布文件为依据，不用代码行数或测试数量推算“完成百分比”。“本地已验证”表示真实 PostgreSQL/签名测试 IdP/合成供应商条件下通过，不能替代真实大陆驻留、企业 IdP 或供应商付费验收。

## 主链路验收结论

1. 管理账号登录 → 建组织/项目 → 配模型 → 发项目密钥 → 文本推理 → 查询用量/执行记录：本地闭环已验证。
2. 超限拒绝 → 供应商失败 → 不确定占额 → 熔断/单次恢复探测 → 只读核查：本地故障场景已验证。
3. 标准化最终账单 → 导入 → 核对差异 → 独立管理员确认 → 财务/审核/审计原子提交：本地 API 闭环已验证；Web 覆盖导入、重复、驳回、刷新及预算不变，正向财务通过/并发/回滚由 API 测试覆盖，不冒充双人浏览器端到端验收。
4. 三家真实供应商 → 真实付费 usage/账单 → 已核验中国大陆处理与存储 → 企业身份和生产部署：尚未验收。

自动跨供应商重放、SSE 输出后重试、超时自动退款、Agent 工作流、知识库及插件市场按当前边界不做，不能为了补齐功能表而直接加入。

## 建议推进顺序

- P0 真实验收准备：确定大陆网关/数据库/日志/备份及操作终端位置，取得企业 IdP 配置、三家真实账号/合同/模型/价格和脱敏账单样本。没有这些证据，不使用真实业务载荷或账单来冒充验收。
- P1 MVP 功能收尾：GET /v1/models 与基础 Web 成员管理已补齐，接下来是预算调整/周期管理的版本化设计、完整成员生命周期；供应商/价格发布和首次接入指南。按小阶段交付，避免同时引入宽泛重试/自动退款。
- P1 运行保障：容器/部署产物，Prometheus/OTel 与告警，数据保留，固定硬件压测、备份恢复及升级回退演练。规模目标先定再测，不给未经测量的吞吐承诺。
- P2 产品扩展：真实场景证明需要后，再决定更多协议、导出、复杂报表和财务贷项/差额流程。
