# 架构与决策记录

## ADR-001：Higress保留为主模型数据面

不Fork/改写其Envoy核心，不默认串联LiteLLM/Bifrost。Higress负责供应商协议、凭证托管及后续受控路由。自有代码负责主体、预算和审计。

当前可运行路径：客户端 → 治理适配服务 → 内部Higress → 模型。适配服务在非流式请求前后做账本操作，便于先验证业务不变量。它不是最终高性能数据面，新增一跳和同步SQLite是有意受限的alpha取舍。测试使用替代Higress协议的fixture，不代表真Higress实测。

目标路径：客户端 → Higress及自研Wasm治理插件 → 模型；插件在请求前调用独立决策/预占接口，响应结束提交签名usage事件。控制面不经过SSE正文；预算与身份决策服务用共享存储。先验证丢事件恢复、幂等和结算来源可信，再迁移路径。

## ADR-002：本轮控制/决策原型使用Node24与TypeScript

本轮可执行环境没有Go、Maven/JDK编译器和Docker；Node24可运行原生TypeScript并提供SQLite。为交付可独立执行和验证的核心业务，采用零第三方运行依赖的TypeScript模块。与调研中的Go/Java候选相比，这是自有控制/决策原型的明确调整，Higress选型未改变。

Node类型擦除不进行静态类型检查，当前依靠运行时输入验证和行为测试。P1加入受控的TypeScript编译器、node类型定义和锁文件，再启用strict/typecheck；不能将当前“npm test通过”写成类型检查已通过。

业务层不绑定Higress配置API，但当前Store直接使用SQLite。迁移PostgreSQL前应抽出异步仓储接口和事务服务，保留相同契约测试。不能不经实现就宣称已支持PostgreSQL/Redis。

## ADR-003：本地持久化与资金状态

SQLite WAL、BEGIN IMMEDIATE及数据库约束保护单节点账本；只支持一个应用实例，禁止多实例同时调用recover。多连接事务测试不代表分布式HA。启动时将未完成预占转为待对账，保留资金，避免进程崩溃导致重复可花。

RESERVED → SETTLED，或RESERVED → PENDING_RECONCILIATION → SETTLED。已结算记录重复相同usage无额外扣费，冲突usage返回409。客户端相同幂等键返回409并禁止重复上游调用，客户端应查询账本而不是自动改新键重试。

## ADR-004：货币与费率

统一演示微元CNY，费率是每Token整数微元。预算使用字节数加4096余量估算输入和最大输出。它不是严格分词，存在提供商隐藏开销和usage欺骗风险。本版只用于受控模型契约，正式商业使用前必须实现提供商完整计费规则、usage校验及账单对账。超预占实际费用仍如实计入，余额超支后停止新请求。

## ADR-005：信任边界

凭证→主体/租户/项目由服务端查询，不信任客户端身份头。上游地址与密钥由管理员保护的部署配置决定，调用者不可提交URL。HTTP只允许明确本地服务名，其他目的地址强制HTTPS，禁止重定向。该限制不等于完整SSRF防护，管理配置、DNS与出口仍需运维控制。

初始admin为一次性部署引导身份，24小时有效。生产使用必须先完成SSO、管理认证、密钥轮换和恢复工具，不允许删除账本重新引导。

## ADR-006：当前不授予开源许可

目标是私有企业产品仓库。原创代码保留版权，不默认选择MIT/Apache将内部代码对外授权。Higress及其他依赖按各自许可证处理，发布时生成SBOM与NOTICE。内部PPT、调研中的敏感经营信息不随代码推往公开仓库。
