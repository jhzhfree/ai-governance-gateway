# ADR 0030：基于设备私钥持有证明的基础准入

状态：已实现并验收，验证范围见 [交付跟踪](../p0-p1-delivery.md)。

先建立可审计的登记与准入基础，不把客户端设备编号或安全自报当作信任依据。客户端生成 Ed25519 密钥，组织管理员核对公钥并确认；设备所属人登录后证明持有私钥，获取绑定设备/项目/模型的五分钟不透明调用令牌，数据库仅保存摘要。初期采用 HTTPS + DPoP 结构的签名证明，不引入企业 CA，不宣称 TPM、不可导出密钥、SAC/DAS 或完整 OAuth 授权服务器能力。

共享 PostgreSQL 消费每次证明的 jti，数据库时间验证 60 秒旧/30 秒超前窗口，绑定方法、公开路径与令牌摘要。查询与撤销使用相同数据库权威状态，不以 JWT 到期代替实时撤销。设备/会话验证按本地账号、成员、部门权限、设备、会话的顺序加锁，避免与停用反向等待；全局本地停用也通过 CAS 防止并发状态覆盖。

项目策略默认关闭。开启后长期项目密钥不能调用或发现模型，普通调用者不能借设备头绕过。管理员仍能显式调整策略，这是治理权限，不是假装管理账号失陷后也无法修改的监管锁。

Linux 客户端复用现有管理登录，实现私有文件密钥、登记和回环 SDK 代理；本机令牌、Host/Origin、路径、大小、并发和重定向均受限制。私钥仍可被同用户恶意程序或 root 复制，硬件保护属于下一阶段。

预算事务保存入账请求与设备/会话关联，失败一起回滚；组织成员/本地账号停用永久撤销设备与会话，恢复不复活。已授权的在途推理按原结算语义继续，不擅自退款或重放。

见 [基础准入说明](../device-admission.md)。mTLS/TPM、安全状态、目录对接、浏览器管理端强制准入和出口防绕过另行推进。
