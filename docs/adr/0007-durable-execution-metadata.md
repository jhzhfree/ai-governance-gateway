# ADR 0007：先持久化执行意图，再记录独立结果

状态：已实现并本地集成；真实大陆供应商联调仍待验收。

既有账本可以回答预留和结算，却不能可靠解释模型、供应商、协议失败与取消。新增 execution 模块和受管 inference_attempts 表，用独立 attempt_id 关联一个已预留 request_id。当前 request_id 唯一，不引入重试或跨区回退。

开始记录必须持久化且预算仍 reserved，之后才允许派发；失败保留原预留，不冒充已派发。不在 Reserve 中复制执行字段，也不在元数据模块修改余额。结束记录在正常响应/成功终止标记前落库，completed 只允许对应账本已 settled、有合法 HTTP 200 与用量。终态保持不可变；同结果重写幂等、冲突结果拒绝，避免应答丢失后的失败补写抹掉事实。

账本结算和执行记录分别提交，不宣称原子性。结算后元数据失败时不返回成功标记，财务事实不回滚；开始失败或结束失败都不触发退款或供应商重放。跨模块大事务会把网络生命周期和数据库事务耦合，并改变已验证的预算边界，暂不采用。需要后续恢复协议时再设计事务 outbox/恢复任务，而不是静默吞掉元数据错误。

执行结果只表示网关已观察和持久化的协议/记账事实，不声称客户端已收悉。unfinished 也不是仍在运行的证明。历史记录不从价格指纹推测模型，也不回填结果。元数据只含白名单字段、固定错误分类与可空用量/时间，不含正文和凭证。

API 继续由 control 执行项目 RBAC，按组织/项目预算行关联并显式投影元数据。Web 与 CLI 增加独立 outcome 筛选，TUI 增加详情和滚动，复用生成契约，禁止双端重新计算权限或结算结果。配置区域沿用已声明供应商 profile，中国大陆处理与存储的独立验收要求不变。

运行、语义、故障边界及验证范围见[执行元数据](../execution-metadata.md)。
