# ADR 0004：受治理执行桥接及用量来源

状态：受控本地集成；主程序未切换。基于 Bifrost Core v1.14.1。

## 接入边界

根网关 `ProviderExecutor` 仅替换物理执行。`Validate` 无派发副作用，在预算预留前拒绝不支持请求；`Open` 仅在身份、设备、内容审计预写、限流、熔断、预算预留和持久 attempt/dispatch 后执行。未提供执行器时保持原生供应商链路；显式执行器失败时禁止回退或重放。

模块公开 `execution`，不暴露 SDK 类型。`gatewaybridge.Binding` 固定一份受信 route/价格指纹/模型映射与执行器，拒绝不同路由或低于 16 的 max_tokens。模型名只能来自服务端映射。它不是动态凭证池：路由和凭证变更后必须由所有者重建并排空旧绑定。尚未加入 main 的选项，避免未验证的轮换、供应商路径和参数行为进入真实运行。

桥接器使用无缓冲 pipe，事件消费者直接施加背压。JSON 单事件、SSE 单帧 64KiB/总量 16MiB、JSON 1MiB、request/attempt 关联、成功 HTTP 状态和显式 usage 均验证。关闭 Body 取消上游并等待生产者退出。SDK 关闭仍由执行器所有者负责。首次有效事件前不返回 200；成功事件的 200 来自 SDK OpenAI Chat 对上游状态严格为 200 的检查，不从 SDK 错误臆造状态。

所有正文继续经过根网关规范化、关键字、加密检查点与封存，只有唯一 PostgreSQL 账本结算。SDK Payload 中的 usage 被删除，仅显式证据可进入原计费校验器；未知证据保留 uncertain，不退款、不补造零费用。

## 本轮发现与修复

集成测试首次发现：上游重复发送相同 usage，SDK 对计数取最大值并合成尾包，原桥接会结算成功，未能观察重复帧。SDK 还可能将不一致 total 修正成 input+output，不能直接将归一化用量当成原始证据。

适配器启用内部原始响应捕获，对捕获到的 JSON 文档逐帧校验：不允许重复字段、重复用量、结束前用量、负数/缺少计数/算术不一致或超过输出上限。原始计数必须与归一化计数一致，才发出显式证据。原始请求/响应字段在输出事件前清除；无 SDK 日志插件或原始内容持久化。已有流式正常测试原先缺少 finish_reason，已补齐合法样本，并新增缺失 finish 的拒绝回归。

## 必须保留的生产门禁

SDK 的捕获接口不是完整的原始传输证明：源码在解析失败时可能丢弃帧，待转发原始帧队列超过 1MiB 时可截断且不向当前适配接口返回可靠的截断标记。新增校验可以发现已捕获帧的重复/冲突，但不能证明捕获完整。下一阶段须引入可验证的原始响应接收边界，或固定补丁/升级 SDK 提供完整性信号，补充畸形帧与超大非转发帧验收后才能开放真实切换。不得通过忽略这些案例或直接相信归一化 usage 消除此门禁。

尚需三家供应商实际路径、thinking/stream_options 语义与 TLS/出口策略的契约；动态配置/凭证轮换；有界共享执行池；工具内容贯通审计；真实性能与真实账号受控验收。现有主程序继续使用原链路，不受本模块 SDK 依赖升级影响。本 ADR 不能作为 V1 发布验收通过证明。

## 验证

`gatewaybridge` 使用真实隔离 PostgreSQL、真实项目 Key 撤销和模型授权、共享准入/熔断、预算、attempt 和加密审计，执行到本地 HTTP Bifrost 上游。验证 JSON/SSE 的同一 request_id、整数费用 14（合成价格）、内容解密关联、异常 uncertain、拒绝时零派发，以及禁止原生回退。设备场景验证无效设备会话拒绝，不冒充真实终端准入联调。独立测试验证 Close 释放背压、迟到错误不变成功 EOF、关联错误/超大事件拒绝。

完整验证以根脚本为准。根脚本先准备测试数据库再执行嵌套模块，嵌套脚本缺少 TEST_DATABASE_URL 时直接失败，避免新增集成测试被跳过后误报通过。
