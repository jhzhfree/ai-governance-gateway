# ADR 0004：共享契约的只读 CLI/TUI 与设备授权

状态：已实施本地集成；企业身份与桌面钥匙串待验证。

## 问题与决定

Web 已有管理契约与服务端 RBAC。终端需要同一套权限和预算语义、可供脚本消费的稳定输出，以及可取消的交互查询。因此新增独立 `cmd/aigw`，由 Cobra 处理命令、Bubble Tea v2 处理 Model/Update/View、Lip Gloss v2 处理排版。固定版本为 Cobra 1.10.2、Bubble Tea 2.1.1、Lip Gloss 2.0.6；统一使用 v2 import，避免混用历史 v1 示例。该组合依赖要求将模块最低 Go 从 1.24 提升至 1.26，开发与 CI 仍固定 Go 1.27.3。

从现有 OpenAPI 用 oapi-codegen 2.5.1 生成 Go 数据类型，命令通过独立 HTTP 适配器调用管理 API。生成工具写入 go.mod 的 tool 指令；校验脚本拒绝契约漂移。HTTP 适配器集中限制 origin、重定向、超时、响应大小和错误回显。CLI 与 TUI 不依赖领域存储，也不复制权限判定；角色由 API 决定。本阶段仅提供查询，不扩张服务端接口或数据库。

公共终端客户端使用 RFC 8628 Device Flow，openid + aigw:manage；得到 access token 后复用 OIDC 校验并实际访问目标 API，成功才保存。采用 go-keyring 0.2.8 默认系统钥匙串、显式文件回退，无 refresh token。对无交互自动化仅支持外部注入 AIGW_TOKEN。凭证绑定服务/issuer/client/audience，配置独立于敏感内容。

TUI 将 HTTP 请求置于可取消命令，作用域和递增代次决定是否接纳响应。刷新错误保留同项目最后数据，切换作用域清空旧数据。列表游标前进/历史回退，终端控制字符过滤，退出释放请求并恢复终端。没有在渲染或客户端重做授权/预算计算规则。

## 替代与取舍

- 直接查 PostgreSQL 会绕过管理授权和审计边界，且要求终端分发数据库凭证，因此不采用。
- Web 与 TUI 共享契约和术语，而非渲染组件；这让两端独立遵循浏览器/终端交互习惯。
- 浏览器回调 + PKCE 可以支持更多 IdP，但会增加本地回调监听与注册要求；先完成设备流。有些企业 IdP 禁用 Device Flow，当前明确失败，后续再按真实接入需求添加 PKCE。
- 新增 Bubbles 通用组件不是首轮必需；当前有限层级使用小型状态机，保留键盘/缩放测试。
- 不默认明文文件、不保存 refresh token，代价是部分桌面外环境需要明确选择文件且到期重登。原生钥匙串可用性不能由内存替身测试推断。
