# 组织成员停用、恢复与权限回收

“成员管理 → 组织成员”支持组织所有者停用或恢复现有成员，并查看变更历史。该功能使用真实 PostgreSQL 与既有身份认证；只作用于**当前组织**，不禁用企业 IdP/本地账号、不退出所有登录会话、不改变其他组织权限或平台管理员身份。

## 停用

选择成员后填写原因并明确确认。以下操作在同一事务内提交：

- 将组织成员设为停用，递增生命周期版本；管理鉴权与组织列表据此拒绝/隐藏该成员的当前组织。
- 撤销该身份在本组织签发的全部未撤销项目密钥，包括已到期但未标记撤销的记录；模型发现和新推理同时检查签发者组织状态。
- 删除本组织项目单独授权，撤销本组织独立审计员授权。
- 取消以此成员为接收人的待处理所有权交接。
- 为撤销的密钥、项目授权、审计员和交接分别写入审计，再记录成员状态事件与回收数量。

任何步骤或审计失败都会整体回滚，避免“成员停用了、密钥却仍能用”的半完成状态。原有正文审计和所有权历史保留引用，成员记录不物理删除。

组织 owner 不能被停用，必须先完成 [所有权交接](organization-ownership.md)。自我状态变更被拒绝；普通管理员不能停用组织成员。身份和角色变更接口不会隐式重新启用已停用成员，也不能重新授予其项目/审计员权限。

## 恢复

恢复必须选择组织角色，默认是**开发者**。开发者需要重新配置项目权限；管理员和只读成员会按既有规则继承组织范围权限，选择时应核查业务需要。状态变化使用 `lifecycle_revision` 比较，过时操作返回冲突，需要刷新确认。

恢复不会复活旧密钥、项目单独授权、审计员权限或已取消的交接；需要由相应管理员重新配置并签发新凭据。生命周期版本只针对停用/恢复，普通角色变更仍使用原有 expected_role 比较。

本地平台账号若也处于停用或待首次改密状态，组织恢复不会改变它；需要本地管理员独立处理。OIDC 模式也不会擅自启用企业目录账号。离职处理如需全面停止登录，应另外协调 IdP/本地账号、其他组织和平台权限。

## 在途请求与竞态

管理鉴权对成员行持有 SHARE 锁，停用更新同一行。密钥签发若先完成，会被随后停用事务撤销；停用若先提交，已经通过登录认证但尚未完成签发的请求会重新检查停用状态，不能留下新密钥。审计授权写入与成员写入使用相同组织锁，防止停用后被迟到授权恢复。

已经开始授权的推理可能继续运行、封存审计并按真实供应商用量结算。此功能不强行关闭网络流、不退款、不释放旧占额、不重放推理。不能把停用操作成功当作“所有在途响应已停止交付”的证据。

测试已覆盖两种密钥签发/停用锁顺序，以及停用后新请求被拒绝、已派发供应商请求正常结算。账本、预算和其他组织不会被状态变更改写。

## 页面与 API

组织所有者可操作“停用成员/恢复成员”，组织管理员可查看成员状态历史。历史每页固定 50 条，包含操作者、原因、角色变化和各项回收数量，不返回密钥原文或模型正文。终端既有组织/项目查询也遵守停用鉴权；状态写入通过 Web 明确确认。

- PUT `/api/v1/organizations/{org}/members/enabled`
  - body：`target: {issuer, subject}`、`enabled`、`expected_revision`、`reason`。
  - `enabled=true` 时必须提供 `restore_role`（admin/developer/viewer）；停用时不提供。
- GET `/api/v1/organizations/{org}/members/lifecycle?issuer=...&subject=...&after=REVISION`
  - 返回 `data` 和升序版本 `next_cursor`。
- 原有成员查询增加 `enabled`、`lifecycle_revision`；停用成员有效权限显示为未授权。

Cookie 写操作仍须正确 Origin/CSRF。记录与审计日志、数据库及备份必须留在中国大陆，按组织元数据保留策略管理。

## 升级与验收边界

按 [Ubuntu 部署流程](deployment/ubuntu-24.04.md) 摘流、排空、备份，执行新版本 `migrate up` 升到 **0019**，再 `migrate check` 和启动服务。0019 为旧成员设置 enabled=true、版本 0，保持旧权限；追加历史表、签发者索引及 owner 必须启用的约束。不修改旧预算、费用、正文或密钥数据，只有显式停用才执行回收。

新版不能在未迁移旧库上运行。迁移测试直接构造不可变的旧版表格式数据，不通过缺少新字段的旧库调用新版权限代码，也不增加缺表时静默放行的兼容分支。

当前不包含部门层级、邀请/目录同步、组织整体停用或自动判断人员离职。测试使用真实临时 PostgreSQL、签名测试 IdP、本地双会话和合成 TLS 供应商，不代表真实目录、生产硬件容量或实际大陆部署验收。
