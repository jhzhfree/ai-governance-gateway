# 部门层级与项目授权

组织所有者和管理员可在“部门管理”维护真实 PostgreSQL 配置。部门是当前组织内部的项目分组，不是新的租户；不能借部门授权访问另一组织。

## 权限规则

- 部门树最多 100 个节点、8 层。上级部门的成员授权覆盖全部下级部门所属项目；下级授权不会向上或旁支扩散。
- 一个项目最多归属一个部门，允许不归属部门。项目归属调整不迁移组织、预算、币种、费用和原有账本。
- 部门成员必须是本组织已启用成员，可以加入多个部门，角色为只读、开发者或项目管理员。
- 组织 developer 在“项目单独授权”和命中的部门/祖先角色之间取较高权限；组织 viewer 仍是组织范围只读，owner/admin 保持原有权限。部门管理员不获得组织成员管理、模型目录编辑或明文审计权限；具体操作仍遵守原有组织/项目接口要求。
- 项目列表、项目详情、密钥签发、用量/账本与成员页有效权限使用同一继承规则。CLI/TUI 既有项目发现和查询自动遵守该规则；本阶段配置写入通过 Web 或管理 API。

例：研发部门授予小王 developer，平台部门是研发子部门，项目 A 归属平台。小王可通过研发继承访问 A；销售部门项目 B 不受该授权覆盖。若小王的组织角色是 viewer，则仍不能签发密钥。

## 密钥与离职处理

**部门调整不是密钥撤销。** 已签发的项目密钥继续作为独立凭据使用，操作前页面要求填写原因并确认，应同时核查、撤销不应保留的密钥。新管理请求和新签发遵守提交后的权限；已经授权的事务可以先完成。

组织成员停用会原子删除其全部部门授权，递增部门配置版本、保留配置快照和原因；生命周期事件增加 `removed_department_grants`。恢复成员不恢复部门授权。停用前打开的旧配置不能用过期版本重新提交。旧密钥仍按成员停用规则永久撤销。

## 配置操作与一致性

页面提供部门新增/重命名/移动、成员授予/移除、项目归属/解除、空部门删除。删除存在子部门或引用的节点前必须先处理引用。移动部门可能改变整个子树项目的访问范围，应核查后确认。

写入采用完整配置的乐观版本比较，`revision` 从 0 开始；每次成功写入递增。配置、关系表、版本快照与审计在同一事务提交，失败全部回滚。版本冲突返回 409，请刷新后重新核查；不自动合并旧配置覆盖其他管理员操作。

鉴权事务持有组织成员行锁及部门共享事务锁；部门写入先串行化成员写入、再取得部门排他事务锁。这样配置替换不会在已授权事务中途消失，也不会接受停用后迟到的部门授权。循环、孤立节点、重复身份/项目引用、过深层级、跨组织引用和停用成员均被拒绝。

## API

- GET `/api/v1/organizations/{org}/departments`：返回 `revision`、`departments`、`grants`、`projects`，空配置数组不为 null。
- PUT 同路径：`{configuration: {revision, departments, grants, projects}, reason}`。父节点 `parent_id=""` 表示根；每个节点有稳定 ID。最多 1000 条成员授权、1000 条项目归属，正文上限 1 MiB。
- GET `/api/v1/organizations/{org}/departments/history?after=REVISION`：升序版本、操作者、原因和时间，固定每页 50 条及 `next_cursor`。完整配置快照保存在版本表，普通历史接口不返回快照中的全部身份。

仅组织 owner/admin 可读写上述配置。浏览器写入仍要求有效 Origin/CSRF。配置和历史属于组织元数据，数据库、备份与日志必须保存在中国大陆。

## 升级与验证边界

按 [Ubuntu 24.04 部署流程](deployment/ubuntu-24.04.md) 摘流、排空并备份，运行新二进制 `migrate up` 升至 **0020**，再 `migrate check` 后启动。新迁移创建 5 张部门配置/关系/历史表，给成员生命周期历史追加回收计数；原有成员、项目和预算不变，默认无部门继承授权。

验收使用真实临时 PostgreSQL、签名测试 IdP、真实 Go 托管页面及合成 TLS 供应商，不代表生产大陆部署或企业目录验收。当前不包含目录同步、人员邀请、部门预算账户、按历史部门归属的财务重算、自动撤销旧密钥或双人审批；部门树也不创建父子租户。

0021 起，新增请求的项目部门归属会捕获到 [部门成本快照](department-cost-attribution.md)；配置变更不改旧账。当前权限仍决定能否查询历史费用，部门预算与个人费用继续待后续。
