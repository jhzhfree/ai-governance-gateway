# 内容审计持久检查点与崩溃恢复

本阶段补齐**已开启审计项目的输出持久检查点**。标准化回复在转发前先提交到同一个境内 PostgreSQL；进程退出后可由独立维护工具将超出租约的记录封存为 `incomplete`。这不重放推理、不退款、不改变预算占额，也不证明客户端收到了哪些字节。

## 设计与边界

1. Begin 把请求密文、start 链事件、空输出检查点放在同一事务中；审计关闭的项目不产生检查点。
2. 输出保留前缀拆成只追加的加密片段，每片绑定请求、策略快照和序号。超过 max_bytes 后不再新增正文片段，仅更新完整已观测 SHA、字节数及认证摘要。避免每个 SSE 片段都重写整个增长中的前缀。内存/明文留存上限仍为每请求 1–256 KiB，每进程最多 16 个审计捕获。
3. 片段使用 AES-256-GCM；从组织 DEK 按请求、用途派生独立片段密钥和 HMAC 密钥。HMAC 认证片段链头、数量、捕获长度、完整 SHA 和已观测长度，恢复会检查连续性、认证标签和内容边界。不序列化 SHA 内部状态，不存明文文件或明文 spool。
4. 每次输出前同步提交片段和检查点，提交后才能转发；写失败立即停止转发。首字节前返回 503，已开始 SSE 返回审计不可用错误且不发送 `[DONE]`。结算已经成功时保留真实费用，未结算时保留占额供既有核查工具处理。
5. 正常 Finish 原子写入最终回复密文、seal 链事件并删除临时检查点及片段。到期 Purge 同样删除暂存正文，不能用恢复绕过留存期限。

客户端遇到 503 或 SSE 中断时不能据此认定未收费。建议将 OpenAI 兼容 SDK 的自动重试设为 `max_retries=0`，先按请求编号核查账本，再由业务决定是否重提；恢复工具不会代为重试。

检查点记录**已观测的标准化输出**，不保证是最终交付给客户端的全部内容：提交后、转发前仍可能崩溃；失败的最后一个片段也可能在内存中被正常封存。未读到的供应商字节、未成功提交且未能正常封存的字节不在恢复承诺中。回复前缀达到留存上限后，其余正文不保存，完整已观测 SHA 和长度仍保留。

此路径增加每个输出片段的数据库往返与 WAL 写入。片段只追加且正文总量有界，但仍有行与索引开销；首字节和吞吐需在目标盒子实测，不能套用关闭正文审计时的容量承诺。本阶段没有异步批量 spool、月度分区运维、KMS 或外部不可变锚点。

## 租约与恢复

每个捕获持有随机 owner ID，初始租约 5 分钟，每次检查点更新续期。该窗口高于网关现有 120 秒推理超时。恢复只选择**未过期的 capturing 记录且检查点租约已过期**，使用行锁及 SKIP LOCKED 避免并发重复封存；锁住记录后重新读取租约，防止误收刚续期的活跃请求。旧捕获在恢复后不能再写入或覆盖结果。

租约超时不等于进程死亡证明。长暂停进程恢复后也必须服从 fencing；不要把租约随意缩短到推理超时之内。恢复结果固定为 `incomplete`、status=0（HTTP 结果未知），不根据已见 `[DONE]`、账本状态或供应商返回推断 complete。

恢复只使用数据库密文与部署的历史密钥，不依赖旧进程 RAM。坏密钥、篡改、缺失片段或封存失败会回滚整批，返回失败，不跳过损坏记录伪报成功。排查时先保护现场并检查相关请求的元数据；不要手改密文或摘要。可缩小批次，但不能把“恢复计数为 0”当作所有旧记录均已处理。

## Ubuntu 运维操作

先按 [Ubuntu 部署流程](deployment/ubuntu-24.04.md) 摘流、排空并备份，用新版本 `migrate up` 升级到 **0017**，`migrate check` 成功后启动。运行服务不会自动建表。

维护工具与远程 `aigw` 客户端分开，必须在中国大陆、持有专用数据库维护权限和历史审计密钥的环境运行。使用受控秘密注入已有 `AIGW_DATABASE_URL`、`AIGW_CONTENT_AUDIT_KEYS`、`AIGW_CONTENT_AUDIT_ACTIVE_KEY`，不要把秘密放入命令行、日志或 Git。

```bash
# 每批 1–100 条，默认 50；输出只有 recovered 数量。
content-audit recover 50
# 验证指定组织的 start/seal/purge 链，不输出正文。
content-audit verify ORGANIZATION_ID
# 删除已到期正文，包含临时检查点；不需要正文密钥。
content-audit purge 1000
```

进程异常退出后先恢复数据库/密钥，再待租约超时执行 recover，随后 verify，并用既有流量核查/账本工具处理未结束执行和占额。recover 可以重试，多维护实例并发不会重复封存。建议由受控维护账号每分钟调度一次；当前不在网关后台自动执行。失败时保留错误退出状态并告警，不把输出写入公共日志平台。备份、WAL、数据库副本、密钥备份和维护输出均须留在中国大陆。

恢复依赖 PostgreSQL 与存储的持久性。本模块对 Begin/检查点/Finish/Recover 使用 `synchronous_commit=on`；运维仍须保证 `fsync=on`、磁盘可靠、备份可恢复。异步副本切换、数据库回滚或损坏仍可能丢失已提交数据，不承诺断电/磁盘故障下零丢失。数据库超级用户整体重写或回滚历史仍需外部不可变锚定来发现。

**升级前遗留的 capturing 记录没有本格式检查点，工具不会为其编造空回复或将其冒充恢复成功。** 保留现场按旧版本边界核查，最终按留存策略处理。旧主密钥版本必须覆盖 retained 数据与备份恢复窗口；缺失密钥时不得生成同 ID 的新密钥替代。

## 验收口径

使用真实临时 PostgreSQL、独立子进程 SIGKILL、服务重建、合成 TLS 供应商验证：提交后恢复、截断/完整摘要、租约隔离、并发去重、篡改拒绝、整批回滚、过期暂存清除、首字节前/流中检查点失败及账本保持。全部为合成测试数据；不代表目标硬件断电、生产 I/O 容量或实际大陆部署验收。
