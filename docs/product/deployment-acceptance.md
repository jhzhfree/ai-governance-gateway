# 部署与验收手册

> 单进程分支提示（2026-11-08）：`feature/v1-single-process-commercial` 现在以进程内 Bifrost 为产品入口，并已开始提供对应候选安装包；下文四协议和双进程能力仍是旧分支基线，不等于新引擎已全部迁移。新引擎已接入受控文本 Chat 与无状态文本 Responses JSON/SSE；Embeddings、Messages、工具和多模态仍在迁移。当前启动与安装以 [单进程入口](../engine-entrypoint.md)、[Linux 候选包](../linux-package.md) 和 [交付跟踪](../v1-delivery.md) 为准。

适用版本见 [文档中心](README.md)。本手册是实施工作顺序，不能将待验收项预先勾选通过。命令使用当前控制面候选包名称，历史专题中的旧路径需按实际安装布局调整。

当前确认的 V1 目标包含四类受控 API；单进程分支仍按文首说明逐项迁移，不能提前勾选四协议完成。单进程安装使用候选包中的 `aigw-gateway`，包含默认启动自动升级与嵌入式执行器，无 new-api 运行依赖。以下显式 newapi 步骤仅供旧分支对照：须按 [双进程部署说明](../new-api-deployment.md) 准备独立数据面、TLS、服务身份及审核目录；不得套用到新产品入口。

## 1. 交付前准备表

| 项目 | 需要提供/确认 |
| --- | --- |
| 版本 | 完整 commit、候选包 SHA-256、清单、对应 CI 两个 job 结果 |
| 机器 | Linux 架构、非 root 网关账号、时间同步、独立日志/数据规划 |
| 数据库 | 专用 PostgreSQL、连接与权限、备份目标、迁移账号模式 |
| 访问地址 | 正式 HTTPS origin、证书、反代保留 Host、管理/推理/指标访问策略 |
| 身份 | OIDC 客户端与管理 audience，或显式本地模式与初始化负责人 |
| 平台权限 | 供应商管理员和系统管理员的稳定 issuer+subject，避免混用角色 |
| 秘密材料 | 厂商凭证、内容/供应商加密密钥及历史版本、独立监控令牌 |
| 网络 | 四家需要使用的出口、DNS、证书信任；主机网络变更的带外通道 |
| 业务数据 | 真实模型 ID、合同价格、依据与有效期、组织/项目/部门责任人 |
| 验收 | 专用测试项目、合成文本、真实付费调用预算、证据保存责任人 |

环境变量由服务管理器或受控部署系统注入；网关**不会自动加载 `.env` 文件**。不要将真实值提交 Git 或贴入交付文档。

## 2. 配置分组

| 配置组 | 关键变量 |
| --- | --- |
| 基础 | `AIGW_DATABASE_URL`、`AIGW_BROWSER_ORIGIN` |
| OIDC | `AIGW_AUTH_MODE=oidc`、`AIGW_OIDC_ISSUER`、`AIGW_OIDC_AUDIENCE`、`AIGW_OIDC_CLIENT_ID`、`AIGW_OIDC_CLIENT_SECRET` |
| 本地身份 | `AIGW_AUTH_MODE=local`，正式 origin 与离线管理员初始化 |
| 平台供应商权限 | `AIGW_PROVIDER_ADMIN_ISSUER`、`AIGW_PROVIDER_ADMIN_SUBJECT` |
| 供应商加密托管 | `AIGW_PROVIDER_ENCRYPTION_KEYS`、`AIGW_PROVIDER_ENCRYPTION_ACTIVE_KEY` |
| 环境注入厂商凭证 | `AIGW_ALIYUN_API_KEY`、`AIGW_VOLCENGINE_API_KEY`、`AIGW_ZHIPU_API_KEY`、`AIGW_DEEPSEEK_API_KEY` |
| 内容审计 | `AIGW_CONTENT_AUDIT_KEYS`、`AIGW_CONTENT_AUDIT_ACTIVE_KEY` |
| 系统管理 | `AIGW_SYSTEM_ADMIN_ISSUER`、`AIGW_SYSTEM_ADMIN_SUBJECT`、`AIGW_SYSTEM_NODE`、`AIGW_HOST_AGENT_SOCKET` |
| 监控 | `AIGW_METRICS_TOKEN`，独立于所有业务密钥 |

具体格式以仓库 [.env.example](../../.env.example) 与专题为准。空的可选配置通常表示能力未启用，不应凭示例名推断已生效。不要为图方便复用不同用途的密钥。

## 3. 首次安装顺序

1. 获取可信候选包，核对外部整包摘要和包内清单、源 commit。将文件解压到独立版本目录，不覆盖正在运行的目录。
2. 准备数据库、受控配置和秘密注入。网关使用非 root 运行账号，目录权限保证其能读所需静态资源和配置。
3. 选择升级模式：默认业务启动自动迁移；若业务账号无 DDL 权限，则由迁移账号先运行 `aigw-migrate up` 和 `check`，之后业务进程使用 `--schema-mode=check`。
4. 本地模式先按 [本地身份说明](../local-identity.md) 用 `aigw-local-admin` 交互式初始化，没有默认账号密码。OIDC 模式注册正确回调与客户端，再验证身份。
5. 启动原生网关，显式指定候选包内 Web 路径。以下仅示意，环境变量须已安全注入：

```bash
/opt/aigw/VERSION/bin/aigw-gateway \
  --listen 127.0.0.1:8080 \
  --web-dir /opt/aigw/VERSION/web
```

6. 配置反代/TLS，保持 canonical Host，不把 `/v1`、`/api/v1`、`/auth` 随意重写到其他前缀。
7. 从管理入口发布供应商配置。空目录时 live 可正常而 ready 为 503；不能让 readiness 路由策略阻断唯一初始化管理入口。
8. 按操作手册开通组织、项目、模型与密钥，执行分角色验收后再接入真实业务。

`aigw-migrate --help` 目前显示用法并退出 1，不代表迁移执行失败；真正的 `up/status/check` 按对应执行结果判断。不要以帮助输出代替结构检查。

## 4. 系统管理部署附加步骤

需要主机监控时可先只读启用系统权限；要执行网络变更，再按 [主机代理说明](../system-management.md) 安装独立 root 代理、设置指定网关 UID、稳定节点名和允许网卡。

候选包中的 systemd 文件是部署示例，不会自动安装。确认实际二进制路径与环境文件、socket 目录/权限一致。不同节点的名称不能重复；通过可靠的固定节点管理地址访问，避免负载均衡把操作发往另一主机。

在专用 VM 验证 DHCP/静态地址、DNS、失联 90 秒回退、代理退出、NM 重启、断电以及外部工具冲突。未完成前，不对生产管理网卡开放页面写操作。

## 5. 分角色验收用例

以下“预期”是验收要求，不是本环境已经完成的记录。每项保存版本、操作者角色、时间、脱敏结果及问题编号。

| ID | 场景与操作 | 预期结果 |
| --- | --- | --- |
| A01 | 正确/错误身份登录、退出后再次访问 | 正常身份可用；错误身份/旧会话被拒绝 |
| A02 | 本地初始账号登录与首次改密 | 改密前不能进入正常管理；无默认密码 |
| A03 | 普通组织管理员打开供应商/系统写功能 | 未被独立授权时不能写全局配置 |
| A04 | 创建项目、授权模型、生成密钥、关闭弹窗 | 明文只展示一次；模型可调用范围符合授权 |
| A05 | 访问其他组织/项目 ID | 服务端拒绝越权，不只靠隐藏按钮 |
| A06 | 调用超过预算或并发限制 | 请求被正确拒绝；核查没有违规新增费用 |
| A07 | 请求断流/超时后查看账本 | 执行与费用分开解释；未知费用保留占额 |
| A08 | 双人审批调额，申请人尝试自审 | 自审不通过；另一有权身份按流程处理 |
| A09 | 导入标准账单、重复导入、另人审核 | 重复不新增计账；审核约束和审计生效 |
| A10 | 修改项目部门归属后查前后费用 | 历史快照不被新归属改写 |
| A11 | 未确认设备调用、确认后调用、撤销后调用 | 准入策略按状态生效；普通密钥不能绕过强制项目策略 |
| A12 | 开启正文审计、普通管理员查看、审计员带理由查看 | 独立授权及访问留痕生效；正确处理截断/过期 |
| A13 | 关键字告警/阻断的输入与输出合成样例 | 命中记录符合策略版本；不把输出阻断当成免费 |
| A14 | 修改供应商配置时制造版本冲突 | 409 拒绝覆盖旧版本；发布无半份状态 |
| A15 | 系统网络临时应用、不确认、带外核查 | 真实 NM 回退满足要求；未知状态不伪报成功 |
| A16 | 账号停用/恢复、成员撤权、所有者交接 | 撤销立即约束后续操作；恢复不复活旧密钥 |
| A17 | 无效监控令牌、有效令牌、未启用指标 | 按配置返回拒绝/指标/404，不泄露秘密 |
| A18 | 旧结构升级、损坏迁移、恢复有效备份 | 升级与回滚约束生效；恢复后结构/账本/授权可核查 |
| A19 | 候选包被修改或提交不匹配 | 校验失败，不能作为已验证包部署 |

真实供应商请求需要业务授权的费用预算；合成供应商通过不等于真实账号通过。每个厂商都应覆盖 JSON、SSE、凭证拒绝、用量与账单口径，不仅测试一条成功回复。

## 6. 升级、回退与恢复

升级前保存版本清单、备份与历史加密密钥，并确认旧版本和新版本结构兼容策略。停止新增流量并按现有生命周期安排排空；在途费用和 uncertain 请求必须留痕核查。

在隔离目标验证备份恢复，再决定是否切流。旧备份可能恢复旧会话、Key、设备状态；补齐备份后的撤销和授权变化。供应商已发生的费用不会被数据库回滚撤销。主机网卡是外部状态，也不会随库恢复。

本地演练命令：

```bash
# 需受控注入专用 TEST_DATABASE_URL 与兼容 PostgreSQL 客户端
bash scripts/verify-restore.sh
# 完整后端与恢复门禁
AIGW_VERIFY_RESTORE=1 AIGW_VERIFY_WEB=0 bash scripts/verify.sh
# 自建候选包与无服务启动的发行检查
bash scripts/verify-release.sh
```

演练只允许专用测试库，不能指向生产。普通 CI 的主测试与包验证不自动意味着恢复门禁已执行。真实规模、跨主机、密钥恢复、PITR/WAL及 RPO/RTO 另行验收。

## 7. 运维检查与交付签收

日常分别检查 live/ready、依赖、配置/依据有效期、预算占额、审计积压/到期、数据库容量、备份可恢复性和主机状态。指标抓取部署参考 [监控说明](../monitoring.md)，流式请求耗时包括完整流生命周期。

签收至少记录：

- 正式域名、部署节点、源 commit、数据库版本、工具链、包摘要。
- 管理员职责分工、权限矩阵、组织/项目/模型配置与秘密保管责任人。
- 本地与远端测试证据、真实外部验收结果、未关闭问题及批准人。
- 备份与历史密钥保管位置、恢复演练时间、RPO/RTO、回退负责人。
- 终端与主机网络变更的恢复通道、审计与日志保留责任。
- 依赖授权、发布来源核验、签名/供应链要求是否满足。

未完成上述必需门禁时，交付应明确为开发候选/受限试用，而不是用“V1.0”标题替代正式验收。
